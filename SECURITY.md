# Security policy

## Supported versions

ResticHub has no release yet. After the first release, this section will list the versions that get security fixes.

## Report a vulnerability

Do not open a public issue for a security problem.

Use [GitHub private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability) in this repository. Include:

1. The affected component: agent, control plane, web UI, installer or documentation.
2. The version or commit.
3. The steps to reproduce the problem.
4. The effect that you saw.

The maintainers send a first reply in 7 days or less. The maintainers tell you when the fix is ready and agree with you on the disclosure date.

## Contact

Use GitHub private vulnerability reporting. The maintainers will add an email address before the first public release.

The threat model is in [`design/threat-model.md`](design/threat-model.md). Read it to see which risks ResticHub accepts and which risks it controls.
