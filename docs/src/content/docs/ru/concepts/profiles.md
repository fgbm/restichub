Профиль — это описание резервной копии: что копировать, что пропускать, как запускать restic и какие снимки хранить. [План](/restichub/ru/concepts/plans/) назначает профиль на хост по расписанию. Профиль принадлежит одному [репозиторию](/restichub/ru/concepts/repositories/).

## Разделы редактора

Редактор профиля — одна страница. У каждого раздела видно состояние (включено, выключено или требует внимания) и краткую сводку. Боковая панель показывает живую сводку и команды restic, которые получаются из профиля.

| Раздел | Что задаётся |
|---|---|
| Основное | Имя профиля и репозиторий. По имени профиль находят в списке и в планах. |
| Что копировать | Один путь в строке. Пути «Для всех систем» берутся на любом хосте, остальные только на своей системе (Windows, Linux или macOS). |
| Исключения | Шаблоны вида `*.tmp` или пути, по одной записи в строке. Можно указать и путь к файлу со списком шаблонов на хосте. |
| Параметры копирования | Теги снимков, VSS (только Windows, флаг `--use-fs-snapshot`), запрет выхода за границу файловой системы, пропуск каталогов кэша с файлом `CACHEDIR.TAG`, ограничения скорости отдачи и приёма в КиБ/с. |
| Проверка репозитория | Проверка после копирования. Без доли чтения проверяется только структура репозитория: это быстро. Доля вида `5%` или `1/10` читает эту часть данных. Чем больше доля, тем дольше проверка и тем больше трафика. |
| Скрипты на хосте | Скрипты до и после копирования. См. [Серверные скрипты](/restichub/ru/operations/scripts/). |
| Лимиты выполнения | Лимит «Остановить без прогресса» и максимальная длительность задания. См. раздел ниже. |

Правила хранения входят в профиль. Шаги `forget` и `prune` выполняет только [хост обслуживания](/restichub/ru/concepts/repositories/) репозитория.

## Правила хранения

Снимок остаётся, если его оставило хотя бы одно правило. Правила не вычитаются, а складываются.

Значение 0 или пустое поле выключает правило. Если ни одно правило не включено, сервер управления не удаляет снимки и не запускает `prune`.

| Правило | Что остаётся |
|---|---|
| Последние | N самых новых снимков. |
| По часам | Самый новый снимок каждого из последних N часов, в которых есть снимки. |
| По дням | Самый новый снимок каждого из последних N дней, в которых есть снимки. |
| По неделям | Самый новый снимок каждой из последних N недель (с понедельника по воскресенье), в которых есть снимки. |
| По месяцам | Самый новый снимок каждого из последних N календарных месяцев, в которых есть снимки. |
| По годам | Самый новый снимок каждого из последних N календарных лет, в которых есть снимки. |
| За период | Все снимки не старше заданного срока. Срок отсчитывается от самого нового снимка, а не от сегодняшнего дня. Примеры: `30d`, `6m`, `1y2m7d3h`. |
| Теги, которые не удаляются | Снимок с любым из этих тегов остаётся всегда. |

Правила по часам, дням, неделям, месяцам и годам считают только интервалы, в которых есть снимки. Правило «по дням 5» оставляет пять дней с копиями, а не последние пять суток.

Правила применяются к каждой группе снимков отдельно, поэтому копии разных хостов или путей не вытесняют друг друга. Если группа не выбрана, используется группировка по умолчанию: хост и пути. Фильтр ограничивает правила отдельными хостами, тегами или путями. Снимки вне фильтра не удаляются.

Редактор показывает пример из 60 ежедневных снимков и то, какие из них оставят текущие правила.

### Готовые наборы

Новый профиль начинается с набора «Стандарт». Можно выбрать другой набор или изменить значения.

| Набор | Последние | По дням | По неделям | По месяцам | По годам |
|---|---|---|---|---|---|
| Минимум | 3 | 7 | 0 | 0 | 0 |
| Стандарт | 3 | 7 | 4 | 6 | 0 |
| Долго | 3 | 14 | 8 | 12 | 5 |

## Лимиты заданий

Лимиты защищают от зависших и слишком долгих заданий. Лимит «Остановить без прогресса» действует всегда, а максимальную длительность можно выключить значением 0. Пустое поле означает значение по умолчанию.

| Лимит | По умолчанию | Переменная окружения для всего стека |
|---|---|---|
| Остановить без прогресса | 60 минут (от 5 до 10080) | `RESTICHUB_JOB_STALL_TIMEOUT_SECS` |
| Максимальная длительность | 48 часов (от 0 до 43200, 0 выключает лимит) | `RESTICHUB_JOB_MAX_DURATION_SECS` |

Если агент не сообщает о прогрессе дольше первого лимита, сервер управления останавливает задание как зависшее. Задание, которое идёт дольше второго лимита, останавливается, даже если прогресс есть. Переменная окружения задаёт значение по умолчанию, значение в профиле имеет приоритет. Страница [Задания](/restichub/ru/concepts/jobs/#ограничения-по-времени) описывает, как агент измеряет прогресс.
