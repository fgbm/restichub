Профиль — это описание резервной копии: что копировать, что пропускать, как запускать restic и какие снимки хранить. [План](/restichub/ru/concepts/plans/) назначает профиль на хост по расписанию. Профиль принадлежит одному [репозиторию](/restichub/ru/concepts/repositories/).

## Разделы редактора

Редактор профиля — одна страница. Нажмите «Добавить профиль» на экране «Профили» или выберите имя профиля. В меню «…» строки профиля есть только «Сделать копию» и «Удалить профиль». У каждого раздела видно состояние («Включено», «Выключено» или «Требует внимания») и краткую сводку. Раздел можно включить или выключить, а кнопки «Развернуть всё» и «Свернуть всё» меняют все разделы сразу. Боковая панель «Что получится» показывает живую сводку и команды restic, которые профиль даёт для выбранного хоста. Если есть несохранённые изменения, редактор пишет «Изменения не сохранены.» Если у профиля есть планы, редактор сообщает, сколько планов его используют. Новые настройки действуют с их следующего запуска.

| Раздел | Что задаётся |
|---|---|
| Основное | Имя профиля и репозиторий. По имени профиль находят в списке и в планах. |
| Что копировать | Один путь в строке. Пути «Все системы» берутся на любом хосте, остальные только на своей системе (Windows, Linux или macOS). |
| Исключения | Шаблоны вида `*.tmp` или пути, по одной записи в строке. Можно указать и путь к файлу со списком шаблонов на хосте («Файлы исключений»). |
| Теги | Теги снимков этого профиля. По ним снимки ищут и отбирают правила хранения. Введите тег и нажмите Enter или разделите теги запятой или пробелом. Каждый тег становится чипом. Чтобы убрать тег, нажмите крестик на чипе. |
| Параметры копирования | VSS (только Windows, флаг `--use-fs-snapshot`). «Не выходить за файловую систему» (`--one-file-system`). «Исключить каталоги кэша» с файлом `CACHEDIR.TAG` (`--exclude-caches`). «Ограничение отдачи (КиБ/с)» и «Ограничение приёма (КиБ/с)» (`--limit-upload`, `--limit-download`). |
| Хранение | Правила, которые решают, какие снимки остаются. См. раздел ниже. |
| Проверка репозитория | Проверка после копирования. Если поле «Доля чтения данных» пустое, проверяется только структура репозитория: это быстро. Доля вида `5%` или `1/10` читает эту часть данных. Чем больше доля, тем дольше проверка и тем больше трафика. |
| Скрипты на хосте | Скрипты до и после копирования. См. [Скрипты сервера](/restichub/ru/operations/scripts/). |
| Лимиты выполнения | Лимит «Остановить, если нет прогресса» и максимальная длительность задания. См. раздел ниже. |

У профиля нет хуков. Чтобы выполнить команду на хосте до или после копирования, используйте [скрипты сервера](/restichub/ru/operations/scripts/).

Шаги `forget` и `prune` выполняет только [хост обслуживания](/restichub/ru/concepts/repositories/) репозитория.

## Правила хранения

Снимок остаётся, если его оставило хотя бы одно правило. Правила не вычитаются, а складываются.

Значение 0 или пустое поле выключает правило. Если ни одно правило не включено, сервер управления не удаляет снимки и не запускает `prune`.

| Правило | Что остаётся |
|---|---|
| Последние | N самых новых снимков. |
| По часам | Самый новый снимок каждого из последних N часов, в которых есть снимки. |
| По дням | Самый новый снимок каждого из последних N дней, в которых есть снимки. |
| По неделям | Самый новый снимок каждой из последних N недель (с понедельника по воскресенье), в которых есть снимки. |
| По месяцам | Самый новый снимок каждого из последних N календарных месяцев, в которых есть снимки. |
| По годам | Самый новый снимок каждого из последних N календарных лет, в которых есть снимки. |
| За период | Все снимки не старше заданного срока. Срок отсчитывается от самого нового снимка, а не от сегодняшнего дня. Примеры: `30d`, `6m`, `1y2m7d3h`. |
| Теги, которые не удаляются | Снимок с любым из этих тегов остаётся всегда. |

Правила по часам, дням, неделям, месяцам и годам считают только интервалы, в которых есть снимки. Правило «по дням 5» оставляет пять дней с копиями, а не последние пять суток.

Правила применяются к каждой группе снимков отдельно, поэтому копии разных хостов или путей не вытесняют друг друга. Если группа не выбрана, используется группировка по умолчанию: хост и пути. Фильтр ограничивает правила отдельными хостами, тегами или путями. Снимки вне фильтра не удаляются.

Редактор показывает пример из 60 ежедневных снимков, по два снимка в день за последние три дня, и то, какие из них оставят текущие правила. Снимок, который остаётся из-за защищённого тега, в легенде имеет подпись «остаётся из-за тега».

### Готовые наборы

Новый профиль начинается с набора «Стандарт». Можно выбрать другой набор или изменить значения.

| Набор | Последние | По дням | По неделям | По месяцам | По годам |
|---|---|---|---|---|---|
| Минимум | 3 | 7 | 0 | 0 | 0 |
| Стандарт | 3 | 7 | 4 | 6 | 0 |
| Долго | 3 | 14 | 8 | 12 | 5 |

## Лимиты заданий

Раздел «Лимиты выполнения» защищает от зависших и слишком долгих заданий. Лимит «Остановить, если нет прогресса» действует всегда. Пустое поле оставляет значение серверу: новый профиль получает значение по умолчанию, а изменяемый профиль сохраняет прежнее.

| Поле | Единица | По умолчанию | Допустимые значения | Переменная для всей установки |
|---|---|---|---|---|
| «Остановить, если нет прогресса, минут» | Минуты | 60 минут | от 5 до 10080 | [`RESTICHUB_JOB_STALL_TIMEOUT_SECS`](/restichub/ru/operations/environment-variables/) |
| «Максимальная длительность, часов» | Часы | 48 часов | от 0 до 720. 0 — без ограничения. | [`RESTICHUB_JOB_MAX_DURATION_SECS`](/restichub/ru/operations/environment-variables/) |

Если restic не продвигается дольше первого лимита, агент останавливает шаг, и задание завершается как зависшее. Шаги `check` и `prune` ждут не меньше 6 часов, даже если профиль задаёт меньший лимит. Задание, которое идёт дольше второго лимита, останавливается, даже если прогресс есть. Переменная задаёт значение по умолчанию для нового профиля, значение в профиле имеет приоритет. Страница [Задания](/restichub/ru/concepts/jobs/#ограничения-по-времени) описывает, как агент измеряет прогресс. Карточка задания показывает лимиты каждого задания.
