---
title: Планы
description: Назначение профиля на хост по расписанию.
---

План назначает один профиль на один агент по расписанию. Расписание хранит сервер управления; он же создаёт задания. Агент не хранит расписание (ADR-0002).

## Поля плана

| Поле | Значение |
|---|---|
| Имя | Имя плана. Уникально в организации. |
| Профиль | Описание резервного копирования, которое сервер управления компилирует для каждого задания. |
| Хост | Агент, который выполняет план. |
| Выражение cron | Пять полей: минута, час, день месяца, месяц, день недели. |
| Часовой пояс | Имя IANA, например `Europe/Berlin`. |
| Пропущенные запуски | Правило для момента запуска, который сервер управления пропустил. |
| Включён | Отключённый план не создаёт заданий. |

Профиль и агент принадлежат одной организации. Перед записью плана сервер управления компилирует сохранённый профиль для операционной системы агента. Профиль без пути для этой операционной системы отклоняется.

## Расписание

Сервер управления вычисляет каждый момент запуска из выражения cron и часового пояса. Задание называет план и момент запуска. На каждый момент запуска сервер управления создаёт одно задание. Пара «план, момент запуска» уникальна, поэтому два экземпляра сервера управления создают одно задание на один момент запуска (FR-SC-02, ADR-0010).

Сервер управления применяет правила перехода на летнее время:

- Момент запуска внутри пропуска часов выполняется один раз, сразу после перевода часов.
- Момент запуска внутри повторяющегося интервала выполняется один раз, в первое его наступление.

## Пропущенные запуски

Момент запуска считается пропущенным, если сервер управления не создал для него задание, например после простоя. Итог определяет правило плана:

| Правило | Результат |
|---|---|
| Запускать каждый пропущенный | Одно задание на каждый пропущенный момент. За один проход создаётся не более 100 заданий; моменты сверх предела отбрасываются. |
| Запускать только последний пропущенный | Одно задание на последний пропущенный момент. |
| Пропускать пропущенные запуски | Заданий нет. |

У каждого планового задания есть срок годности: 24 часа после момента запуска. Просроченное задание сервер управления переводит в состояние `expired`.

Приостановленная организация не создаёт заданий. План, агент которого отозван, не создаёт заданий.

## Роли

| Роль | Право |
|---|---|
| Администратор, Оператор | Создавать, изменять и удалять план. |
| Наблюдатель | Читать план. |

## API

| Метод и путь | Назначение |
|---|---|
| `GET /api/v1/plans` | Список планов. Параметры `cursor` и `limit` листают список. |
| `POST /api/v1/plans` | Создать план. |
| `GET /api/v1/plans/{id}` | Прочитать один план. |
| `PATCH /api/v1/plans/{id}` | Изменить план. |
| `DELETE /api/v1/plans/{id}` | Удалить план. |
| `GET /api/v1/plans/{id}/next-runs?count=5` | Следующие моменты запуска в UTC. |

План другой организации даёт HTTP 404. Платформенная организация отклоняет любую операцию с планом с кодом HTTP 403.
