---
title: Планы
description: Назначение профиля на хост по расписанию.
---

План назначает один профиль на один агент по расписанию. Расписание хранит сервер управления; он же создаёт задания. Агент не хранит расписание.

## Поля плана

| Поле | Значение |
|---|---|
| Имя | Имя плана. Уникально в организации. |
| Профиль | Описание резервного копирования, которое сервер управления компилирует для каждого задания. |
| Хост | Агент, который выполняет план. |
| Выражение cron | Пять полей: минута, час, день месяца, месяц, день недели. |
| Часовой пояс | Имя IANA, например `Europe/Berlin`. |
| Пропущенные запуски | Правило для момента запуска, который сервер управления пропустил. |
| Включён | Отключённый план не создаёт заданий. |

Профиль и агент принадлежат одной организации. Перед записью плана сервер управления компилирует сохранённый профиль для операционной системы агента. Профиль без пути для этой операционной системы отклоняется.

## Расписание

Сервер управления вычисляет каждый момент запуска из выражения cron и часового пояса. Задание называет план и момент запуска. На каждый момент запуска сервер управления создаёт одно задание. Пара «план, момент запуска» уникальна, поэтому два экземпляра сервера управления создают одно задание на один момент запуска.

Сервер управления применяет правила перехода на летнее время:

- Момент запуска по фиксированному времени внутри пропуска часов выполняется один раз, сразу после перевода часов.
- Момент запуска по фиксированному времени внутри повторяющегося интервала выполняется один раз, в первое его наступление.
- Момент запуска по интервалу, например `0 * * * *` или `*/15`, не называет время настенных часов. Он выполняется в обе половины повторяющегося интервала.

## Пропущенные запуски

Момент запуска считается пропущенным, если сервер управления не создал для него задание, например после простоя. Момент запуска в пределах короткого окна допустимого опоздания считается своевременным, и он выполняется всегда. Правило пропущенных запусков применяется только к более старым моментам. Итог определяет правило плана:

| Правило | Результат |
|---|---|
| Запускать каждый пропущенный | Одно задание на каждый более старый пропущенный момент. За один проход сохраняются последние 100 моментов запуска. |
| Запускать только последний пропущенный | Одно задание на последний более старый пропущенный момент. |
| Пропускать пропущенные запуски | Заданий для более старых пропущенных моментов нет. |

У каждого планового задания есть срок годности: 24 часа после момента запуска. Сервер управления не создаёт задание для момента, которое задание пережило бы сразу: такое задание истекает сразу. Просроченное задание сервер управления переводит в состояние `expired`.

Приостановленная организация не создаёт заданий. План, агент которого отозван, не создаёт заданий.

## Доставка

Плановое задание начинается в состоянии `queued`. Очередь отправляет задание агенту, который на связи. Страница [Задания](/restichub/ru/concepts/jobs/) описывает очередь, лимиты и повторы. Удаление плана завершает его задания в очереди с результатом `cancelled`.

## Запуск вручную

Действие «Запустить сейчас» сразу ставит в очередь одно задание плана. Задание подчиняется тем же правилам, что и плановое. Отключённый план можно запустить вручную. Перед постановкой в очередь сервер управления проверяет, что профиль компилируется для агента.

## Роли

| Роль | Право |
|---|---|
| Администратор, Оператор | Создавать, изменять, удалять и запускать план. |
| Наблюдатель | Читать план и предпросматривать расписание. |

## API

| Метод и путь | Назначение |
|---|---|
| `GET /api/v1/plans` | Список планов. Параметры `cursor` и `limit` листают список. |
| `POST /api/v1/plans` | Создать план. |
| `GET /api/v1/plans/{id}` | Прочитать один план. |
| `PATCH /api/v1/plans/{id}` | Изменить план. |
| `DELETE /api/v1/plans/{id}` | Удалить план. |
| `POST /api/v1/plans/{id}/run` | Сразу поставить в очередь одно задание плана. Ответ содержит задание. |
| `GET /api/v1/plans/{id}/next-runs?count=5` | Следующие моменты запуска в UTC. |
| `POST /api/v1/plans/preview` | Следующие моменты запуска несохранённого расписания, в UTC. Тело содержит `cron`, `time_zone` и `count`. |

План другой организации даёт HTTP 404. Платформенная организация отклоняет любую операцию с планом с кодом HTTP 403.
