Параметр профиля — это именованное значение, которое объявляет профиль, а задаёт хост. Значение можно переопределить в плане. Профиль использует значение в пути, исключении, теге или в переменной скрипта.

Например, три хоста хранят дамп базы данных в разных каталогах. Профиль объявляет параметр `pg_dir`. Каждый хост задаёт свой каталог, а три плана используют один профиль.

## Поля параметра

| Поле | Значение |
|---|---|
| Параметр | Имя. Строчная латинская буква, затем строчные латинские буквы, цифры и подчёркивания, не больше 64 символов. Имя уникально в профиле. |
| Тип | «Текст» или «Секрет». |
| Обязательный | План не сохраняется, пока у параметра нет значения. |
| По умолчанию | Значение, если его не задали план и хост. Значение по умолчанию есть только у текстового параметра. |
| Описание | Необязательный текст не длиннее 200 символов. Его показывают страница плана и страница хоста. |

Текстовое значение занимает от 1 до 4096 байт. Профиль объявляет не больше 64 параметров. У параметра типа «Секрет» нет значения по умолчанию: одно значение дало бы одинаковый пароль всем хостам.

## Откуда берётся значение

Хост хранит значения по именам, и их читают все профили хоста. План может переопределить значение. Сервер управления выбирает значение в таком порядке:

1. Значение плана.
2. Значение хоста.
3. Значение по умолчанию в профиле.

Раздел «Параметры профиля» на странице плана показывает значение и источник: «план», «хост», «по умолчанию» или «не задано». Раздел «Значения параметров» на странице хоста показывает значения хоста и профили, которым нужен каждый параметр.

Хост хранит и то значение, которое не объявляет ни один профиль. Страница хоста помечает его «Не нужен профилям», и такое значение можно удалить.

## Где применяется параметр

Текстовый параметр подставляется как `{{param.<имя>}}` в таких полях профиля:

- Пути, отдельно для каждой системы.
- Исключения.
- Файл со списком исключений на хосте.
- Теги.

В правилах хранения и в проверке репозитория параметр не подставляется. Сервер управления выполняет один шаг обслуживания для всего репозитория, поэтому значение одного хоста там не имеет смысла. В этих полях сервер отклоняет параметр с кодом `parameter_not_allowed`.

Необязательный параметр без значения по умолчанию даёт пустую строку. Пустой путь или тег недопустим. Поэтому профиль, который использует такой параметр в пути или теге, не сохраняется, а сервер отвечает кодом `parameter_needs_default`.

Синтаксис всех переменных описан на странице [Переменные шаблона](/restichub/ru/reference/variables/).

## Секретный параметр

Значение секретного параметра — это ссылка на сохранённый секрет с назначением `hook_secret`. Текст секрета сервер управления не хранит.

Секретный параметр никогда не подставляется в путь, исключение или тег. Командная строка restic видна в списке процессов хоста, и секрет в ней утёк бы. Сервер отклоняет сохранение с кодом `parameter_secret_in_template`.

Переменная скрипта вида «Параметр профиля» называет параметр. Текстовое значение сервер управления отправляет агенту как маскированное, и агент скрывает его в журнале скрипта. Секретное значение попадает в скрипт как значение своего секрета. См. [Скрипты сервера](/restichub/ru/guides/scripts/).

Значение в пути, исключении или теге входит в команду restic и в снимок. Его видят все роли, которые видят задания и снимки. Не помещайте секрет в такие поля.

## Кто задаёт значение

| Роль | Право |
|---|---|
| Администратор | Задавать, менять и удалять текстовое и секретное значение. |
| Оператор | Задавать, менять и удалять текстовое значение. На секретное значение сервер отвечает 403. |
| Наблюдатель | Видеть имена и типы. Текстовое значение скрыто. |

Удалить план с секретным значением может только администратор, потому что удаление уносит значение. Наблюдатель видит имя секрета, а не сам секрет.

Журнал аудита записывает каждое изменение значения. Запись содержит имя параметра, его тип и идентификатор секрета. Значения в записи нет.

## У сохранённого плана есть все значения

Сервер управления отклоняет запись, после которой у плана нет значения обязательного параметра:

| Отказ | Когда |
|---|---|
| `parameter_missing` | При сохранении плана нет значения обязательного параметра. |
| `parameter_missing_in_plans` | Сохранение профиля или изменение значений хоста оставляет план без значения. |
| `parameter_kind_mismatch` | Тип значения не совпадает с объявлением. Значение неверного типа считается отсутствующим. |

Сервер управления проверяет значения ещё раз при сборке задания. Задание без значения завершается с результатом `config_error`.

## Удаление параметра

Сохранение профиля без параметра удаляет значения этого параметра в планах профиля. Значения хостов остаются, и страница хоста помечает их «Не нужен профилям». Редактор запрашивает подтверждение и перечисляет планы со значением. Удалить параметр, который хост хранит как секретное значение, может только администратор.

Переименование — это новый параметр. У нового имени нет значения, а значения старого имени остаются на хостах без применения.

## API

| Метод и путь | Назначение |
|---|---|
| `GET /api/v1/agents/{id}/parameters` | Значения хоста и параметры профилей его планов. |
| `PUT /api/v1/agents/{id}/parameters` | Заменяет значения хоста в одной транзакции. |
| `POST /api/v1/profiles`, `PATCH /api/v1/profiles/{id}` | Поле `parameters` содержит объявления. |
| `POST /api/v1/plans`, `PATCH /api/v1/plans/{id}` | Поле `parameter_values` содержит переопределения плана. |
