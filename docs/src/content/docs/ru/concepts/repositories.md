Репозиторий — это место, где restic хранит резервные копии. Сервер управления хранит адрес репозитория и его секреты. Агент получает секреты только на время одного задания.

## Обслуживание

У каждого репозитория есть один хост обслуживания — агент обслуживания. Только этот хост выполняет `forget`, `prune` и `check`. Хост резервного копирования никогда не получает эти шаги. Для обслуживания используйте отдельный хост.

Репозиторий без хоста обслуживания не получает заданий обслуживания. Диалог репозитория показывает предупреждение, а сервер управления не создаёт задания `forget`, `prune` и `check` для этого репозитория.

Сервер управления создаёт задания обслуживания по двум расписаниям репозитория:

| Задача | По умолчанию | Задание |
|---|---|---|
| Хранение | Раз в неделю, в воскресенье в 03:00 | Один шаг `forget` на каждый профиль и хост, затем один шаг `prune`. |
| Проверка | Раз в месяц, 1-го числа в 04:00 | Один шаг `check`. |

У каждого расписания есть выражение cron и признак «включено». Оба расписания используют один часовой пояс, по умолчанию UTC. Диалог репозитория показывает ближайшие моменты запуска. После изменения расписания отсчёт идёт от ближайшего момента запуска после изменения.

Сервер управления создаёт задание обслуживания, только если репозиторий инициализирован и на нём нет другого эксклюзивного задания в очереди или в работе. Если репозиторий занят другим эксклюзивным заданием, расписание остаётся просроченным, и сервер управления создаёт задание после завершения того задания. Пропущенный момент запуска старше 24 часов пропускается.

### Запустить сейчас

Оператор или администратор может сразу запустить хранение или проверку в строке репозитория. Задание подчиняется тем же правилам, что и плановое. Для хранения нужен профиль с политикой хранения, который запускает план активного агента.

### Барьеры

Задание обслуживания эксклюзивное. Оно стартует после завершения работающих резервных копий репозитория. Резервные копии, поставленные в очередь после него, ждут его завершения. Страница [Задания](/restichub/ru/concepts/jobs/) показывает задания обслуживания вместе с резервными копиями.

### Хранение при нескольких профилях

Один репозиторий могут использовать несколько профилей. Политика хранения профиля удаляет только снимки этого профиля:

- Сервер управления добавляет тег `restichub-profile-<идентификатор профиля>` к каждой резервной копии профиля.
- Префикс тегов `restichub-` зарезервирован. Тег профиля, тег хранения и тег фильтра политики хранения не могут начинаться с него.
- Каждый профиль с политикой хранения получает один шаг `forget`. Шаг фильтрует по тегу профиля. Он использует группировку профиля. Профиль без группировки использует `host,paths`, поэтому каждый хост и каждый набор путей сохраняют свою политику.
- Фильтр в политике хранения профиля сужает шаг. Снимок должен иметь тег профиля и все теги фильтра. Пути и хосты фильтра сужают шаг дальше. Агент плана, чьего имени хоста нет в хостах фильтра, не даёт шага. Имя хоста сравнивается с именем хоста, которое restic записывает в снимок. Шаблон в хостах фильтра не допускается.
- Теги фильтра всегда означают «И» с тегом профиля. Шаг `forget` после резервного копирования использует то же правило.
- Шаг всегда группирует по хосту, потому что профиль может работать на нескольких агентах. Если в группировке профиля нет хоста, сервер управления добавляет его, и каждый хост хранит свои снимки.
- Агент из более старого выпуска не знает фильтр с несколькими тегами. Политика хранения с тегами фильтра завершается с причиной `agent_capability_missing`, пока вы не обновите этот агент. Сервер управления использует возможности, которые агент объявил в текущем соединении. Если вы установите более старый пакет агента, сервер заметит это при следующем соединении и не отправит фильтр. Это безопасно: вы можете вернуть более старую версию агента в любой момент.
- Шаг `forget`, который не выбрал ни одного снимка, даёт заданию статус `succeeded_with_warnings`. Причина: `forget_selected_nothing`.

Снимок, сделанный до появления тега, не имеет тега, и ни одна политика хранения его не выбирает. Чтобы подчинить такие снимки политике хранения, добавьте тег один раз. Выполните эту команду на хосте агента для каждого профиля, с именем хоста и путём резервной копии:

```sh
restic tag --add restichub-profile-<id> --host <host> --path <path>
```

Иначе удаляйте такие снимки вручную. Профиль с политикой хранения без плана не даёт шага `forget`.

### Проверка

Шаг `check` читает наибольшую часть данных, которую задаёт профиль репозитория. Если две части равны, выигрывает старший профиль. Если ни один профиль не задаёт часть данных, проверка читает только структуру.

## Роли

| Роль | Право |
|---|---|
| Администратор | Читать и менять хост обслуживания и расписания. |
| Оператор | Читать обслуживание и запускать задачу сразу. |
| Наблюдатель | Читать обслуживание. |
