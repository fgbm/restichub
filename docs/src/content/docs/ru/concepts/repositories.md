Репозиторий — это место, где restic хранит резервные копии. Сервер управления хранит адрес репозитория и его секреты. Агент получает секреты только на время одного задания.

Сервер управления хранит каждый секрет в базе данных в зашифрованном виде. После сохранения веб-интерфейс больше не показывает значение секрета. Чтобы изменить секрет, замените его значение. Пароль репозитория задаётся при добавлении репозитория, и в этой версии его нельзя изменить. Ключи S3 и учётные данные REST-сервера можно заменить.

## Обслуживание

У каждого репозитория есть один хост обслуживания — агент обслуживания. Только этот хост выполняет `forget`, `prune` и `check`. Хост резервного копирования никогда не получает эти шаги. Для обслуживания используйте отдельный хост.

Локальный репозиторий устроен иначе: его путь есть только на одном хосте. Это хост репозитория. Он же хост обслуживания, на нём выполняются все задания репозитория, и после инициализации его изменить нельзя. См. [Локальный репозиторий](/restichub/ru/guides/add-a-repository/#локальный-репозиторий).

Репозиторий без хоста обслуживания не получает заданий обслуживания. На странице репозитория показано предупреждение, а сервер управления не создаёт задания `forget`, `prune` и `check` для этого репозитория.

Сервер управления создаёт задания обслуживания по двум расписаниям репозитория:

| Задача | По умолчанию | Задание |
|---|---|---|
| Хранение | Раз в неделю, в воскресенье в 03:00 | Один шаг `forget` на каждый профиль и хост, затем один шаг `prune`. |
| Проверка | Раз в месяц, 1-го числа в 04:00 | Один шаг `check`. |

Страница репозитория `/repositories/<id>` содержит расписания в двух разделах. Раздел «Правила хранения» содержит расписание хранения и «Часовой пояс» — имя IANA, например `Europe/Berlin`. Раздел «Проверка» содержит расписание проверки. У каждого раздела есть «Выражение cron», кнопки готовых расписаний и переключатель, который включает или выключает расписание. Оба расписания используют один часовой пояс. Для нового репозитория страница предлагает часовой пояс браузера. Каждый раздел показывает «Ближайшие запуски» и «Последний запуск». После изменения расписания отсчёт идёт от ближайшего момента запуска после изменения.

Сервер управления создаёт задание обслуживания, только если репозиторий инициализирован и на нём нет другого исключительного задания в очереди или в работе. Если репозиторий занят другим исключительным заданием, расписание остаётся просроченным, и сервер управления создаст задание, когда то задание завершится. Момент запуска, пропущенный более 24 часов назад, пропускается.

### Запустить сейчас

Оператор или администратор может сразу запустить хранение или проверку из меню «…» в строке репозитория в списке «Репозитории». На странице репозитория этих действий нет. Выберите «Удалить устаревшие снимки сейчас» или «Запустить проверку сейчас». Первое действие выполняет `forget` по правилам хранения каждого профиля, затем `prune` освобождает место. К заданию применяются те же правила, что и к плановому. Для хранения нужен профиль с политикой хранения, который используется в плане активного агента.

### Очерёдность с резервными копиями

Задание обслуживания исключительное: оно начинается после завершения идущих резервных копий репозитория. Резервные копии, поставленные в очередь после него, ждут его окончания. Страница [Задания](/restichub/ru/concepts/job-lifecycle/) показывает задания обслуживания вместе с резервными копиями.

### Хранение при нескольких профилях

Один репозиторий могут использовать несколько профилей. Политика хранения профиля удаляет только снимки этого профиля:

- Сервер управления добавляет тег `restichub-profile-<идентификатор профиля>` к каждой резервной копии профиля.
- Префикс тегов `restichub-` зарезервирован. Тег профиля, тег хранения и тег фильтра политики хранения не могут начинаться с него.
- Каждый профиль с политикой хранения получает один шаг `forget`. Шаг фильтрует по тегу профиля. Он использует группировку профиля. Профиль без группировки использует `host,paths`, поэтому каждый хост и каждый набор путей сохраняют свою политику.
- Фильтр в политике хранения профиля сужает шаг. Снимок должен иметь тег профиля и все теги фильтра. Пути и хосты фильтра сужают шаг дальше. Если имени хоста агента плана нет среди хостов фильтра, шаг для него не создаётся. Имя хоста сравнивается с именем хоста, которое restic записывает в снимок. Шаблоны в хостах фильтра не допускаются.
- Теги фильтра всегда объединяются с тегом профиля по «И». Шаг `forget` после резервного копирования использует то же правило.
- Шаг всегда группирует по хосту, потому что профиль может работать на нескольких агентах. Если в группировке профиля нет хоста, сервер управления добавляет его, и каждый хост хранит свои снимки.
- Агент из более старого выпуска не поддерживает фильтр с несколькими тегами. Политика хранения с тегами фильтра завершается с причиной `agent_capability_missing`, пока вы не обновите этот агент. Сервер управления учитывает возможности, о которых агент сообщил при текущем подключении. Если установить более старый пакет агента, сервер заметит это при следующем подключении и не отправит фильтр. Это безопасно: вернуть более старую версию агента можно в любой момент.
- Шаг `forget`, который не выбрал ни одного снимка, присваивает заданию статус `succeeded_with_warnings`. Причина: `forget_selected_nothing`.

Снимок, сделанный до появления тега, не помечен им, и ни одна политика хранения его не выбирает. Чтобы подчинить такие снимки политике хранения, добавьте тег один раз. Выполните эту команду на хосте агента для каждого профиля, с именем хоста и путём резервной копии:

```sh
restic tag --add restichub-profile-<id> --host <host> --path <path>
```

Или удаляйте такие снимки вручную. Для профиля с политикой хранения, который не используется ни в одном плане, шаг `forget` не создаётся.

### Проверка

Шаг `check` читает наибольшую часть данных, которую задаёт профиль репозитория. Если доли равны, берётся профиль, созданный раньше. Если ни один профиль не задаёт часть данных, проверка читает только структуру.

## Роли

| Роль | Право |
|---|---|
| Администратор | Читать и менять хост обслуживания и расписания. |
| Оператор | Читать обслуживание и запускать задачу сразу. |
| Наблюдатель | Читать обслуживание. |
