Репозиторий — это место, где restic хранит резервные копии. Сервер управления хранит адрес репозитория и его секреты. Агент получает секреты только на время одного задания (ADR-0003).

## Обслуживание

У каждого репозитория есть один хост обслуживания — агент обслуживания. Только этот хост выполняет `forget`, `prune` и `check` (FR-RP-08). Хост резервного копирования никогда не получает эти шаги. Для обслуживания используйте отдельный хост.

Репозиторий без хоста обслуживания не получает заданий обслуживания. Диалог репозитория показывает предупреждение, а сервер управления не создаёт задания `forget`, `prune` и `check` для этого репозитория.

Сервер управления создаёт задания обслуживания по двум расписаниям репозитория:

| Задача | По умолчанию | Задание |
|---|---|---|
| Хранение | Раз в неделю, в воскресенье в 03:00 | Один шаг `forget` на каждый профиль и хост, затем один шаг `prune`. |
| Проверка | Раз в месяц, 1-го числа в 04:00 | Один шаг `check`. |

У каждого расписания есть выражение cron и признак «включено». Оба расписания используют один часовой пояс, по умолчанию UTC. Диалог репозитория показывает ближайшие моменты запуска. После изменения расписания отсчёт идёт от ближайшего момента запуска после изменения.

Сервер управления создаёт задание обслуживания, только если репозиторий инициализирован и на нём нет другого эксклюзивного задания в очереди или в работе. Если репозиторий занят другим эксклюзивным заданием, расписание остаётся просроченным, и сервер управления создаёт задание после завершения того задания. Пропущенный момент запуска старше 24 часов пропускается.

### Запустить сейчас

Оператор или администратор может сразу запустить хранение или проверку в строке репозитория. Задание подчиняется тем же правилам, что и плановое. Для хранения нужен профиль с политикой хранения, который запускает какой-либо план.

### Барьеры

Задание обслуживания эксклюзивное (FR-SC-04). Оно стартует после завершения работающих резервных копий репозитория. Резервные копии, поставленные в очередь после него, ждут его завершения (AC-SC-03). Страница [Задания](/restichub/ru/concepts/jobs/) показывает задания обслуживания вместе с резервными копиями.

### Хранение при нескольких профилях

Один репозиторий могут использовать несколько профилей. Политика хранения профиля удаляет только снимки этого профиля (ADR-0034):

- Сервер управления добавляет тег `restichub-profile-<идентификатор профиля>` к каждой резервной копии профиля.
- Шаг `forget` профиля фильтрует по этому тегу, по имени хоста агента и по путям резервной копии агента. Он использует группировку профиля. Профиль без группировки использует `host,paths`.
- Фильтр в политике хранения профиля не действует в задании обслуживания.
- Профиль, который работает на двух хостах, получает по одному шагу `forget` на каждый хост.

Снимок, сделанный до появления тега, не имеет тега, и ни одна политика хранения его не выбирает. Удаляйте такие снимки вручную. Профиль с политикой хранения без плана не даёт шага `forget`.

### Проверка

Шаг `check` читает часть данных, которую задаёт первый профиль репозитория с таким значением. Если ни один профиль не задаёт часть данных, проверка читает только структуру.

## Роли

| Роль | Право |
|---|---|
| Администратор | Читать и менять хост обслуживания и расписания. |
| Оператор | Читать обслуживание и запускать задачу сразу. |
| Наблюдатель | Читать обслуживание. |
