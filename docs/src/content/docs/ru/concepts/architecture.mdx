## Части системы

| Часть | Назначение |
|---|---|
| Сервер управления | Хранит конфигурацию, создаёт задания по расписанию, отправляет их агентам и показывает результаты. |
| Агент | Работает на каждом хосте: получает подписанные задания, запускает restic и отправляет результаты. |
| Репозиторий | Репозиторий restic. Агент обращается к нему напрямую. |

## Соединения

<Diagram name="architecture" label="Соединения между браузером, сервером управления, агентами и репозиториями" />

| Откуда | Куда | Порт и протокол | Назначение |
|---|---|---|---|
| Браузер | Обратный прокси | 443, HTTPS | Веб-интерфейс и API. |
| Обратный прокси | Сервер управления | 8080, HTTP | Прокси передаёт запросы серверу управления по внутренней сети. |
| Агент | Сервер управления через обратный прокси | 443, HTTPS | Регистрация, один раз. См. [Добавление хоста](/restichub/ru/getting-started/add-a-host/#как-работает-регистрация). |
| Агент | Порт агентов сервера управления | 8443, gRPC с mTLS | Поток для заданий, хода выполнения и результатов. Агент открывает его и держит открытым. |
| restic на хосте | Репозиторий | Порт бэкенда | Данные резервной копии. Они не проходят через сервер управления. |

Сервер управления никогда не открывает соединение с хостом. Обратный прокси не завершает mTLS агентов. Порт агентов ведёт прямо на сервер управления.

## Термины

| Термин | Значение |
|---|---|
| Организация | Единица изоляции в одной установке: владеет хостами, репозиториями, планами, профилями, секретами и членством. |
| Профиль | Описание резервного копирования: репозиторий, пути, исключения, срок хранения, скрипты. |
| План | Профиль, назначенный на агенты, с расписанием. |
| Задание | Один запуск плана или ручная операция. |
| Шаг | Одна команда в задании, например `backup` или `forget`. |
| Скрипт сервера | Скрипт, который вы пишете в веб-интерфейсе. Агент выполняет его на доверенном хосте до или после резервного копирования. |
| Хост обслуживания | Хост, который выполняет `forget`, `prune` и `check` для репозитория. |

## Как выполняется задание

1. Сервер управления определяет по расписанию плана, когда запускать следующее задание.
2. Когда это время наступает, сервер управления ставит задание в очередь.
3. Когда репозиторий свободен, сервер управления подписывает задание и отправляет его агенту.
4. Агент проверяет подпись.
5. Агент выполняет шаги по порядку и отправляет ход выполнения на сервер управления.
6. Агент отправляет результат. Сервер управления показывает его на панели мониторинга.
