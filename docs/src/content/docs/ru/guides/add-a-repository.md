---

Репозиторий — место, где restic хранит снимки. Сервер управления хранит расположение репозитория и его секреты. Хосты подключаются к репозиторию напрямую, поэтому данные резервных копий не проходят через сервер управления.

## Перед началом

- Зарегистрируйте хотя бы один хост и убедитесь, что его состояние — «В сети». См. [Регистрация агента](/restichub/ru/getting-started/add-a-host/). Этот хост станет хостом обслуживания.
- Подготовьте хранилище, доступное хосту по сети:
  - S3-совместимое хранилище: бакет, ключ доступа и секретный ключ с правами на чтение, запись, просмотр списка и удаление объектов в бакете.
  - [rest-server](https://github.com/restic/rest-server). Дайте каждому репозиторию свой путь, например `https://rest.example.com:8000/fs-01`. Если rest-server использует файл `.htpasswd`, подготовьте имя пользователя и пароль одной учётной записи из этого файла.
  - Локальный путь: каталог на диске одного хоста, например `/mnt/backup/restic`. См. [Локальный репозиторий](#локальный-репозиторий).
- Войдите как Admin. Репозиторий создаёт только Admin.

## Поля хранилища

| Тип хранилища | Поле | Значение |
|---|---|---|
| S3-совместимое | «Адрес» | Адрес хранилища со схемой, например `https://s3.example.com` |
| S3-совместимое | «Бакет» | Имя бакета, например `backups` |
| S3-совместимое | «Префикс» | Необязательно. Путь внутри бакета, например `restic/fs-01` |
| S3-совместимое | «Регион» | Необязательно. Регион бакета, например `us-east-1` |
| S3-совместимое | «Ключ доступа S3», «Секретный ключ S3» | Учётные данные бакета |
| REST-сервер | «Адрес» | Адрес репозитория на rest-server, например `https://rest.example.com:8000/fs-01` |
| REST-сервер | «Имя пользователя» | Необязательно. Имя учётной записи из файла `.htpasswd` rest-server |
| REST-сервер | «Пароль REST-сервера» | Необязательно. Пароль той же учётной записи |
| Локальный путь | «Путь» | Абсолютный путь на диске хоста репозитория, например `/mnt/backup/restic` |

«Адрес» использует схему `https` или `http`. В нём не может быть имени пользователя, пароля, строки запроса или фрагмента. Учётные данные rest-server введите в поля «Имя пользователя» и «Пароль REST-сервера» в разделе «Доступ».

Имя пользователя не секрет: страница репозитория показывает его, и его можно изменить в любой момент. Пароль — секрет. Агент передаёт оба значения restic в переменных окружения `RESTIC_REST_USERNAME` и `RESTIC_REST_PASSWORD`, а не в командной строке. Для rest-server с `--no-auth` учётные данные не нужны.

## Создание репозитория

:::danger[Опасно]
Сохраните копию пароля репозитория вне ResticHub. Если сервер управления потерян, restic не откроет снимки без пароля. После сохранения репозитория пароль изменить нельзя.
:::

1. Откройте «Репозитории».
2. Нажмите «Добавить репозиторий». Откроется страница «Новый репозиторий».
3. В разделе «Основное» введите имя в поле «Репозиторий».
4. В разделе «Расположение» выберите «Тип хранилища»: «S3-совместимое», «REST-сервер» или «Локальный путь».
5. Заполните поля хранилища по таблице выше.
6. В разделе «Доступ» введите «Пароль репозитория».
7. Введите учётные данные хранилища.
8. В разделе «Хост обслуживания» выберите хост. Для локального репозитория раздел называется «Хост репозитория», и хост обязателен.
9. Нажмите «Сохранить».

Репозиторий появится в списке с состоянием «Не инициализирован». Сервер управления больше не показывает значения секретов. Ключи S3 и пароль REST-сервера можно только заменить.

Разделы «Обслуживание» и «Проверка» содержат расписания заданий обслуживания. Для первого репозитория оставьте значения по умолчанию. См. [Репозитории](/restichub/ru/concepts/repositories/#обслуживание).

## Инициализация репозитория

Новый репозиторий в пустом расположении нужно инициализировать. Если в расположении уже есть репозиторий restic с тем же паролем, проверьте доступ.

1. В списке «Репозитории» откройте меню «…» в строке репозитория.
2. Выберите «Инициализировать». Для существующего репозитория restic выберите «Проверить доступ».
3. Убедитесь, что в поле «Хост» указан хост обслуживания. Сервер управления выполняет инициализацию только на хосте обслуживания.
4. Нажмите «Запустить».
5. Дождитесь, когда диалог покажет состояние «Успешно» и результат «Репозиторий готов.».

Состояние репозитория изменится на «Готов».

| Результат | Значение | Действие |
|---|---|---|
| «Репозиторий готов.» | Restic инициализировал репозиторий, или доступ работает. | Не нужно. |
| «Репозитория пока нет. Инициализируйте его.» | Проверка доступа не нашла репозиторий в расположении. | Выберите «Инициализировать». |
| «Пароль репозитория или учётные данные неверны.» | Restic не может открыть репозиторий. | Проверьте пароль и учётные данные хранилища. |
| «Репозитория нет по этому пути на этом хосте. Проверьте путь, точку монтирования и хост.» | Хост не может обратиться к расположению. | Проверьте «Адрес», бакет и сетевой путь от хоста. |
| «Срок задания истёк до ответа хоста. Запустите его снова.» | Хост не ответил вовремя. | Убедитесь, что хост в сети, и запустите задание снова. |

## Как работает инициализация

Задание содержит шаг `test_access` и, для инициализации, шаг `init`. Для шага `test_access` агент выполняет `restic cat config`, для шага `init` — `restic init`.

Агент выполняет `init` только тогда, когда `test_access` завершается с кодом restic 10. Код restic 10 означает, что репозиторий не существует. При любом другом результате задание останавливается, поэтому агент не инициализирует существующий репозиторий повторно. Неверный пароль даёт код 12, и задание сообщает `config_error`.

Пароль репозитория и учётные данные хранилища передаются только в составе подписанного задания. Агент передаёт их restic через переменные окружения. Они никогда не попадают в аргументы команды, журнал, файл журнала заданий или текст ошибки.

## Локальный репозиторий

Локальный путь есть только на диске одного хоста. Поэтому локальный репозиторий привязан к одному хосту — хосту репозитория. Хост репозитория — это и хост обслуживания репозитория.

- Хост репозитория нужно выбрать при создании репозитория. Сервер управления отклоняет локальный репозиторий без хоста.
- Все задания репозитория выполняются на хосте репозитория. Это резервные копии планов, `forget`, `prune`, `check`, `unlock`, инициализация, проверка доступа, список снимков, дерево файлов и восстановление.
- План профиля, который пишет в этот репозиторий, выполняется только на хосте репозитория. Страница плана предлагает только этот хост. См. [Планы](/restichub/ru/concepts/plans/#локальный-репозиторий).
- Восстановление из репозитория пишет файлы только на хост репозитория, потому что restic читает репозиторий на этом хосте.
- До инициализации хост репозитория можно изменить. Сервер управления отклоняет изменение, пока план репозитория выполняется на старом хосте. Сначала перенесите или удалите план.
- После инициализации хост репозитория изменить нельзя, как и путь. Снимки лежат на диске этого хоста. Страница показывает поле заблокированным и объясняет причину. API отклоняет изменение с кодом `repository_host_locked`.

Репозиторий S3 или rest-server доступен каждому хосту по сети. Для него смена хоста обслуживания — обычная операция.

### Репозитории, сохранённые до этого правила

Сервер управления сохраняет локальный репозиторий без хоста и план, который выполняется на другом хосте. Он ничего не удаляет. При запуске сервер управления пишет в журнал предупреждение о каждом таком репозитории с идентификаторами планов. Задание такого плана сервер управления отклоняет с причиной `not_repository_host`. Чтобы исправить репозиторий:

1. Откройте страницу репозитория.
2. В разделе «Хост репозитория» выберите хост, на котором лежит путь. Репозиторий без хоста принимает это изменение, даже если план выполняется на другом хосте.
3. Откройте каждый план из журнала и выберите хост репозитория.
