---
title: Сертификаты агента и повторная регистрация
description: Как агент обновляет сертификат, как зарегистрировать хост заново с сохранением планов и как объединить две записи одного компьютера.
---

У каждого агента есть клиентский сертификат для подключения к серверу управления по mTLS. Агент обновляет его сам. Если агент потерял учётные данные или срок сертификата истёк, зарегистрируйте хост заново: хост сохранит планы, метки и ссылки на хост обслуживания.

## Хосты, которые ожидают подключения

Агент зарегистрировался, но ещё не открыл поток: хост имеет статус «Ожидает подключения». Такой хост не в сети и не вне сети. На экране «Обзор» его считает отдельный показатель «Хосты ожидают подключения». Когда агент подключается в первый раз, статус меняется на «В сети».

Хост остаётся в этом статусе, если служба не запускается или не может связаться с сервером управления. Выполните на хосте `status`, чтобы прочитать последнюю ошибку (см. [Регистрация агента](/restichub/ru/reference/agent-commands/#устранение-неполадок)).

## Срок действия и окно замены

- Срок действия по умолчанию — 30 дней. Чтобы изменить срок, задайте `RESTICHUB_AGENT_CERT_LIFETIME_SECS` или `agent_cert_lifetime_secs` в файле конфигурации. Значение указывается в секундах. Наименьшее значение — 600, наибольшее — 7 776 000 (90 дней).
- Агент запрашивает новый сертификат, когда пройдут две трети срока. При сроке по умолчанию это 20-й день.
- Сервер управления принимает запрос после половины срока. Запас между половиной и двумя третями срока покрывает расхождение часов агента и сервера.
- Для одного агента сервер управления подписывает не больше одного нового сертификата за 10 минут (или за четверть срока, если она короче). Реестр хранит время последнего запроса, поэтому ожидание не сбрасывается ни переподключением, ни переходом на другой экземпляр сервера управления. Ожидание начинается и после отклонённого запроса. Сертификат, который агент не подтвердил, так же блокирует следующий запрос.
- Если при подключении агент видит, что срок замены уже прошёл, он ждёт случайное время до 60 секунд и только потом запрашивает сертификат. После отказа он повторяет запрос через 11 минут.
- Новый сертификат начинает действовать за 5 минут до времени выдачи, поэтому агент с отстающими часами его принимает. Начало срока не бывает раньше начала срока выпускающего CA.

## Что происходит при замене

1. Агент создаёт новую пару ключей. Новый закрытый ключ остаётся в памяти агента до ответа.
2. Агент отправляет запрос на подпись сертификата (CSR) по открытому соединению.
3. Сервер управления проверяет запрос. Агент должен быть активным и предъявить зарегистрированный сертификат. Запрос должен содержать новый открытый ключ. Сервер выпускает сертификат для того агента, чей сертификат предъявлен, а не для того, чьё имя указано в запросе.
4. Сервер управления сохраняет новый сертификат как ожидающий и добавляет запись аудита `agent_certificate_rotate`.
5. Агент проверяет ответ по корневому удостоверяющему центру, который он запомнил при регистрации. Агент сохраняет новый ключ, новый сертификат и новую цепочку в защищённом каталоге конфигурации и отправляет подтверждение.
6. Сервер управления регистрирует новый сертификат. С этого момента сертификат со старым серийным номером отклоняется.

Старый сертификат действует до шага 6. Если агент подключился с новым сертификатом до отправки подтверждения, новый сертификат тоже регистрируется.

Во время замены открытое соединение продолжает работать, а выполняющееся задание не прерывается. Новый сертификат агент использует при следующем подключении.

## Файлы на агенте

Агент записывает новые файлы в тот же каталог, где лежит остальное состояние агента, и ограничивает доступ так же, как при регистрации: только для владельца. Если питание пропадёт в середине замены, учётные данные не повредятся: при следующем запуске агент завершит замену или отбросит её. Ключ всегда соответствует сертификату.

## Что показывает экран «Хосты»

Экран «Хосты» и API агентов показывают срок действия сертификата и время последней замены для каждого хоста. Хост, у которого до конца срока осталось меньше 3 дней, требует внимания: его агент не обновил сертификат.

## Подключение со старым сертификатом

После замены старый сертификат подключаться не должен. Если кто-то предъявляет его, сервер управления отклоняет подключение, добавляет запись аудита `agent_superseded_certificate_used` (не чаще раза в час), а экран «Хосты» показывает для этого хоста предупреждение. Возможно, существует копия старого закрытого ключа. Проверьте хост. Если хост небезопасен, отзовите агента и зарегистрируйте хост заново.

## Если агент не обновил сертификат

Агент обновляет сертификат только по открытому соединению. Если агент был не в сети, пока сертификат не истёк, он не может ни подключиться, ни обновить сертификат. В этом случае в журнале агента появится сообщение:

```text
the agent certificate is expired and cannot rotate; register the agent again with a new enrollment token
```

С истёкшим сертификатом замена невозможна. Зарегистрируйте хост заново (см. [Зарегистрировать хост заново](#зарегистрировать-хост-заново)). Хост сохранит планы и метки.

## Зарегистрировать хост заново

Используйте эту процедуру, когда агент потерял идентичность или когда агент нужно перенести в новую установку. Хост сохраняет идентификатор, планы, ссылки на хост обслуживания и метки.

1. Откройте экран «Хосты» от имени администратора.
2. Откройте меню «…» в строке хоста и выберите «Зарегистрировать заново». Та же кнопка есть на странице хоста в разделе «Опасные действия».
3. Выберите «Создать токен». Экран показывает токен один раз.
4. Выполните показанную команду на компьютере хоста от имени `root` или администратора. Укажите полный путь агента, потому что команда установки не создаёт ссылку в `PATH`: в Linux — `/opt/restichub-agent/bin/restichub-agent register --force --url <url> --token <token>`, в Windows — `& "$env:ProgramFiles\ResticHub\Agent\restichub-agent.exe" register --force --url <url> --token <token>` в PowerShell с повышенными правами. Папка запуска не важна.

Токен привязан к хосту. Команда сообщает, что заменила запись хоста. Сервер управления сразу перестаёт принимать старый сертификат и закрывает открытый поток старого агента. В журнале аудита появляется действие `agent_reenroll`.

Токен, привязанный к хосту, виден в списке «Ожидают регистрации» с текстом «Повторная регистрация хоста» и именем хоста. Токен забирает идентичность хоста, поэтому он действует не дольше одного часа. Чтобы изменить предел, задайте [`RESTICHUB_REENROLL_TOKEN_MAX_TTL_SECS`](/restichub/ru/reference/environment-variables/). Новый токен для того же хоста отменяет прежние неиспользованные токены этого хоста, а успешная регистрация отменяет остальные. Отозванный хост не может зарегистрироваться заново, а журнал аудита фиксирует попытку.

Пока новый агент не подключился, хост имеет статус «Ожидает подключения» и не вызывает оповещение «Хост не в сети».

## Возможные дубли

При регистрации агент отправляет дайджест стабильного идентификатора компьютера: `MachineGuid` в Windows и файла `/etc/machine-id` в Linux. Сам идентификатор остаётся на компьютере. Сервер управления хранит только ключевой хеш дайджеста. Ключ строится из KEK и организации, поэтому организация не узнаёт, что компьютер зарегистрирован в другой организации, а дамп базы данных не подтверждает регистрацию компьютера. У виртуальных машин, клонированных из одного образа, идентификатор может совпасть. Предупреждение — только подсказка, решение принимаете вы.

Если токен без привязки к хосту регистрирует компьютер с уже известным идентификатором, обе записи получают в списке хостов статус «Возможный дубль». Страница более новой записи показывает баннер «Эта запись может дублировать более старую запись „имя“. Старую запись видели <время>.»

Чтобы объединить записи:

1. Откройте меню «…» более новой записи или страницу более новой записи. Замену предлагает только новая запись.
2. Выберите «Заменить старую запись». На странице эта кнопка есть в баннере. Диалог показывает время последнего контакта обеих записей.
3. Выберите «Заменить».

Сервер управления переносит планы, ссылки на хост обслуживания, задания в очереди и метки старой записи на новую запись. Затем он отзывает старую запись и отменяет её выполняющиеся задания, как при отзыве. В журнале аудита появляются действия `agent_replace` и `agent_revoke`. Экран показывает «Старая запись заменена» и число перенесённых планов.

Сервер управления заменяет запись, только если выполнены все условия:

- Обе записи активны.
- Обе записи сообщают один и тот же идентификатор компьютера.
- Запись, которую вы открыли, новее старой записи.
- Старая запись не выходила на связь за последние 5 минут. Иначе сервер управления отклоняет замену с HTTP 409 `agent_recently_online`. Чтобы изменить окно, задайте [`RESTICHUB_REPLACE_ONLINE_WINDOW_SECS`](/restichub/ru/reference/environment-variables/).

Если пара записей не образует возможный дубль, сервер управления отвечает HTTP 404.

## Ожидающие подключения токены

Список «Ожидают регистрации» показывает токены регистрации, которые ждут хост. В каждой строке видно, кто создал токен, время создания и время истечения. Чтобы отменить токен, выберите «Отменить». Список обновляется каждые 10 секунд. Токен, который использовал хост, исчезает из списка. Диалог «Добавить хост» показывает «Хост зарегистрирован: имя», когда хост использует токен, созданный в этом диалоге.

Токен нельзя отменить в таких случаях. Сервер управления отвечает HTTP 409 с типизированным кодом:

| Код | Значение |
|---|---|
| `token_used` | Хост уже использовал токен. |
| `token_already_revoked` | Администратор уже отменил токен. |
| `token_expired` | Срок действия токена истёк. |
