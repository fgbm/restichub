На экране «Восстановление» можно просмотреть снимки репозитория, их файлы и восстановить файлы. Экран доступен оператору и администратору, наблюдателю — нет.

Данные восстановления идут из репозитория прямо на целевой агент и не проходят через сервер управления. Целевой агент получает секреты репозитория только на время задания восстановления. Каждая выдача секретов добавляет в журнал аудита запись `secret_delivered`. Запуск восстановления добавляет запись `restore_start` с репозиторием, снимком, целевым агентом и целевым путём. Список снимков или страница дерева, для которых запускается задание, добавляют запись `browse_start` с репозиторием и агентом, который читает репозиторий: этот агент получает секреты репозитория.

## Требования

- Репозиторий должен быть инициализирован.
- Выбранный агент должен быть в сети.
- Агент должен сообщать о поддержке `restore-v1`. Она есть в пакетах агента, которые поддерживают экран восстановления. Агент без неё может показать список снимков, но для дерева файлов и восстановления сервер управления отклонит задание с причиной `agent_capability_missing`. Обновите агент.
- Репозиторий с локальным путём доступен только своему хосту репозитория. Данные остаются на этом хосте, и восстановление пишет файлы на этот хост.
- Целевой путь должен лежать внутри корня восстановления агента (см. [Корни восстановления](#корни-восстановления)).

## Список снимков

1. Откройте **Восстановление**.
2. Выберите репозиторий в заголовке страницы. Агент один раз запускает `restic snapshots` для всего репозитория, и экран показывает все снимки. Если у сервера управления уже есть сохранённый список, экран показывает его и время, когда он получен.
3. Сузьте список полем поиска и фильтрами над списком. Фильтры применяются сразу к загруженному списку. Кнопки поиска нет.
   - **Поиск по пути**: введите часть пути. Снимок подходит, если любой из его путей содержит этот текст. Регистр не учитывается.
   - **Хост** и **Тег**: выберите одно или несколько значений. В меню перечислены значения из загруженных снимков и число снимков для каждого. Тег из профиля показан с именем профиля.
   - **Период**: выберите 24 часа, 7 дней, 30 дней, 90 дней или всё время. **Свой диапазон…** принимает две даты, обе даты входят в диапазон.
4. Каждый заданный фильтр показан плашкой. Чтобы убрать фильтр, нажмите крестик на плашке. Чтобы убрать все фильтры, нажмите **Сбросить**.
5. Кнопка обновления заново запускает задание списка и читает актуальные снимки из репозитория. Рядом показано, когда список получен.

Список показывает заголовок для каждого дня и размер каждого снимка справа. Несколько значений одного фильтра подходят по любому из них. Разные фильтры должны совпасть все. Например, хосты `nas` и `ws` вместе с тегом `daily` дают снимки любого из двух хостов с тегом `daily`.

Адрес страницы хранит репозиторий и фильтры. На странице снимка хлебные крошки `<организация> / Восстановление / <репозиторий> / Снимок <id>` возвращают к тому же виду. У экрана есть отдельные пустые состояния: нет репозитория, в репозитории нет снимков, ни один снимок не подходит под фильтры.

Диапазон дат в API применяет сервер управления, а хост, тег и путь в API — restic. Экран фильтрует загруженный список по тем же правилам, поэтому результат совпадает с выводом `restic snapshots --json` для тех же фильтров. Если в репозитории больше снимков, чем помещается в один результат, экран показывает предупреждение и оставляет самые новые снимки.

## Дерево снимка

Выберите снимок, чтобы открыть его страницу. На ней показаны идентификатор, время, хост, пути и теги снимка, а также дерево файлов. Чтобы вернуться к списку с теми же фильтрами, выберите репозиторий в хлебных крошках. У папки, у ссылки и у каждого типа файла свой значок. У ссылки показан её целевой путь, размера нет. Дерево прокручивается внутри рамки, а в подвале под ним показаны отмеченные пути. Экран показывает по одному каталогу. Агент читает каталог и возвращает страницу не больше чем из 1000 записей. Чтобы открыть следующую страницу, нажмите **Загрузить ещё**. Первая страница каталога с миллионом файлов открывается меньше чем за 5 секунд.

Сервер управления хранит страницу 10 минут. Если за это время вы снова откроете тот же каталог, экран покажет сохранённую страницу, а новое задание не запустится. Если такой же запрос уже ждёт или выполняется, он получит то же задание. Список снимков сохраняется на один час. В списке заданий такие задания не показываются.

Один пользователь может отправлять до 60 запросов списка и страниц в минуту. Каждый экземпляр сервера управления считает этот предел отдельно. На одном агенте может ждать не больше 8 заданий просмотра, на следующий запрос сервер отвечает HTTP 429 `rate_limited`. Агент выполняет не больше двух заданий просмотра одновременно, и они не задерживают резервное копирование.

## Восстановление файлов

<Screen name="restore-snapshot" alt="Страница снимка с деревом файлов и кнопкой «Восстановить…»" />

1. Отметьте нужные файлы и каталоги в дереве. Если вы ничего не отметите, восстановится весь снимок.
2. Нажмите **Восстановить…**.
3. Выберите целевой хост («Целевой хост»). По умолчанию это хост снимка, если он активен, иначе хост обслуживания репозитория.
4. Проверьте целевой путь. Экран предлагает новый каталог в первом корне восстановления агента, например `/var/lib/restichub-restore/a1b2c3d4`. Путь должен быть абсолютным и лежать внутри корня восстановления. На хосте Windows путь показан в формате Windows, например `C:\ProgramData\ResticHub-Restore\a1b2c3d4`. Кнопка в конце поля возвращает предложенный путь. Если у агента несколько корней восстановления, нажмите корень под полем, чтобы подставить его.
5. Если вы не отметили ни одного пути, можно указать пути для исключения. Используйте шаблоны restic, по одному в строке.
6. Выберите, что делать с файлом, который уже есть в целевом каталоге. Для режима «Заменять каждый файл» экран показывает предупреждение.
7. Прочитайте итог в правой части диалога. В узком окне итог показан под полями.
8. Нажмите **Начать восстановление**. Экран откроет задание.

<Screen name="restore-dialog" alt="Диалог восстановления с целевым хостом, целевым путём и корнями восстановления" />

Карточка задания показывает блок «Параметры восстановления»: снимок, целевой хост и путь, пути, режим замены, проверку и пробный запуск. Она также показывает ход выполнения, а после завершения — сколько файлов и байтов агент восстановил и сколько пропустил.

| Параметр | Значение |
|---|---|
| «Существующие файлы»: «Заменять каждый файл» (`always`) | Заменять каждый существующий файл. |
| «Существующие файлы»: «Заменять файл, который отличается» (`if-changed`) | Заменять файл, если его содержимое отличается. |
| «Существующие файлы»: «Заменять файл, который старше снимка» (`if-newer`) | Заменять файл, если он старше копии в снимке. |
| «Существующие файлы»: «Оставлять каждый существующий файл» (`never`) | Оставлять каждый существующий файл. |
| «Пробный запуск» | Проверить восстановление. Агент ничего не записывает и не меняет. |
| «Проверить после восстановления» | После восстановления агент заново читает файлы и сравнивает их со снимком. Нельзя включить вместе с пробным запуском: при пробном запуске файлы не записываются. |

Restic не принимает в одном восстановлении и список включений, и список исключений. Экран восстанавливает отмеченные файлы, а API отклоняет запрос с обоими списками.

В отмеченном пути экран экранирует символы `*`, `?` и `[`, чтобы путь совпадал только с самим собой. Снимок выбирается по идентификатору. Экран и API не принимают `latest`: между двумя чтениями это значение может измениться.

## Корни восстановления

Агент работает от имени root на Linux и от имени LocalSystem на Windows. Он восстанавливает файлы только внутри *корня восстановления*. Корни задают только root или администраторы на хосте, а сервер управления и задания менять их не могут.

| Система | Корень по умолчанию |
|---|---|
| Linux | `/var/lib/restichub-restore` |
| Windows | `C:\ProgramData\ResticHub-Restore` |

Команда `install-service` создаёт корень по умолчанию с доступом только для учётной записи службы. Агент сообщает свои корни серверу управления. Экран предлагает первый корень, а сервер управления отклоняет путь вне корней с кодом HTTP 409 `restore_target_denied`. Агент проверяет путь ещё раз, и его проверка окончательная: при нарушении он отклоняет задание с причиной `restore_target_denied`.

Чтобы добавить корень, запишите по одному абсолютному пути в строке файла `/etc/restichub-agent-restore-roots.txt` (Windows: `C:\ProgramData\ResticHub\Agent-restore-roots.txt`). Строка, которая начинается с `#`, — комментарий. В Linux агент игнорирует строку с кавычкой, обратной косой чертой, `%`, пробелом или управляющим символом. Если строка содержит не абсолютный путь или агент её игнорирует, агент записывает в журнал предупреждение, а `install-service` отклоняет строку и называет её номер. Владельцем файла и тем, кто может его изменять, должен быть только root или администратор. Агент игнорирует файл, который может изменить другая учётная запись. Создайте каталог каждого корня и ещё раз выполните `restichub-agent install-service`. Команда добавляет корни в `ReadWritePaths` юнита systemd. Без этого шага systemd оставит корень доступным только для чтения, и восстановление не будет работать. В Linux агент при каждом запуске записывает в журнал предупреждение о корне, который установленный юнит не может изменять.

У локальных репозиториев в Linux свой файл корней — `/etc/restichub-agent-repository-roots.txt`, с теми же правилами. Корень репозиториев — не корень восстановления. Восстановление никогда не пишет в корень репозиториев. Команда `install-service` отклоняет корень восстановления и корень репозиториев, если один из них содержит другой. Корень восстановления `/` остаётся допустимым. См. [Локальный репозиторий в Linux](/restichub/ru/guides/add-a-repository/#локальный-репозиторий-в-linux).

Писать в корень должны мочь только root или администраторы. Сам корень и все его существующие родительские каталоги должны принадлежать root или администраторам. Ни у одной группы или другой учётной записи не должно быть права записи. Агент игнорирует корень, который нарушает это правило, и записывает предупреждение в журнал. Команда `install-service` такой корень отклоняет. Иначе другая учётная запись могла бы заменить каталог ссылкой и вывести восстановление за пределы корня.

Корень `/` разрешает восстановление в любой каталог, который не совпадает с файлами агента, не содержит их и не находится внутри них (например, `/srv/data`). Сам путь `/` использовать нельзя, потому что он содержит файлы агента. Задавайте корень `/` только осознанно. Для системного пути, например `/etc`, экран показывает предупреждение. Корень `/` не делает `/home`, `/root` и `/run/user` доступными для записи, потому что юнит задаёт `ProtectHome=read-only`. Корень восстановления `/home` или `/root` этого не меняет: systemd оставляет эти каталоги доступными только для чтения. Поэтому агент игнорирует такой корень и записывает в журнал предупреждение, а `install-service` его отклоняет и называет номер строки. Используйте каталог ниже него, владелец которого — root. Также восстановление на месте ниже `/home` или `/root` невозможно. Восстановите файлы в другой корень, например в корень по умолчанию, и скопируйте их на место.

Агент всегда отклоняет путь, который совпадает с его собственными файлами, содержит их или находится внутри них. Это каталог учётных данных, каталог кэша, а также каталог исполняемых файлов агента и restic. Перед проверкой агент раскрывает символьные ссылки. Корень `/` не меняет это правило.

В Windows непосредственно перед запуском restic агент также проверяет пути, в которые пишет восстановление. Агент получает список файлов снимка и проверяет в целевом каталоге каждый выбранный файл и каталог, а также их родительские каталоги внутри цели. Символическая ссылка или точка соединения (junction) на таком пути должна вести внутрь целевого каталога. У файла на таком пути не должно быть других имён (жёстких ссылок). Иначе шаг восстановления завершается с ошибкой и называет путь. Причина в том, что restic в Windows записывает файл через ссылку на файл. Такую ссылку может оставить предыдущее восстановление или локальный пользователь. Ссылка на другом пути, например в каталоге, который восстановление не выбирает, восстановлению не мешает. Удалите ссылку или восстановите данные в пустой каталог. Пробный прогон и восстановление в пустой или новый каталог эту проверку пропускают. Проверка подчиняется отмене и ограничению времени шага. Если восстановление пишет больше 1 000 000 записей в непустой каталог, шаг завершается с ошибкой: сузьте выбор файлов или восстановите данные в пустой каталог. В Linux такая проверка не нужна: restic в Linux заменяет ссылку файлом или каталогом из снимка.

### Корень по умолчанию из прежней версии

Прежний агент для Windows использовал `C:\ProgramData\ResticHub\Restore` как корень по умолчанию. Этот каталог лежит в дереве агента, где агент сам задаёт права каждого каталога. Теперь агент не считает его корнем по умолчанию. Он не переносит и не меняет данные в нём. Восстановление в этот каталог завершается причиной `restore_target_denied`, пока вы не добавите корень явно. Восстанавливайте в новый корень по умолчанию или запишите старый путь отдельной строкой в файл `C:\ProgramData\ResticHub\Agent-restore-roots.txt`.

## API

| Метод и путь | Роль | Назначение |
|---|---|---|
| `POST /api/v1/repositories/{id}/snapshots` | Оператор | Запускает задание, которое получает список снимков. |
| `GET /api/v1/repositories/{id}/snapshots` | Наблюдатель | Читает результат задания (`job`) или последний сохранённый список. Параметры `from` и `to` фильтруют по дате. |
| `POST /api/v1/repositories/{id}/ls` | Оператор | Запускает задание, которое получает содержимое одного каталога снимка. Если страница уже сохранена, возвращается она, с кодом HTTP 200. |
| `GET /api/v1/repositories/{id}/ls` | Оператор | Читает страницу задания (`job`). |
| `POST /api/v1/repositories/{id}/restore` | Оператор | Запускает восстановление и возвращает задание. |

Для восстановления и страницы дерева нужен идентификатор снимка из 8–64 строчных шестнадцатеричных символов. Ответы об ошибках:

- HTTP 400: `dry_run` и `verify` указаны вместе;
- HTTP 409 `agent_offline`: агент не в сети;
- HTTP 409 `agent_capability_missing`: агент слишком старый;
- HTTP 409 `restore_target_denied`: путь вне корней агента;
- HTTP 404: репозиторий другой организации.

`GET /api/v1/agents` показывает `restore_roots` каждого агента.
