---
title: Скрипты сервера
description: Как запускать скрипты до и после резервного копирования, как администратор хоста включает режим доверия и какой риск принимает этот режим.
---

Скрипт сервера — это скрипт, который вы пишете в веб-интерфейсе. Сервер управления отправляет его вместе с заданием. Агент выполняет его на хосте до или после резервного копирования. Каждый скрипт — отдельный шаг задания со своим статусом, длительностью и журналом.

Хост выполняет скрипты сервера, только если его администратор включил локальный режим доверия. По умолчанию режим выключен. Хост без этого режима не выполняет скрипты, а сервер управления отклоняет план со скриптом для такого хоста.

## Риск

:::caution
Скрипт сервера выполняется от имени root в Linux и от имени LocalSystem в Windows. Включайте режим доверия только на хосте, которым сервер управления может управлять без риска.
:::

На хосте с режимом доверия тот, кто контролирует сервер управления, может выполнить на этом хосте любой код. То же верно для того, кто контролирует учётную запись администратора. Защита устроена так:

- Режим доверия локальный. Включить его может только root или администратор, а задание изменить режим не может.
- Сервер управления подписывает каждое задание. Подпись покрывает текст каждого скрипта. Она защищает задание в сети. Она не останавливает того, кто контролирует сервер управления или его базу, потому что сервер подписывает задание по своим данным.
- Изменять скрипт или шаблон может только администратор. Оператор может их читать. Наблюдатель не может читать текст скрипта: API возвращает пустой текст и пустые значения строковых переменных для каждого скрипта профиля и отклоняет запросы списков шаблонов. В скрипт часто вписывают учётные данные, поэтому наблюдатель не должен их видеть.
- Журнал аудита записывает каждое изменение скрипта и каждое задание со скриптами. В каждой записи есть хеш SHA-256 текста скрипта.
- Секрет попадает в скрипт только через переменную окружения. Его нет ни в тексте скрипта, ни в аргументах, ни в журнале.

Схема [модели доверия](/restichub/ru/concepts/trust-model/) показывает проверки агента.

## Включение режима доверия

:::danger[Опасно]
Когда вы включаете режим доверия, сервер управления может выполнить на этом хосте любую команду от имени root или LocalSystem. Взломанный сервер управления или взломанная учётная запись администратора тогда управляет хостом. Сейчас никакая настройка не ограничивает команды одобренными скриптами. Режим, который выполняет только скрипты с одобренным хешем SHA-256, запланирован после MVP ([задача 136](https://github.com/fgbm/restichub/issues/136)).
:::

1. Войдите на хост как root или как администратор.
2. Выполните команду:

   ```sh
   sudo /opt/restichub-agent/bin/restichub-agent trust-server-scripts --enable
   ```

   В Windows откройте PowerShell от имени администратора и выполните `& "$env:ProgramFiles\ResticHub\Agent\restichub-agent.exe" trust-server-scripts --enable`.
3. Дождитесь завершения команды. Новое состояние действует со следующего задания. Серверу управления агент сообщает состояние при каждом подключении. Поэтому, если служба простаивает, команда перезапускает её и ждёт, пока агент снова подключится. Если выполняется задание, команда службу не перезапускает, потому что перезапуск прервёт задание. Команда предложит перезапустить службу после задания: `systemctl restart restichub-agent` на Linux, `Restart-Service restichub-agent` на Windows. Если служба не запущена, сервер управления увидит новое состояние при её запуске. Параметр `--no-restart` отключает перезапуск.
4. Откройте **Хосты** в веб-интерфейсе и выберите имя хоста. Раздел **Скрипты сервера** на странице хоста покажет «Включены» и интерпретаторы, которые нашёл агент. Хост, который ещё не прислал отчёт, показан как «Неизвестно». Фильтр **Скрипты сервера** в списке хостов находит хосты по этому значению.

Чтобы выключить режим, выполните команду с `--disable`. Команда так же перезапускает службу. Агент читает настройку перед каждым заданием, поэтому изменение действует со следующего задания.

Режим можно включить и при регистрации хоста: добавьте `--trust-server-scripts` к `register`. Команда записывает настройку до использования токена, поэтому настройка, которой агент не доверяет, не расходует токен. Если регистрация не удалась, команда возвращает прежнюю настройку. Уже первое подключение сообщает режим. Без этого параметра режим остаётся выключенным.

Команда записывает небольшой файл рядом с каталогом конфигурации агента. В файле одна строка: `server_scripts = enabled` или `server_scripts = disabled`.

| Система | Файл |
|---|---|
| Linux | `/etc/restichub-agent-server-scripts` |
| Windows | `%ProgramData%\ResticHub\Agent-server-scripts` |

Агент доверяет файлу, только если им владеет root или администраторы. Другие учётные записи не должны иметь права записи ни в файл, ни в каталоги над ним. Если файл доступен для записи другой учётной записи, режим считается выключенным. В списке хостов написано «Выключены, файл настройки не защищён». Задание, сервер управления и самообновление изменить этот файл не могут.

Агент сообщает режим и найденные интерпретаторы, а сервер управления сохраняет этот отчёт. Форма профиля предупреждает «Хост не принимает скрипты», если хост плана не включил режим или на нём нет интерпретатора для скрипта. Если режим на хосте выключен, сервер отклоняет план или задание со скриптом. Агент тоже отклоняет такое задание с причиной `server_scripts_disabled`.

## Создание скрипта

1. Откройте **Профили**. Нажмите «Добавить профиль» или выберите имя профиля.
2. Откройте раздел **Скрипты на хосте** и включите его.
3. В списке «До резервного копирования» или «После резервного копирования» нажмите «Пустой скрипт» или «Из шаблона скрипта».
4. Введите название, выберите интерпретатор и напишите скрипт.
5. Нажмите «Сохранить».

Скрипты профиля может изменять только администратор. Оператор видит скрипты и может изменять остальные настройки профиля.

В разделе два списка. Скрипты первого списка выполняются до резервного копирования. Скрипты второго списка выполняются после него. Порядок в списке — это порядок выполнения. Чтобы переместить скрипт, используйте стрелки.

| Фаза | Когда выполняется скрипт |
|---|---|
| До | До резервного копирования. |
| После | После резервного копирования, в том числе когда оно завершилось с ошибкой. |
| При успехе | После резервного копирования, если ни один шаг не завершился с ошибкой. |
| При ошибке | После резервного копирования, если какой-то шаг завершился с ошибкой. |
| В конце | В конце задания, в том числе после отмены. |

### Интерпретаторы

| Интерпретатор | Система | Командная строка агента |
|---|---|---|
| Bash | Linux, macOS | `bash --noprofile --norc <файл>` |
| sh | Linux, macOS | `sh <файл>` |
| PowerShell | Windows | `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <файл>` |
| cmd | Windows | `cmd.exe /D /E:ON /V:OFF /C <файл>` |

Флаги менять нельзя. Групповая политика может задать для компьютера политику выполнения PowerShell, и она сильнее, чем `-ExecutionPolicy Bypass`. Тогда PowerShell отказывается загружать скрипт и завершается с ненулевым кодом, шаг заканчивается ошибкой, а текст ошибки попадает в журнал шага. Попросите администратора домена разрешить на хосте агента политику `RemoteSigned` или `Bypass`. PowerShell сам не останавливается на первой ошибке. Начните скрипт PowerShell со строки `$ErrorActionPreference = 'Stop'`. Начните скрипт Bash со строки `set -euo pipefail`.

### Политика ошибки и лимит времени

Политика определяет, что происходит, если скрипт завершился с ошибкой:

- **Остановить резервное копирование.** Если скрипт фазы «До» завершился с ошибкой, резервное копирование не запускается. Скрипты фаз «При ошибке» и «В конце» всё равно выполняются. Задание завершается с ошибкой.
- **Продолжить и сообщить предупреждение.** Задание продолжается. Шаг отмечен как завершённый с ошибкой, а задание завершается с предупреждением.

Лимит времени задаётся в секундах. Если поле пустое, лимит равен одному часу. Наибольший лимит — 24 часа. Когда лимит истекает, агент останавливает скрипт и все его дочерние процессы.

### Параметры и секреты

Скрипт получает параметры в переменных окружения. У параметра один из трёх видов:

| Вид | Значение |
|---|---|
| Текст | Текст, который вы вводите в профиле. |
| Секрет | Сохранённый секрет с назначением `hook_secret`. |
| Параметр профиля | Значение параметра, который объявляет профиль. Значение задаёт хост, план может его переопределить. См. [Параметры профиля](/restichub/ru/concepts/profile-parameters/). |

Для секрета выберите сохранённый секрет. Нажмите «Новый секрет», чтобы создать его. Сервер управления читает значение только в момент отправки задания и добавляет запись аудита `secret_delivered`. Агент маскирует значение в журнале скрипта. Значение никогда не попадает в аргументы или файлы.

Для параметра профиля выберите параметр в поле «Параметр». Список показывает вид и описание каждого параметра, а поиск находит параметр по имени или описанию. Имя, которого нет в профиле, даёт ошибку «Параметр … не объявлен в профиле». Текстовое значение сервер управления отправляет как маскированное, и агент скрывает его в журнале скрипта. Секретное значение попадает в скрипт как значение своего секрета. Значения параметра нет в тексте скрипта, поэтому сохранённый скрипт не меняется при изменении значения.

## Шаблоны

Шаблон скрипта — это готовый скрипт с описанными параметрами. В профиль попадает копия шаблона, поэтому последующие изменения шаблона профиль не затрагивают.

Шаблоны находятся в разделе **Настройки** → **Скрипты** → **Шаблоны скриптов**. Чтобы открыть страницу шаблона, выберите его имя. Встроенные шаблоны изменить нельзя: нажмите «Сделать копию» и меняйте копию. Встроенные шаблоны:

| Шаблон | Система |
|---|---|
| Дамп PostgreSQL с pg_dump | Linux, Windows |
| Дамп MySQL с mysqldump | Linux |
| Резервная копия MSSQL с sqlcmd | Windows |
| Заметка о VSS | Windows |
| Остановка и запуск службы | Linux, Windows |
| Проверка свободного места на диске | Linux, Windows |
| Выполнение команды | Linux, Windows |

Шаблон задания — это набор скриптов в заданном порядке. В форме профиля нажмите «Взять шаблон задания», чтобы добавить его скрипты. Управлять шаблонами заданий можно в разделе **Настройки** → **Скрипты** → **Шаблоны заданий**. Каждый шаблон задания открывается своей страницей. В шаблоне задания секрет остаётся пустым. Выберите секрет в профиле.

## Что делает агент

Для каждого скрипта агент выполняет такие шаги:

1. Он ещё раз проверяет режим доверия и скрипт.
2. Он записывает скрипт в новый файл в защищённом каталоге своего кеша. Доступ к каталогу есть только у учётной записи агента.
3. Он запускает интерпретатор с неизменными флагами. В путь поиска (`PATH`) входят только каталоги, которыми владеет root или администраторы. Другие учётные записи не могут писать в них и в каталоги над ними. Остальные каталоги агент убирает и один раз за задание перечисляет их в журнале первого скрипта. В Windows `TEMP` и `TMP` указывают на защищённый каталог. Рабочий каталог — тот же защищённый каталог. Раздел «Где выполняется скрипт» описывает окружение.
4. Он читает вывод скрипта, маскирует секретные значения и хранит не больше 256 КиБ на скрипт.
5. Он удаляет файл и каталог.

### Где выполняется скрипт

В Linux скрипт идёт отдельной временной службой systemd, а не потомком агента. Песочницы у этой службы нет: скрипт получает права root и может писать в любую точку хоста. Иначе обычные инструменты не работают. `chpst` нужна возможность сменить учётную запись. Ruby с `ffi` нужна страница памяти, доступная и для записи, и для исполнения. Дампу в `/var/backups` нужна запись вне разрешённых каталогов. Режим доверия и так означает, что сервер управления может выполнить на этом хосте любую команду от root ([ADR-0037](https://github.com/fgbm/restichub/blob/main/design/adr/0037-server-scripts-on-trusted-hosts.md), [ADR-0053](https://github.com/fgbm/restichub/blob/main/design/adr/0053-server-scripts-outside-the-agent-sandbox.md)).

У службы `KillMode=control-group` и `RuntimeMaxSec`, равный лимиту скрипта плюс одна минута. Скрипт получает окружение менеджера служб. К нему добавляются проверенный агентом путь поиска и параметры шага. Параметры агент записывает в защищённый файл рядом со скриптом и удаляет его после прогона. Значение сохраняет каждый байт, в том числе кавычку и перевод строки. Служба, оставшаяся после сбоя агента, работает до конца своего `RuntimeMaxSec`, а следующий запуск агента её останавливает.

В Windows и macOS, а также в Linux без systemd скрипт идёт потомком агента. В таком Linux действует песочница юнита. `ProtectSystem=strict` разрешает запись только в каталог кеша, каталог конфигурации и каталоги восстановления. Фильтр системных вызовов завершает вызов вне списка ошибкой `EPERM`. Поэтому отладочные инструменты вроде `strace` или `perf` в таком скрипте не работают. Чтобы разрешить другой путь, добавьте файл-дополнение:

```ini
# systemctl edit restichub-agent
[Service]
ReadWritePaths=/var/backups
```
Если лимит времени истёк или задание отменено, агент просит скрипт остановиться, а после короткой паузы завершает все его процессы. Повторная отмена завершает их сразу. В Linux сигнал получает вся контрольная группа временной службы.

У скриптов фаз «После», «При успехе», «При ошибке» и «В конце» есть лимит времени после окончания задания. Это оставшееся время плюс не больше 10 минут. Если собственный лимит скрипта короче, действует он.

Процесс, который покидает группу процессов (например, через `setsid` или `nohup`), выходит из дерева, которое завершает агент. В Linux временная служба держит всю контрольную группу, поэтому systemd завершает и такой процесс. Процесс, который уходит из самой службы (например, запускает свою службу через `systemd-run`), остаётся снаружи. Не запускайте из скрипта процессы, которые должны работать долго.

Если агент перезапустится, сервер управления может доставить резервное копирование со скриптом ещё раз, потому что не получил подтверждения. Агент не запустит такое задание снова, потому что скрипт не должен выполняться дважды. Агент вернёт итоговый результат `interrupted`. Сервер управления завершает такое резервное копирование как отменённое и не создаёт оповещение о задании. Пропущенную копию показывает оповещение RPO. Если агент перезапустится без чистой остановки после подтверждения задания, сервер управления потеряет задание. Задание завершится с ошибкой и причиной `agent_lost` и создаст оповещение. Для уже завершённого задания возвращается сохранённый результат, в том числе после выключения режима.

## Сведения о задании

В карточке задания каждый скрипт перечислен по порядку ещё до запуска задания. Каждый шаг показывает статус, время начала, длительность и код выхода. Выберите «Показать журнал шага ...», чтобы прочитать вывод только этого шага. Журнал есть и у шага резервного копирования. «Полный журнал» задания находится под списком шагов.

## Аудит

| Действие | Когда |
|---|---|
| `profile_create`, `profile_update` | Профиль изменился. В записи указаны название, фаза и хеш каждого скрипта, а также имена параметров. |
| `agent_parameters_update` | Значения параметров хоста изменены. Запись содержит имена параметров, их типы и идентификаторы секретов. Значений в записи нет. |
| `script_template_create`, `script_template_update`, `script_template_delete` | Шаблон скрипта изменился. |
| `job_template_create`, `job_template_update`, `job_template_delete` | Шаблон задания изменился. |
| `profile_hooks_removed` | Миграция удаляет хуки профиля. В записи указаны имя профиля, идентификатор и фаза каждого хука. |
| `script_run` | Сервер управления отправляет задание со скриптами. В записи указаны название, фаза и хеш каждого скрипта. |
| `secret_delivered` | Сервер управления отправляет секрет агенту. |

Ни в одной записи нет текста скрипта или значений параметров.

## Роли

| Действие | Администратор | Оператор | Наблюдатель |
|---|---|---|---|
| Читать скрипты и шаблоны | да | да | нет |
| Изменять скрипты профиля | да | нет | нет |
| Изменять шаблон | да | нет | нет |
| Задавать текстовое значение параметра на хосте и в плане | да | да | нет |
| Задавать, менять и удалять секретное значение параметра | да | нет | нет |
| Запускать план | да | да | нет |
