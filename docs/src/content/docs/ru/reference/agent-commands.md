На этой странице описаны команды агента и файлы, которые он хранит. Чтобы добавить новый хост, см. [Добавление хоста](/restichub/ru/getting-started/add-a-host/).

## Установка службы

`register` уже устанавливает службу. Используйте `install-service`, если вы зарегистрировали хост с `--no-service` или если службу нужно починить. Если у хоста нет учётной записи агента, команда откажется работать и предложит сначала выполнить `register`. Команду можно повторять без последствий. Она запускает службу и ждёт подключения так же, как `register`.

Запускайте команды от имени `root` на Linux или администратора на Windows. В примерах указан полный путь установленного агента, потому что команда установки не создаёт ссылку в `PATH`. В Windows агент лежит в `%ProgramFiles%\ResticHub\Agent\restichub-agent.exe`. На этой странице команда называется по своему имени, например `status`.

```sh
sudo /opt/restichub-agent/bin/restichub-agent install-service
sudo /opt/restichub-agent/bin/restichub-agent status
sudo /opt/restichub-agent/bin/restichub-agent uninstall-service
```

- `install-service`, `register`, `restic update` и `uninstall-service` отказываются работать, пока в службе выполняется задание. Сообщение `cannot stop the service` называет причину и следующий шаг.
- `status` печатает идентификатор агента, идентификатор организации, срок действия сертификата, версию и путь restic, состояние службы, адрес сервера управления, состояние соединения, время последнего подключения и последнюю ошибку. Секретов в выводе нет. Если агент не подключён, код возврата равен 1.
- `uninstall-service` останавливает и удаляет службу. Данные остаются, поэтому `install-service` может установить службу снова. Пока выполняется задание, команда отказывается работать, как и `install-service`.

Вывод `status` выглядит так:

```text
agent id:            0192f1e0-0000-7000-8000-000000000001
organization:        0192f1e0-0000-7000-8000-000000000002
certificate expires: 2026-12-01 10:00:00.0 +00:00:00
restic:              restic 0.19.1 (/opt/restichub-agent/bin/restic)
service:             installed, running, start type automatic
control plane:       https://<control-plane>:8443
connection:          connected
last connected:      2026-10-15 09:30:12.0 +00:00:00
```

Все команды агента:

| Команда | Назначение |
| --- | --- |
| `register` | Зарегистрировать хост, установить файлы, скачать restic, установить и запустить службу и дождаться подключения. |
| `install-service` | Установить и запустить службу для имеющейся учётной записи агента. Скачать restic, если его нет. |
| `restic update` | Скачать последний restic и заменить установленный. |
| `uninstall-service` | Остановить и удалить службу. |
| `status` | Напечатать состояние агента. |
| `trust-server-scripts --enable` или `--disable` | Включить или выключить локальный режим доверия для [скриптов сервера](/restichub/ru/guides/scripts/). Выполняйте от имени `root` или администратора. Новое состояние действует со следующего задания. Простаивающую службу команда перезапускает, чтобы сервер управления увидел новое состояние. Службу с выполняемым заданием команда не перезапускает. Параметр `--no-restart` отключает перезапуск. |
| `run` | Запустить агент на переднем плане. Эту команду выполняет служба. Вручную её не запускают. |
| `version`, `--version` или `-V` | Напечатать версию агента и версию протокола, например `restichub-agent 0.1.0+3b21922 (protocol 1.1)`. |
| `help`, `--help` или `-h` | Напечатать справку. |

Агент устанавливает себя сам, копировать файлы вручную не нужно. Команда копирует запущенный агент в каталог программы. Писать туда могут только SYSTEM и «Администраторы» (на Linux — `root`). Если служба работает из этого каталога, команда останавливает её, заменяет файл и запускает службу снова. Служба запускается из каталога программы.

| Объект | Linux | Windows |
| --- | --- | --- |
| Исполняемый файл агента | `/opt/restichub-agent/bin/restichub-agent` | `%ProgramFiles%\ResticHub\Agent\restichub-agent.exe` |
| Restic | `/opt/restichub-agent/bin/restic` | `%ProgramFiles%\ResticHub\Agent\restic.exe` |
| Учётные данные, файл состояния, запись restic, кэш, журнал | `/etc/restichub-agent`, `/var/lib/restichub-agent`, `/var/cache/restichub-agent` | `%ProgramData%\ResticHub\Agent` |
| Каталог восстановления по умолчанию | `/var/lib/restichub-restore` | `%ProgramData%\ResticHub-Restore` |
| Журнал службы | journald | `%ProgramData%\ResticHub\Agent-logs` и журнал событий `ResticHub` |

В прежней установке restic лежал в `/var/lib/restichub-agent/bin`. В прежней установке на Windows он лежал в `%ProgramFiles%\ResticHub\Agent\bin` или в `%ProgramData%\ResticHub\Agent\bin`. Команды `register` и `install-service` останавливают работающую службу, переносят restic в каталог программы, переключают службу на новый путь и удаляют старые копии и пустой каталог `bin`. Агент сверяет перенесённый файл с хешем из записи. Учётная запись агента сохраняется, поэтому хост не регистрируется заново. Служба Windows, которая запускается с новым агентом, переносит restic сама, поэтому она продолжает работать без нового `register`. Чтобы перенести старую установку, распакуйте новый пакет агента и выполните `install-service` от имени `root` или администратора.

На Linux команда записывает `/etc/systemd/system/restichub-agent.service` и включает юнит. На Windows команда записывает службу Windows, которая работает от имени LocalSystem. Служба запускается после перезагрузки.

## Сохранённые учётные данные

Команда записывает учётные данные в защищённый каталог конфигурации:

- Linux: `/etc/restichub-agent/`, владелец — служебная учётная запись или `root`. Права на каталог — `0700`.
- Windows: `%ProgramData%\ResticHub\Agent\`. Список прав доступа (ACL) даёт полный доступ только SYSTEM и группе «Администраторы».

В каталоге лежат такие файлы:

- `agent-key.pem` — закрытый ключ агента. Права на Linux — `0600`.
- `agent-cert.pem` — сертификат агента. В сертификате записаны идентификатор агента и идентификатор организации.
- `ca-chain.pem` — цепочка из выпускающего и корневого удостоверяющих центров.
- `identity.json` — идентификатор агента, идентификатор организации, адрес сервера управления и адрес gRPC.
- `signing-keys.json` — набор ключей подписи заданий из регистрации.
- `signing-key-updates.json` — цепочка принятых обновлений ключей подписи заданий.
- `job-journal.json` — принятые и завершённые задания. Если сервер управления доставит задание повторно, агент не выполнит его второй раз.

Пустой файл блокировки не даёт двум процессам агента менять учётные данные одновременно: `/etc/restichub-agent/identity.lock` на Linux и `%ProgramData%\ResticHub\Agent.lock` на Windows.

Токен никогда не попадает в файл и в журнал.

## Обновление агента

Чтобы обновить агент, не регистрируйте хост заново. Учётные данные остаются.

1. Скачайте новый пакет агента на хост и распакуйте его в пустую папку.
2. Выполните `install-service` из распакованного пакета. На Windows используйте PowerShell с повышенными правами, на Linux — `sudo`.

Команда останавливает работающую службу, копирует новый исполняемый файл в каталог программы, направляет службу на него и запускает её. Учётные данные и запись restic остаются. Команда ждёт соединения, как `register`.

На Windows команда также исправляет права доступа к `%ProgramData%\ResticHub` и `%ProgramFiles%\ResticHub`, если прежний агент или ручное копирование оставили там чужой доступ. Сначала команда задаёт каталогу защищённые права. Затем она проверяет объекты в каталоге. Для каждого каталога верхнего уровня команда печатает одну строку с числом исправленных объектов, например `repaired the access control of 812 entries under C:\ProgramData\ResticHub\Agent`. Каждое удаление и каждое предупреждение печатается отдельной строкой. Чтобы получить строку для каждого исправленного объекта, добавьте к `register` или `install-service` параметр `--verbose`. Старый каталог восстановления `%ProgramData%\ResticHub\Restore` команда не читает. Служба исправляет только запись, которую проводник добавляет для администратора (см. [Папки агента в проводнике](#папки-агента-в-проводнике)).

Исправленные права совпадают с правами новой установки: полный доступ для SYSTEM и группы «Администраторы», владелец — группа «Администраторы». Другие пользователи доступа не получают, даже на чтение: служба работает от имени LocalSystem, а каждую команду агента запускает администратор. Папка, созданная вручную в `%ProgramFiles%`, сохраняет унаследованные права. В клиентской редакции Windows эти права дают полный доступ учётной записи администратора, в том числе в сеансе без повышения прав. Тогда программа из такого сеанса может подменить агент или restic. Она также может держать папку открытой и добавить файл уже после смены прав. Поэтому команда не исправляет `%ProgramFiles%\ResticHub` на месте, если может её перенести. Если другая учётная запись могла изменить уровень или объект этой папки или владеет им, команда останавливает службу. Запись restic команда удаляет до изменения папки. Затем она переносит открытую папку в `<имя>.untrusted-<время>` и удаляет её. Затем команда создаёт папку заново с доступом только для SYSTEM и группы «Администраторы» и копирует в неё запущенный агент. Она заново скачивает и проверяет restic. Если запись restic есть, а самого restic нет, команда устанавливает restic заново. Запускайте команду из распакованного пакета. Текущий каталог не должен быть внутри этой папки. Папку с запущенным агентом или с текущим каталогом команда перенести не может. В этих двух случаях команда завершается до остановки службы. Если другой процесс держит открытым файл в папке, перенести папку нельзя. Тогда команда исправляет её на месте. Каждый уровень от открытого уровня до `Agent` и каждый объект в `Agent` получают доступ только для SYSTEM и группы «Администраторы», владелец — группа «Администраторы». Команда удаляет агент и restic и записывает их заново. Файлы, которые агент не знает, она тоже удаляет, как и при переносе. Запущенную программу команда переименовывает в `<имя>.untrusted-<время>`, а Windows удаляет её при следующей перезагрузке. В выводе команда называет процесс, который держит папку, и печатает предупреждение. До перезагрузки этот процесс может добавить файл. Поэтому команда переводит службу на ручной запуск и сохраняет запись об исправлении в разделе реестра `HKLM\SOFTWARE\ResticHub\Agent`. Пока запись есть, каждая команда `install-service` и `register` перед запуском службы отклоняет неизвестный агенту файл, ссылку или открытый доступ в папке. Закройте процесс, перезагрузите компьютер и снова выполните `install-service`. В её выводе не должно быть строк, которые начинаются с `repaired` или `moved`. Этот запуск снова включает автоматический запуск службы и удаляет запись. Команда `uninstall-service` тоже удаляет запись.

Агент не использует файл, который до исправления могла изменить другая учётная запись:

- Если другая учётная запись могла изменить `Agent-server-scripts`, команда удаляет файл. Режим доверия к серверным скриптам после этого выключен. Чтобы включить его снова, выполните `trust-server-scripts --enable` от имени администратора.
- Если другая учётная запись могла изменить `Agent-restore-roots.txt`, команда переименовывает файл в `Agent-restore-roots.txt.untrusted-<время>`. Дополнительные каталоги восстановления после этого выключены. Проверьте файл и верните ему прежнее имя, чтобы снова включить их.
- В каталоге, который могла изменить другая учётная запись, команда удаляет файлы незавершённой смены сертификата: `rotation.next` и файлы с окончанием `.next`.
- Если другая учётная запись могла прочитать или изменить учётные данные агента, команда выводит предупреждение. Зарегистрируйте хост заново (см. [Повторная регистрация хоста](/restichub/ru/guides/agent-certificates/)).
- Если другая учётная запись могла изменить каталог `Agent` или файл учётных данных, например `ca-chain.pem`, `signing-keys.json` или `identity.json`, `install-service` не использует учётные данные и не запускает службу. Эта учётная запись могла подменить корни доверия агента. Зарегистрируйте хост заново командой `register --force`.

Команда останавливается на объекте, который она не может исправить: объект другого владельца, ссылка, файл с несколькими именами (жёсткая ссылка) или неизвестный агенту файл. Сообщение называет этот объект.

`register --force` выполняет все проверки и исправления до удаления старых учётных данных: каталог программы, каталог данных и состояние службы. Если проверка не прошла, старые файлы учётных данных остаются на месте.

Служба права не исправляет, кроме записи, которую проводник добавляет для администратора. Служба не запускается, если другая учётная запись могла изменить файл учётных данных, их каталог, родительский каталог, резервную копию `Agent.old` прерванной регистрации или подготовленный файл смены сертификата. То же относится к обновлениям ключей подписи, записи restic и журналу заданий. Ту же проверку служба выполняет при каждой повторной загрузке учётных данных после переподключения. Служба также не запускается, если другая учётная запись могла изменить программу агента, каталог над ней или restic. Причину и способ исправления она записывает в журнал событий `ResticHub` (на Linux — в journald) и завершается с кодом 78. Команда `status` показывает ту же причину в строке `identity`.

На Linux исправление не нужно: команда сама задаёт режим `/etc/restichub-agent`, и прежняя установка не оставляет каталога, который команда отвергает.

## Папки агента в проводнике

На Windows проводник может изменить права доступа к папке агента. Что произойдёт, зависит от папки и учётной записи:

- `%ProgramFiles%\ResticHub`: группа «Пользователи» может читать и запускать файлы. Проводник открывает папку без запроса и доступ не добавляет.
- `%ProgramData%\ResticHub` и вложенная папка `Agent`: доступ есть только у SYSTEM и группы «Администраторы». Проводник показывает запрос с кнопкой «Продолжить». После нажатия он добавляет запись с полным доступом для учётной записи, под которой выполнен вход.

| Кто открывает папку | Что происходит | Что делать |
| --- | --- | --- |
| Локальный администратор нажимает «Продолжить» | Служба удаляет запись при следующем запуске: после перезапуска службы или компьютера. Работающая служба находит запись при следующем разрыве соединения с сервером управления: она останавливается, Windows запускает её снова, и служба удаляет запись. Запись удаляет и `install-service`. Служба пишет предупреждение в журнал событий `ResticHub`. Для папки `Agent` предупреждение сообщает, что учётные данные агента были доступны этой учётной записи. | Ничего. Регистрировать хост заново не нужно. Если предупреждение называет папку `Agent` и вы не доверяете этой учётной записи, зарегистрируйте хост заново (см. [Повторная регистрация хоста](/restichub/ru/guides/agent-certificates/)). |
| Пользователь без прав администратора, пароля администратора нет | Проводник не даёт доступа. | Ничего. |
| Пользователь без прав администратора, администратор ввёл пароль в запросе | Проводник добавляет запись для пользователя, под которым выполнен вход, а не для администратора. Служба при каждом запуске завершается с кодом 78. | От имени администратора удалите запись: `icacls "<path>" /remove:g <account> /T`. Затем выполните `install-service` в PowerShell с повышенными правами. Если сообщение называет учётные данные агента, создайте токен кнопкой «Зарегистрировать заново» на странице хоста и выполните с ним `register --force`. |

Если в папке есть файл, который агент отвергает, служба оставляет и запись администратора и завершается с кодом 78. Сообщение называет этот файл. См. [Устранение неполадок](#устранение-неполадок).

Предупреждения читайте в средстве просмотра событий или в PowerShell с повышенными правами (см. [Журналы агента](/restichub/ru/reference/agent-logs/)).

Чтобы посмотреть содержимое папок агента, не используйте проводник. Используйте PowerShell с повышенными правами, например `Get-ChildItem "<path>"` и `icacls "<path>"`.

## Устранение неполадок

Агент завершается с кодом 0 при успехе и с кодом 1 при ошибке. Код 78 означает, что служба запустилась без действующей учётной записи агента или с учётными данными, которые могла изменить другая учётная запись. Тот же код служба возвращает, если restic отсутствует или отличается от своей записи, а также если другая учётная запись могла изменить программу агента или restic. После кода 78 диспетчер служб не перезапускает службу: причину может устранить только администратор. После другого сбоя диспетчер служб перезапускает службу: systemd через 5 секунд, Windows через 5, 30 и затем 60 секунд после каждого следующего сбоя. На Windows счётчик сбоев обнуляется через сутки без сбоев.

| Сообщение или признак | Причина | Действие |
| --- | --- | --- |
| `--url is required for register` | В команде нет `--url`. | Добавьте адрес сервера управления. |
| `give the token with --token, --token-file or --token-stdin` или `give exactly one of ...` | В команде нет источника токена или их несколько. | Укажите только один источник. |

## Ограничения юнита systemd

Юнит оставляет службе пять привилегий (capabilities): `CAP_DAC_READ_SEARCH`, `CAP_DAC_OVERRIDE`, `CAP_CHOWN`, `CAP_FOWNER` и `CAP_FSETID`. Restic работает от имени `root`, поэтому только эти пять привилегий остаются в ограниченном наборе. Без них restic не может прочитать файл другой учётной записи и не может сохранить владельца и права восстановленного файла.

`ProtectSystem=strict` и `ProtectHome=read-only` делают всю файловую систему доступной только для чтения. Исключения — каталог учётных данных (через `ReadWritePaths`) и каталог кэша. Читать источник резервного копирования по-прежнему можно. Restic пишет в локальный репозиторий. Юнит перечисляет в `ReadWritePaths` каждый корень репозиториев из `/etc/restichub-agent-repository-roots.txt` (см. [Локальный репозиторий в Linux](/restichub/ru/getting-started/add-a-repository/#локальный-репозиторий-в-linux)). Не изменяйте юнит вручную: `install-service` записывает его заново. Там же юнит перечисляет каталоги восстановления (`/var/lib/restichub-restore` и каждый каталог из `/etc/restichub-agent-restore-roots.txt`). Команда `install-service` создаёт каталог по умолчанию. Выполните её снова после добавления каталога: systemd читает список при запуске юнита. Источник резервного копирования ниже `/home` остаётся доступным для чтения. `ProtectSystem=strict` без других параметров не защищает `/home`, `/root` и `/run/user`, поэтому юнит также задаёт `ProtectHome=read-only`.

Юнит не задаёт `RestrictSUIDSGID`. С этой опцией systemd запрещает `chmod` выставлять бит setuid или setgid, и восстановление такого файла, например `/usr/bin/sudo`, завершается ошибкой. `NoNewPrivileges=true` и ограниченный набор привилегий остаются, но действуют только на процессы юнита. Программу с битом setuid, которую записало восстановление, запускают вне юнита, с правами её владельца. Оставляйте каталогу восстановления права 0700 или монтируйте его с параметром `nosuid`.

Юнит задаёт `CacheDirectory=restichub-agent` и `RESTIC_CACHE_DIR=/var/cache/restichub-agent`. Так кэш restic остаётся в каталоге, в который юнит может писать.

## Настройки прокси

Если репозиторий доступен только через прокси, restic использует прокси хоста. Агент передаёт дочернему процессу restic переменные `HTTPS_PROXY`, `HTTP_PROXY` и `NO_PROXY` из собственного окружения, а на Linux и macOS — и их варианты строчными буквами. Задайте эти переменные в окружении службы агента, а не в задании.

Дочерний процесс restic не получает других переменных агента, поэтому задание не может перенаправить трафик репозитория.
