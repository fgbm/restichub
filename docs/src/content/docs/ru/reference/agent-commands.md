На этой странице описаны команды агента и файлы, которые он хранит. Чтобы добавить новый хост, см. [Добавление хоста](/restichub/ru/getting-started/add-a-host/).

## Установка службы

`register` уже устанавливает службу. Используйте `install-service`, если вы зарегистрировали хост с `--no-service` или если службу нужно починить. Если у хоста нет учётной записи агента, команда откажется работать и предложит сначала выполнить `register`. Команду можно повторять без последствий. Она запускает службу и ждёт подключения так же, как `register`.

Запускайте команды от имени `root` на Linux или администратора на Windows.

```sh
restichub-agent install-service
restichub-agent status
restichub-agent uninstall-service
```

- `status` печатает идентификатор агента, идентификатор организации, срок действия сертификата, версию и путь restic, состояние службы, адрес сервера управления, состояние соединения, время последнего подключения и последнюю ошибку. Секретов в выводе нет. Если агент не подключён, код возврата равен 1.
- `uninstall-service` останавливает и удаляет службу. Данные остаются, поэтому `install-service` может установить службу снова.

Вывод `status` выглядит так:

```text
agent id:            0192f1e0-0000-7000-8000-000000000001
organization:        0192f1e0-0000-7000-8000-000000000002
certificate expires: 2026-12-01 10:00:00.0 +00:00:00
restic:              restic 0.19.1 (/opt/restichub-agent/bin/restic)
service:             installed, running, start type automatic
control plane:       https://<control-plane>:8443
connection:          connected
last connected:      2026-10-15 09:30:12.0 +00:00:00
```

Все команды агента:

| Команда | Назначение |
| --- | --- |
| `register` | Зарегистрировать хост, установить файлы, скачать restic, установить и запустить службу и дождаться подключения. |
| `install-service` | Установить и запустить службу для имеющейся учётной записи агента. Скачать restic, если его нет. |
| `restic update` | Скачать последний restic и заменить установленный. |
| `uninstall-service` | Остановить и удалить службу. |
| `status` | Напечатать состояние агента. |
| `trust-server-scripts --enable` или `--disable` | Включить или выключить локальный режим доверия для [скриптов сервера](/restichub/ru/guides/scripts/). Выполняйте от имени `root` или администратора. Новое состояние действует со следующего задания. Простаивающую службу команда перезапускает, чтобы сервер управления увидел новое состояние. Службу с выполняемым заданием команда не перезапускает. Параметр `--no-restart` отключает перезапуск. |
| `run` | Запустить агент на переднем плане. Эту команду выполняет служба. Вручную её не запускают. |
| `version`, `--version` или `-V` | Напечатать версию агента и версию протокола, например `restichub-agent 0.1.0+3b21922 (protocol 1.1)`. |
| `help`, `--help` или `-h` | Напечатать справку. |

Агент устанавливает себя сам, копировать файлы вручную не нужно. Команда копирует запущенный агент в каталог программы. Писать туда могут только SYSTEM и «Администраторы» (на Linux — `root`). Если служба работает из этого каталога, команда останавливает её, заменяет файл и запускает службу снова. Служба запускается из каталога программы.

| Объект | Linux | Windows |
| --- | --- | --- |
| Исполняемый файл агента | `/opt/restichub-agent/bin/restichub-agent` | `%ProgramFiles%\ResticHub\Agent\restichub-agent.exe` |
| Restic | `/opt/restichub-agent/bin/restic` | `%ProgramFiles%\ResticHub\Agent\restic.exe` |
| Учётные данные, файл состояния, запись restic, кэш, журнал | `/etc/restichub-agent`, `/var/lib/restichub-agent`, `/var/cache/restichub-agent` | `%ProgramData%\ResticHub\Agent` |
| Корень восстановления по умолчанию | `/var/lib/restichub-restore` | `%ProgramData%\ResticHub-Restore` |
| Журнал службы | journald | `%ProgramData%\ResticHub\Agent-logs` и журнал событий `ResticHub` |

В прежней установке restic лежал в `/var/lib/restichub-agent/bin`. В прежней установке на Windows он лежал в `%ProgramFiles%\ResticHub\Agent\bin` или в `%ProgramData%\ResticHub\Agent\bin`. Команды `register` и `install-service` останавливают работающую службу, переносят restic в каталог программы, переключают службу на новый путь и удаляют старые копии и пустой каталог `bin`. Агент сверяет перенесённый файл с хешем из записи. Учётная запись агента сохраняется, поэтому хост не регистрируется заново. Служба Windows, которая запускается с новым агентом, переносит restic сама, поэтому она продолжает работать без нового `register`. Чтобы перенести старую установку, распакуйте новый пакет агента и выполните `restichub-agent install-service` от имени `root` или администратора.

На Linux команда записывает `/etc/systemd/system/restichub-agent.service` и включает юнит. На Windows команда записывает службу Windows, которая работает от имени LocalSystem. Служба запускается после перезагрузки.

## Сохранённые учётные данные

Команда записывает учётные данные в защищённый каталог конфигурации:

- Linux: `/etc/restichub-agent/`, владелец — служебная учётная запись или `root`. Права на каталог — `0700`.
- Windows: `%ProgramData%\ResticHub\Agent\`. Список прав доступа (ACL) даёт полный доступ только SYSTEM и группе «Администраторы».

В каталоге лежат такие файлы:

- `agent-key.pem` — закрытый ключ агента. Права на Linux — `0600`.
- `agent-cert.pem` — сертификат агента. В сертификате записаны идентификатор агента и идентификатор организации.
- `ca-chain.pem` — цепочка из выпускающего и корневого удостоверяющих центров.
- `identity.json` — идентификатор агента, идентификатор организации, адрес сервера управления и адрес gRPC.
- `signing-keys.json` — набор ключей подписи заданий из регистрации.
- `signing-key-updates.json` — цепочка принятых обновлений ключей подписи заданий.
- `job-journal.json` — принятые и завершённые задания. Если сервер управления доставит задание повторно, агент не выполнит его второй раз.

Пустой файл блокировки не даёт двум процессам агента менять учётные данные одновременно: `/etc/restichub-agent/identity.lock` на Linux и `%ProgramData%\ResticHub\Agent.lock` на Windows.

Токен никогда не попадает в файл и в журнал.

## Обновление агента

Чтобы обновить агент, не регистрируйте хост заново. Учётные данные остаются.

1. Скачайте новый пакет агента на хост и распакуйте его в пустую папку.
2. Выполните `restichub-agent install-service` из распакованного пакета. На Windows используйте PowerShell с повышенными правами, на Linux — `sudo`.

Команда останавливает работающую службу, копирует новый исполняемый файл в каталог программы, направляет службу на него и запускает её. Учётные данные и запись restic остаются. Команда ждёт соединения, как `register`.

На Windows команда также исправляет права доступа к `%ProgramData%\ResticHub` и `%ProgramFiles%\ResticHub`, если прежний агент или ручное копирование оставили там чужой доступ. Сначала команда задаёт каталогу защищённые права. Затем она проверяет объекты в каталоге. Для каждого каталога верхнего уровня команда печатает одну строку с числом исправленных объектов, например `repaired the access control of 812 entries under C:\ProgramData\ResticHub\Agent`. Каждое удаление и каждое предупреждение печатается отдельной строкой. Чтобы получить строку для каждого исправленного объекта, добавьте к `register` или `install-service` параметр `--verbose`. Старый корень восстановления `%ProgramData%\ResticHub\Restore` команда не читает. Служба права не исправляет.

Исправленные права совпадают с правами новой установки: полный доступ для SYSTEM и группы «Администраторы», владелец — группа «Администраторы». Другие пользователи доступа не получают, даже на чтение: служба работает от имени LocalSystem, а каждую команду агента запускает администратор. Папка, созданная вручную в `%ProgramFiles%`, сохраняет унаследованные права. В клиентской редакции Windows эти права дают полный доступ учётной записи администратора, в том числе в сеансе без повышения прав. Тогда программа из такого сеанса может подменить агент или restic. Она также может держать папку открытой и добавить файл уже после смены прав. Поэтому команда не исправляет `%ProgramFiles%\ResticHub` на месте, если может её перенести. Если другая учётная запись могла изменить уровень или объект этой папки или владеет им, команда останавливает службу. Если в папке есть файлы, которые агент не знает, команда завершается до остановки службы и перечисляет все такие файлы. Запись restic команда удаляет до изменения папки. Затем она переносит открытую папку в `<имя>.untrusted-<время>` и удаляет её. Затем команда создаёт папку заново с доступом только для SYSTEM и группы «Администраторы» и копирует в неё запущенный агент. Она заново скачивает и проверяет restic. Если запись restic есть, а самого restic нет, команда устанавливает restic заново. Запускайте команду из распакованного пакета. Текущий каталог не должен быть внутри этой папки. Папку с запущенным агентом или с текущим каталогом команда перенести не может. В этих двух случаях команда завершается до остановки службы. Если другой процесс держит открытым файл в папке, перенести папку нельзя. Тогда команда исправляет её на месте. Каждый уровень от открытого уровня до `Agent` и каждый объект в `Agent` получают доступ только для SYSTEM и группы «Администраторы», владелец — группа «Администраторы». Команда удаляет агент и restic и записывает их заново. Запущенную программу команда переименовывает в `<имя>.untrusted-<время>`, а Windows удаляет её при следующей перезагрузке. В выводе команда называет процесс, который держит папку, и печатает предупреждение. До перезагрузки этот процесс может добавить файл. Поэтому команда переводит службу на ручной запуск и сохраняет запись об исправлении в разделе реестра `HKLM\SOFTWARE\ResticHub\Agent`. Пока запись есть, каждая команда `install-service` и `register` перед запуском службы отклоняет неизвестный агенту файл, ссылку или открытый доступ в папке. Закройте процесс, перезагрузите компьютер и снова выполните `install-service`. В её выводе не должно быть строк, которые начинаются с `repaired` или `moved`. Этот запуск снова включает автоматический запуск службы и удаляет запись. Команда `uninstall-service` тоже удаляет запись.

Агент не использует файл, который до исправления могла изменить другая учётная запись:

- Если другая учётная запись могла изменить `Agent-server-scripts`, команда удаляет файл. Режим доверия к серверным скриптам после этого выключен. Чтобы включить его снова, выполните `restichub-agent trust-server-scripts --enable` от имени администратора.
- Если другая учётная запись могла изменить `Agent-restore-roots.txt`, команда переименовывает файл в `Agent-restore-roots.txt.untrusted-<время>`. Дополнительные корни восстановления после этого выключены. Проверьте файл и верните ему прежнее имя, чтобы снова включить их.
- В каталоге, который могла изменить другая учётная запись, команда удаляет файлы незавершённой смены сертификата: `rotation.next` и файлы с окончанием `.next`.
- Если другая учётная запись могла прочитать или изменить учётные данные агента, команда выводит предупреждение. Зарегистрируйте хост заново (см. [Повторная регистрация хоста](/restichub/ru/guides/enroll-a-host-again/)).
- Если другая учётная запись могла изменить каталог `Agent` или файл учётных данных, например `ca-chain.pem`, `signing-keys.json` или `identity.json`, `install-service` не использует учётные данные и не запускает службу. Эта учётная запись могла подменить корни доверия агента. Зарегистрируйте хост заново командой `register --force`.

Команда останавливается на объекте, который она не может исправить: объект другого владельца, ссылка, файл с несколькими именами (жёсткая ссылка) или неизвестный агенту файл. Сообщение называет этот объект.

`register --force` выполняет все проверки и исправления до удаления старых учётных данных: каталог программы, каталог данных и состояние службы. Если проверка не прошла, старые файлы учётных данных остаются на месте.

Служба права не исправляет. Служба не запускается, если другая учётная запись могла изменить файл учётных данных, их каталог, родительский каталог, резервную копию `Agent.old` прерванной регистрации или подготовленный файл смены сертификата. Причину и способ исправления она записывает в журнал событий `ResticHub` (на Linux — в journald) и завершается с кодом 78. Команда `status` показывает ту же причину в строке `identity`.

На Linux исправление не нужно: команда сама задаёт режим `/etc/restichub-agent`, и прежняя установка не оставляет каталога, который команда отвергает.

## Устранение неполадок

Агент завершается с кодом 0 при успехе и с кодом 1 при ошибке. Код 78 означает, что служба запустилась без действующей учётной записи агента или с учётными данными, которые могла изменить другая учётная запись. Тот же код служба возвращает, если restic отсутствует или отличается от своей записи. После кода 78 диспетчер служб не перезапускает службу: причину может устранить только администратор. После другого сбоя диспетчер служб перезапускает службу: systemd через 5 секунд, Windows через 5, 30 и затем 60 секунд после каждого следующего сбоя. На Windows счётчик сбоев обнуляется через сутки без сбоев.

| Сообщение или признак | Причина | Действие |
| --- | --- | --- |
| `--url is required for register` | В команде нет `--url`. | Добавьте адрес сервера управления. |
| `give the token with --token, --token-file or --token-stdin` или `give exactly one of ...` | В команде нет источника токена или их несколько. | Укажите только один источник. |
| `an agent identity already exists in ...; pass --force to register again` | На хосте уже есть учётная запись агента. | Создайте токен командой «Зарегистрировать заново» в записи хоста и выполните `register --force` (см. [Повторная регистрация хоста](/restichub/ru/guides/enroll-a-host-again/)). |
| `run this command as an administrator ... or as root` | Команда запущена не от имени `root` или администратора. | Выполните её через `sudo` или в PowerShell с повышенными правами. |
| В ошибке названа разница часов | Часы хоста отличаются больше чем на 5 минут. | Исправьте часы (см. [Часы хоста](/restichub/ru/getting-started/add-a-host/#часы-хоста)). Токен остаётся неиспользованным. |
| Ошибка сообщает, что restic не скачивается | Хост не достигает GitHub. | Используйте прокси или файлы для автономной установки (см. [Исполняемый файл restic](/restichub/ru/reference/agent-packages/#исполняемый-файл-restic)). Токен остаётся неиспользованным. |
| Сервер управления отклоняет токен | Токен использован, просрочен или отменён. | Создайте новый токен командой «Добавить хост». |
| `register first: restichub-agent register ...` | `install-service` не нашла действующей учётной записи агента. | Выполните `register` с новым токеном. |
| `service: installed, not running` | Служба остановилась сразу после запуска. | На Linux прочитайте `journalctl -u restichub-agent`. На Windows прочитайте журнал событий `ResticHub` и файлы в `%ProgramData%\ResticHub\Agent-logs` (см. [Журналы агента](/restichub/ru/reference/agent-logs/)). Устраните причину и выполните `install-service`. |
| `connection: not connected ... after the wait` | Агент не может подключиться к серверу управления. | Проверьте часы хоста, межсетевой экран до порта 8443 и адрес. Выполните `status`, чтобы прочитать последнюю ошибку. |
| `cannot load the agent identity in ...; register the agent again with a new enrollment token` | Каталог учётных данных повреждён или пуст. Служба завершается с кодом 78 и не перезапускается. | Создайте токен командой «Зарегистрировать заново» и выполните `register --force` с ним. |
| Хост остаётся в статусе «Ожидает подключения» | Служба не работает или не может связаться с сервером управления. | Выполните `restichub-agent status` и прочитайте строку `last error`. Проверьте службу, часы и межсетевой экран. |
| `the control plane does not accept the protocol version of this agent` | У агента и сервера управления разные версии протокола. | Обновите агент (см. [Версии агента и сервера управления](/restichub/ru/reference/agent-version-compatibility/)). |
| `the agent does not use the identity in ...: ... grants a write access to an account that is not SYSTEM or Administrators` | Служба нашла учётные данные, которые могла изменить другая учётная запись, и не подключилась. | Выполните `restichub-agent install-service` от имени администратора. Если команда сообщит, что учётные данные могла изменить другая учётная запись, зарегистрируйте хост заново командой `register --force`. |
| На странице задания написано «restic не запустился. Сообщение агента: ...» | Агент не смог запустить restic. Сообщение агента называет причину, например `cannot protect the directory ...`. | Устраните названную причину. Если у каталога чужой доступ, выполните `restichub-agent install-service` от имени администратора. |
| `... cannot protect the directory ...ResticHub ... grants the access mask ... to an account that is not SYSTEM or Administrators` | Прежний агент оставил `%ProgramData%\ResticHub` с правами `%ProgramData%`. | Выполните `restichub-agent install-service` из нового пакета от имени администратора. Команда исправит права и сохранит учётные данные. Не удаляйте каталог: в нём лежат учётные данные. |
| `... holds ..., which is not a file of the agent`, `... is owned by an account that is not SYSTEM or Administrators, so the agent does not use it`, `... is a hard link ...` или `... is a reparse point ...` | В каталоге есть неизвестный агенту файл, файл другого владельца, жёсткая ссылка или ссылка. | Проверьте названный файл. ## Ограничения юнита systemd

Юнит оставляет службе пять привилегий (capabilities): `CAP_DAC_READ_SEARCH`, `CAP_DAC_OVERRIDE`, `CAP_CHOWN`, `CAP_FOWNER` и `CAP_FSETID`. Restic работает от имени `root`, поэтому только эти пять привилегий остаются в ограниченном наборе. Без них restic не может прочитать файл другой учётной записи и не может сохранить владельца и права восстановленного файла.

`ProtectSystem=strict` и `ProtectHome=read-only` делают всю файловую систему доступной только для чтения. Исключения — каталог учётных данных (через `ReadWritePaths`) и каталог кэша. Читать источник резервного копирования по-прежнему можно. Restic пишет в локальный репозиторий. Юнит перечисляет в `ReadWritePaths` каждый корень репозиториев из `/etc/restichub-agent-repository-roots.txt` (см. [Локальный репозиторий в Linux](/restichub/ru/guides/add-a-repository/#локальный-репозиторий-в-linux)). Не изменяйте юнит вручную: `install-service` записывает его заново. Там же юнит перечисляет корневые каталоги восстановления (`/var/lib/restichub-restore` и каждый корень из `/etc/restichub-agent-restore-roots.txt`). Команда `install-service` создаёт корневой каталог по умолчанию. Выполните её снова после добавления корневого каталога: systemd читает список при запуске юнита. Источник резервного копирования ниже `/home` остаётся доступным для чтения. `ProtectSystem=strict` без других параметров не защищает `/home`, `/root` и `/run/user`, поэтому юнит также задаёт `ProtectHome=read-only`.

Юнит задаёт `CacheDirectory=restichub-agent` и `RESTIC_CACHE_DIR=/var/cache/restichub-agent`. Так кэш restic остаётся в каталоге, в который юнит может писать.

## Настройки прокси

Если репозиторий доступен только через прокси, restic использует прокси хоста. Агент передаёт дочернему процессу restic переменные `HTTPS_PROXY`, `HTTP_PROXY` и `NO_PROXY` из собственного окружения, а на Linux и macOS — и их варианты строчными буквами. Задайте эти переменные в окружении службы агента, а не в задании.

Дочерний процесс restic не получает других переменных агента, поэтому задание не может перенаправить трафик репозитория.
