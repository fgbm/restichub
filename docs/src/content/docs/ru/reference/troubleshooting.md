title: Устранение неполадок
description: Как найти причину проблемы по её признаку и какое действие её устраняет.
---

Найдите признак в таблицах ниже. Столбец «Действие» говорит, что сделать в первую очередь. Ссылка ведёт к полному описанию.

## Сервер управления

| Признак | Причина | Действие |
|---|---|---|
| `docker compose ps cp` не показывает `(healthy)` | Сервер управления не запустился. | Прочитайте `docker compose logs cp`. Последняя строка с ошибкой называет причину. |
| Сервер управления останавливается с ошибкой о файле ключа | Файл `secrets/restichub_kek` принадлежит не uid 10001, или его могут читать другие. | Выполните `sudo chown 10001:10001 secrets/restichub_kek` и `sudo chmod 400 secrets/restichub_kek`. См. [Файл окружения](/restichub/ru/getting-started/install-control-plane/#файл-окружения). |
| Браузер показывает ошибку сертификата | Caddy не получил сертификат. Межсетевой экран закрывает порт 80 или 443, или DNS-запись указывает на другой адрес. | Откройте порты и исправьте DNS-запись. Прочитайте `docker compose logs caddy`. |
| Экран «Первоначальная настройка» просит токен | В установке нет администратора. | Выполните `docker compose logs cp \| grep setup_token`. См. [Первый администратор](/restichub/ru/getting-started/install-control-plane/#первый-администратор). |
| Сервер управления останавливается с сообщением о режиме организаций | Режим `single` нашёл больше одной активной организации. | Задайте `RESTICHUB_TENANCY_MODE=multi` или приостановите другие организации. См. [Организации](/restichub/ru/guides/organizations/). |

## Хосты

| Признак | Причина | Действие |
|---|---|---|
| `register` останавливается с сообщением о часах | Часы хоста расходятся больше чем на 5 минут. | Исправьте часы. См. [Часы хоста](/restichub/ru/getting-started/add-a-host/#часы-хоста). |
| `register` останавливается: сервер управления отклоняет токен | Хост уже использовал токен, срок токена истёк или администратор отозвал его. | Создайте новый токен через «Добавить хост». |
| `register` получает HTTP 429 | С одного адреса пришло слишком много запросов регистрации. | Подождите минуту. См. [Предел частоты регистрации агентов](/restichub/ru/operations/enrollment-rate-limit/). |
| Хост остаётся в состоянии «Ожидает подключения» | Служба не работает или не может достучаться до порта 8443. | Выполните `restichub-agent status` и прочитайте «last error». Проверьте межсетевой экран для порта 8443. |
| Хост «Не в сети» | Служба остановилась или нет сети до сервера управления. | Прочитайте журнал агента. См. [Журналы агента](/restichub/ru/reference/agent-logs/). |
| Хост показывает «Агент устарел» | Сервер управления не принимает версию протокола агента. | Обновите агент. См. [Обновление](/restichub/ru/guides/upgrade/). |
| Список показывает «Возможный дубль» | Компьютер зарегистрировался снова, а старая запись осталась. | На более новой записи выберите «Заменить старую запись». См. [Возможные дубли](/restichub/ru/guides/agent-certificates/#возможные-дубли). |
| Служба завершается с кодом 78 | У агента нет пригодных учётных данных, или restic отсутствует или отличается от своей записи. Причину называет журнал событий `ResticHub` (на Linux — journald). | Если причина в учётных данных, зарегистрируйте хост заново командой `register --force`. Если причина в restic, выполните `install-service`. Если хост не может скачать restic, добавьте `--restic-archive <ARCHIVE>`. |
| Служба завершается с кодом 78 после того, как папку агента открыли в проводнике | Проводник выдал учётной записи доступ к `%ProgramFiles%\ResticHub` или `%ProgramData%\ResticHub`. Учётная запись не входит в группу локальных администраторов, или Windows не может это подтвердить. | В PowerShell с повышенными правами выполните `restichub-agent install-service`. Команда проверяет папки и восстанавливает их, а её сообщение называет путь и учётную запись. Если сообщение называет учётные данные, создайте токен кнопкой «Зарегистрировать заново» на странице хоста и выполните с ним `restichub-agent register --force`. Чтобы прочитать записи пути, выполните `icacls "<path>"`. Служба сама удаляет запись локального администратора при следующем запуске и пишет предупреждение в журнал `ResticHub`. Читайте журнал в PowerShell с повышенными правами или в средстве просмотра событий. См. [Журналы агента](/restichub/ru/reference/agent-logs/). |

Сообщения команд агента описаны в разделе [Команды и файлы агента](/restichub/ru/reference/agent-commands/#устранение-неполадок).

## Задания

Откройте задание и прочитайте причину под заголовком и журнал невыполненного шага. Все причины перечислены на странице [Коды статусов и причин](/restichub/ru/reference/status-codes/).

| Признак | Причина | Действие |
|---|---|---|
| Задание остаётся в очереди | Хост не в сети, или репозиторий занят другим заданием. | Проверьте хост. См. [Исключительные операции](/restichub/ru/concepts/job-lifecycle/#исключительные-операции). |
| Задание не выполнено с `wrong_password` | Пароль репозитория или ключи доступа неверны. | Исправьте секреты на странице репозитория. |
| Задание не выполнено с `step_failed` | restic завершился с ошибкой. | Прочитайте журнал шага. Последние строки содержат ошибку restic. |
| Задание локального репозитория не выполнено с `read-only file system`, `repository_path_denied` или `repository_read_only` | В Linux служба может писать локальный репозиторий только ниже корня репозиториев. Путь лежит вне корней, или установленный юнит ещё не содержит корень. | Добавьте корень в `/etc/restichub-agent-repository-roots.txt` и выполните `sudo restichub-agent install-service`. См. [Локальный репозиторий в Linux](/restichub/ru/getting-started/add-a-repository/#локальный-репозиторий-в-linux). |
| Задание не выполнено с `stalled` | restic слишком долго не продвигался. | Проверьте источник резервной копии и сеть до репозитория. См. [Тайм-аут простоя](/restichub/ru/concepts/job-lifecycle/#тайм-аут-простоя). |
| Задание не выполнено с `agent_lost` | Хост пропал из сети во время задания. | Проверьте хост. Сервер управления отмечает возможную устаревшую блокировку. |
| Задание не выполнено с `compile_failed` | Профиль больше не подходит хосту. | Откройте профиль и прочитайте предупреждения. |
| Агент отклоняет задание с `server_scripts_disabled` | В задании есть скрипт, а на хосте нет режима доверия. | Включите режим доверия на хосте или уберите скрипт. См. [Скрипты сервера](/restichub/ru/guides/scripts/). |
| У задания состояние «Попытки исчерпаны» | Репозиторий оставался заблокированным после последнего повтора. | Найдите задание, которое держит блокировку. См. [Устаревшие блокировки](/restichub/ru/concepts/job-lifecycle/#устаревшие-блокировки). |
| У задания состояние «Срок истёк» | Задание ждало дольше окна приёма. | Проверьте, что хост в сети во время запуска плана. См. [Окно приёма](/restichub/ru/concepts/job-lifecycle/#окно-приёма). |

## Восстановление

| Признак | Причина | Действие |
|---|---|---|
| Восстановление не выполнено с `restore_target_denied` | Целевой путь лежит вне каталогов восстановления хоста. | Выберите путь внутри каталога восстановления или добавьте каталог. См. [Каталоги восстановления](/restichub/ru/guides/restore/#каталоги-восстановления). |
| Дерево снимка не открывается, `agent_capability_missing` | Агент слишком старый для восстановления. | Обновите агент. |
| Список снимков пуст | В репозитории нет снимков, или их скрывают фильтры. | Нажмите «Сбросить» над списком. |

## Оповещения

| Признак | Причина | Действие |
|---|---|---|
| Письма не приходят | SMTP-сервер сервера управления не задан или отклоняет сообщение. | Нажмите «Отправить тест» у канала. См. [SMTP-сервер](/restichub/ru/guides/alerts/#smtp-сервер). |
| Сервер управления отклоняет канал вебхука | Адрес вне списка разрешённых сетей. | См. [Список разрешённых сетей вебхуков](/restichub/ru/guides/alerts/#список-разрешённых-сетей-вебхуков). |
| Ссылка в сообщении открывает неверный адрес | Публичный адрес сервера управления не задан. | См. [Публичный адрес](/restichub/ru/guides/alerts/#публичный-адрес). |
