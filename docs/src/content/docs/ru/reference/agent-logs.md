---
title: Журналы агента
description: Куда агент пишет журнал на Linux и Windows и как его прочитать.
---

Команда, которую вы запускаете в консоли, например `register` или `status`, пишет журнал в стандартный поток ошибок.

На Linux служба пишет журнал в journald. Прочитайте его командой `journalctl -u restichub-agent`.

На Windows служба пишет журнал в два места:

- Каталог `%ProgramData%\ResticHub\Agent-logs` содержит полный журнал. Читать его могут только SYSTEM и «Администраторы». Файлы называются `agent-000001.log`, `agent-000002.log` и так далее. Текущий файл — файл с наибольшим номером. Когда текущий файл достигает 10 МБ, служба начинает следующий файл. Служба хранит 5 файлов и удаляет самый старый. Каталог находится вне каталога учётных данных, поэтому `register --force` сохраняет журнал.
- Журнал событий `ResticHub` содержит каждое предупреждение и каждую ошибку с источником `ResticHub Agent`. Читать этот журнал могут только SYSTEM, «Администраторы» и члены группы «Читатели журнала событий». Писать в него могут только SYSTEM и «Администраторы». Максимальный размер журнала — 20 МБ. Когда журнал заполнен, Windows перезаписывает самые старые события. Запуск и остановку службы диспетчер служб записывает в журнал «Система».

Одно и то же предупреждение или ошибку служба пишет в журнал событий не чаще одного раза в 60 секунд. Следующая копия сообщает, сколько одинаковых событий служба не записала. Файлы журнала содержат каждое событие.

Перевод строки и управляющий символ в значении заменяются escape-последовательностью, например `\n`. Поэтому каждое событие занимает в файле журнала одну строку.

Чтобы прочитать события, откройте «Просмотр событий» и перейдите в «Журналы приложений и служб» > «ResticHub». В PowerShell выполните команду:

```powershell
Get-WinEvent -LogName ResticHub -MaxEvents 50 | Format-List TimeCreated, LevelDisplayName, Message
```

Чтобы прочитать последние строки полного журнала, выполните в PowerShell с повышенными правами:

```powershell
Get-ChildItem "$env:ProgramData\ResticHub\Agent-logs\agent-*.log" | Sort-Object Name | Select-Object -Last 1 | Get-Content -Tail 100
```

Если служба не может записать файл журнала, она пишет одно предупреждение в журнал событий. Если служба не может записать событие, она пишет одно предупреждение в файл журнала. Затем служба повторяет попытку каждые 60 секунд. Когда файл журнала снова доступен, его первая строка сообщает, сколько событий пропущено. Ошибка журнала не останавливает задание.

Команда `install-service` регистрирует журнал `ResticHub` и источник событий. Если регистрация не удалась, команда удаляет созданные ею разделы реестра и не меняет службу.

Команда `uninstall-service` останавливает службу, удаляет её и затем удаляет источник событий. После этого остаются:

- журнал событий `ResticHub` и его события. «Просмотр событий» показывает текст каждого события под примечанием «Не найдено описание для события с кодом ...»;
- файлы журнала в `%ProgramData%\ResticHub\Agent-logs`.

Чтобы удалить журнал событий, выполните `Remove-EventLog -LogName ResticHub` в Windows PowerShell 5.1 с повышенными правами. Чтобы удалить файлы журнала, удалите каталог `Agent-logs`.

В журнале нет паролей репозиториев и других секретов.
