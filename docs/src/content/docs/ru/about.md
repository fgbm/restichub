ResticHub — сервер управления резервным копированием [restic](https://restic.net) на многих хостах. Сервер управления хранит профили, расписания и секреты. Лёгкий агент на каждом хосте запускает restic по команде сервера управления.

ResticHub находится на предрелизной стадии. MVP проходит приёмочное тестирование на реальных хостах. Интерфейсы ещё могут измениться.

## Задача и для кого она

restic — хорошая программа резервного копирования для одного хоста. Она шифрует данные, исключает повторы и работает со многими хранилищами. Но у restic нет сервера. Каждый хост хранит свою конфигурацию, своё расписание и свой пароль репозитория.

Это проблема для небольшой команды администраторов, у которой десятки или сотни хостов Windows и Linux:

- на каждом хосте своя конфигурация, и никто не видит её целиком в одном месте;
- пароли репозиториев и учётные данные хранилищ лежат в файлах на каждом хосте;
- никто не знает, какой хост не сделал резервную копию ночью, пока не сорвётся восстановление;
- два хоста могут одновременно запустить `prune` для одного репозитория, а зависшая блокировка может останавливать резервное копирование на несколько дней;
- нигде не записано, кто изменил резервное копирование, кто запустил восстановление и кто получил секрет.

ResticHub создан для таких команд. Он подходит и тем, кто уже использует restic со скриптами или с resticprofile и хочет управлять им из одного места.

## Зачем создан ResticHub

Проект начался со списка функций, которые нужны команде. Ни один инструмент для restic не даёт их вместе:

- Один сервер решает, когда запускать каждое задание. На хостах нет расписаний.
- Секреты остаются на сервере. Хост получает пароль репозитория только на одно задание и не сохраняет его.
- Windows и теневые копии тома (VSS) — основной сценарий, а не дополнение.
- Организации с раздельными данными и роли для их участников.
- Панель мониторинга показывает возраст последней успешной копии каждого плана и сравнивает его с целевой точкой восстановления (RPO). Если возраст слишком большой, сервер управления отправляет оповещение.
- Журнал аудита записывает каждое изменение, запуск, восстановление и каждую выдачу секрета.
- Сервер управления не может выполнить произвольную команду на хосте, пока администратор этого хоста не разрешит это.

Другие инструменты дают часть этих функций. Какие именно — показано в [сравнении](#сравнение).

## Как это работает

Сервер управления — это сервер с PostgreSQL, веб-интерфейсом и REST API. Агент работает как служба на каждом хосте и открывает одно исходящее соединение с сервером управления по взаимному TLS. Агент не слушает порты. Когда наступает время плана, сервер управления подписывает задание и отправляет его агенту вместе с секретами для этого задания. Агент проверяет подпись, запускает restic, передаёт ход выполнения и отправляет результат. Агент пишет данные прямо в репозиторий, поэтому данные резервных копий не проходят через сервер управления. Скрипт с сервера управления выполняется только на хосте, где локальный администратор включил режим доверия. Термины описаны в разделе [Основные понятия](/restichub/ru/concepts/overview/), модель безопасности — в разделе [Безопасность для операторов](/restichub/ru/operations/security-for-operators/).

## Что ResticHub не делает

- Это не новый формат резервных копий. Исключение повторов, шифрование и хранение выполняет restic. Репозиторий остаётся обычным репозиторием restic, и его можно открыть без ResticHub.
- ResticHub не создаёт образы дисков, не восстанавливает систему «с нуля» и не копирует виртуальные машины на уровне гипервизора. Он копирует файлы.
- В нём нет встроенных шагов для баз данных, например для Microsoft SQL Server или PostgreSQL. Чтобы сделать дамп базы перед резервным копированием, используйте скрипт на доверенном хосте.
- Он не подключает репозиторий как файловую систему.
- В MVP нет высокой доступности. Если сервер управления остановлен, задания не запускаются, пока он снова не заработает.
- Он не защищает репозиторий от хоста, который взломан во время задания. На время задания у агента есть пароль репозитория. Используйте защиту на стороне хранилища, например версионирование бакета и отдельную копию, в которую хосты не могут писать.

restic сам умеет делать снимок VSS в Windows с параметром `--use-fs-snapshot`. Инструменты на основе restic могут передать restic этот параметр. В таблице у них прочерк, потому что их документация не описывает VSS как отдельную функцию.

Ближе всего к ResticHub проект Arkeep. У него тоже есть сервер, который планирует каждое задание, и агенты с исходящим соединением по взаимному TLS. Различие — в направлении развития. Arkeep находит контейнеры и тома Docker, уже поддерживает OpenID Connect и SFTP и планирует учёт инфраструктуры и управление обновлениями. ResticHub делает упор на хосты Windows, организации с ролями, секреты только на одно задание, подписанные задания и режим доверия для скриптов. Arkeep по умолчанию отправляет анонимный ежедневный отчёт, и его можно выключить ([README](https://github.com/arkeep-io/arkeep)). ResticHub не отправляет телеметрию.

## Когда выбрать другой инструмент

- **Один хост или несколько личных хостов.** Backrest даёт веб-интерфейс для restic на каждом хосте. Им пользуются многие: на дату проверки у репозитория 7,5 тысячи звёзд.
- **Конфигурация в файлах в Git, без сервера.** resticprofile хранит профили в файле и использует планировщик операционной системы.
- **Нужен выпущенный продукт уже сейчас, с поиском томов Docker, OpenID Connect или репозиториями SFTP.** У Arkeep эти функции уже есть. В ResticHub OpenID Connect и SFTP появятся в версии 1.0.
- **Хосты никогда не должны знать учётные данные хранилища.** Сервер репозитория Kopia хранит их на сервере. В ResticHub агент получает пароль репозитория на время задания.
- **Образы дисков и восстановление системы «с нуля».** UrBackup делает резервные копии образов томов Windows и Linux.
- **Классическая система резервного копирования со своими серверами хранения и каталогом копий.** У Bareos есть Director, File Daemon, Storage Daemon и каталог всех резервных копий.
- **Хосты macOS уже сейчас.** Агент ResticHub для macOS появится в версии 1.0.
- **Высокая доступность сервера.** В MVP ResticHub работает один экземпляр сервера управления.
