---

У сервера управления две конечные точки проверки состояния. Каждая отвечает на свой вопрос.

| Конечная точка | Вопрос | Ответ |
|---|---|---|
| `/healthz` | Процесс работает? | `200`, пока процесс отвечает. |
| `/readyz` | Сервер управления работает? | `200`, если база данных отвечает и ни одна фоновая задача не падает. Иначе `503`. |

## Фоновые задачи

Сервер управления запускает фоновые задачи. Они отправляют задания, запускают расписания, отправляют оповещения, удаляют старые данные и сохраняют состояние хостов. За каждой задачей следит супервизор.

Если задача завершилась с паникой или остановилась, супервизор пишет в журнал строку `ERROR` с именем задачи. Затем супервизор запускает задачу снова после паузы. Пауза начинается с 1 с и удваивается до 60 с.

Пока задача падает, `/readyz` отвечает `503`. Перезапущенная задача считается исправной, когда проработала 60 с без остановки. Задача, которая работает раз в час, после перезапуска сразу выполняет проход. Поэтому проход, который всегда падает, держит `/readyz` на `503`.

## Выбор конечной точки

- Для внешнего мониторинга используйте `/readyz`. Сервер управления не оповещает о собственных сбоях. Мониторинг, который опрашивает `/readyz` раз в минуту, покажет упавшую задачу.
- Для проверки состояния контейнера и для проверки балансировщика используйте `/healthz`.

:::caution[Внимание]
Не используйте `/readyz` как проверку готовности или проверку балансировщика, если работает один экземпляр. Ответ `503` на `/readyz` убирает единственный экземпляр из службы. Тогда веб-интерфейс, API и порт агентов перестают работать, хотя упала только одна фоновая задача.
:::

Эталонный набор проверяет `/healthz`. Контейнер остаётся исправным, пока задача падает, а мониторинг сообщает о сбое.

## Поиск упавшей задачи

1. Прочитайте журнал сервера управления:

   ```sh
   docker compose logs cp | grep "a background task stopped"
   ```

2. Найдите в строке поле `task`. В нём имя упавшей задачи.
3. Прочитайте поле `reason` в той же строке. В нём текст паники или ошибка.

Если `/readyz` остаётся на `503`, а строка повторяется, сообщите об этой строке проекту.
