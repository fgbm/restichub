---
title: Восстановление ключа подписи заданий
description: Как оператор восстанавливает запуск сервера управления, когда все ключи подписи заданий отозваны.
---

:::caution[Внимание]
Ни одна команда не выполняет эту процедуру. Меняйте базу данных вручную и только тогда, когда ни один ключ не выведен из обращения из-за компрометации.
:::

Сервер управления подписывает каждое задание текущим ключом подписи. Набор ключей хранит текущий ключ и следующий ключ. Старый ключ сервер управления выводит из обращения, когда все известные подключённые агенты подтвердили новый набор, но не позже чем через 7 дней после начала замены.

Если все ключи отозваны, сервер управления не запускается и выводит сообщение «every stored job signing key is retired; the installation has no active key set». Сервер управления не заменяет отозванные ключи сам. Тихая замена набора скрыла бы возможную компрометацию.

## Когда это происходит

- В каждой строке таблицы `signing_keys` указано время отзыва.
- Ни в одной строке нет текущего ключа и следующего ключа.

## Перед началом

- Сделайте копию базы данных сервера управления.
- Убедитесь, что ни один ключ не отозван из-за компрометации. После компрометации нужна замена ключей. Агент, который отстал больше чем на одну замену, нужно ещё и зарегистрировать заново. См. [Компрометация ключа подписи заданий](job-signing-key-compromise.md). Спросите ответственного за безопасность.

## Порядок действий

1. Остановите сервер управления.
2. Подключитесь к базе данных как учётная запись владельца.
3. Удалите каждую строку таблицы `signing_keys`.
4. Запустите сервер управления. Он создаст новый текущий ключ и новый следующий ключ.
5. Зарегистрируйте каждый агент заново. При регистрации агент получает новый набор ключей.

## Результат

- У установки новый набор ключей.
- Сервер управления подписывает задания новым текущим ключом.
- Агент, который ещё не зарегистрировался заново, отклоняет задание с причиной «unknown key».
