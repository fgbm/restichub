description: Как оператор восстанавливает запуск сервера управления, когда все ключи подписи заданий отозваны.
---

:::caution[Внимание]
ResticHub на этапе проектирования. Эта процедура запланирована на версию 1.0. Она ещё не реализована.
:::

Сервер управления подписывает каждое задание текущим ключом подписи. Набор ключей хранит текущий ключ и следующий ключ. Сервер управления выводит из обращения старый ключ после того, как все известные подключённые агенты подтвердили новый набор. Он делает это не позже чем через 7 дней после начала замены.

Запуск, при котором все ключи отозваны, отказывает с сообщением «every stored job signing key is retired; the installation has no active key set». Сервер управления не заменяет отозванные ключи сам. Молчаливый новый набор скрыл бы возможную компрометацию.

## Когда это происходит

- Каждая строка таблицы `signing_keys` хранит время отзыва.
- Ни в одной строке нет текущего ключа. Ни в одной строке нет следующего ключа.

## Перед началом

- Сделайте копию базы данных сервера управления.
- Убедитесь, что ни один ключ не отозван из-за компрометации. Компрометация требует замены ключей и повторной регистрации агентов. См. [Компрометация ключа подписи заданий](job-signing-key-compromise.md). Спросите владельца безопасности.

## Порядок действий

1. Остановите сервер управления.
2. Подключитесь к базе данных как учётная запись владельца.
3. Удалите каждую строку таблицы `signing_keys`.
4. Запустите сервер управления. Он создаёт новый текущий ключ и новый следующий ключ.
5. Каждый агент регистрируется заново. Регистрация передаёт агенту новый набор ключей.

## Результат

- У установки новый набор ключей.
- Сервер управления подписывает задания новым текущим ключом.
- Агент, который ещё не зарегистрировался заново, отклоняет задание с причиной «unknown key».
