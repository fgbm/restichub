---
title: Версии агента и сервера управления
description: Какие версии агента работают с какой версией сервера управления и как читать отметки версий.
---

Агент и сервер управления общаются по протоколу агента. У протокола есть старший и младший номер. В первом сообщении каждого соединения агент передаёт версию протокола, версию пакета и версию restic.

## Правило совместимости

- У агента и сервера управления должен быть один старший номер.
- Сервер управления принимает агента с младшим номером N или N-1, где N — младший номер самого сервера управления.
- Сервер управления принимает и агента с более новым младшим номером. Необязательные функции включаются, только если агент сообщает о соответствующей возможности.
- Сервер управления отклоняет агента с другим старшим номером или с младшим номером меньше N-1.

Сначала обновите сервер управления, потом агентов. Агент предыдущей младшей версии продолжает работать во время обновления.

## Что происходит при отказе

Сервер управления отправляет типизированный отказ и закрывает соединение. В отказе указаны причина, версия протокола сервера управления и наименьший младший номер, который сервер принимает. Агент записывает отказ в журнал с текстом «the control plane does not accept the protocol version of this agent». Затем он ждёт 60 секунд до следующей попытки подключиться. Обновите агента или сервер управления так, чтобы у обоих был один старший номер.

## Отметки на экране «Хосты»

Экран «Хосты» показывает версию пакета каждого агента в колонке «Версия агента» и отметку. Подсказка к версии: «Протокол <протокол> · сервер управления <версия>».

| Отметка | Значение |
|---|---|
| Нет отметки | Версия агента совпадает с версией сервера управления или новее её. |
| Доступно обновление | Пакет агента старше сервера управления. Агент работает. |
| Версия не поддерживается | Сервер управления не принимает версию протокола агента. Агент не может подключиться. |

В API агентов те же сведения есть в полях `agent_version`, `protocol_version`, `control_plane_version` и `version_status`.

## Ревизия сборки в версии

У релизной сборки версия пакета равна версии рабочего пространства, например `0.1.0`. Сборка добавляет короткую ревизию после знака плюс, например `0.1.0+3b21922`. Локальная сборка добавляет `+dev`. Команда `restichub-agent --version` выводит версию и версию протокола, например `restichub-agent 0.1.0+3b21922 (protocol 1.1)`. Агент отправляет ту же версию при регистрации и в первом сообщении каждого соединения. Сервер управления показывает свою версию в том же формате.

Ревизия не влияет на сравнение. Отметка «Доступно обновление» зависит только от версии пакета.
