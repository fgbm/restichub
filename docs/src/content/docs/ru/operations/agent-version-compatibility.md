---
title: Версии агента и сервера управления
description: Какие версии агента работают с какой версией сервера управления и как читать отметки версий.
---

Агент и сервер управления говорят по протоколу агента (ADR-0008). У протокола есть старший и младший номер. Агент отправляет версию протокола, версию пакета и версию restic в первом сообщении каждого потока (FR-PR-09).

## Правило совместимости

- У агента и сервера управления должен быть один старший номер.
- Сервер управления принимает агента с младшим номером N и младшим номером N-1. N — младший номер сервера управления.
- Сервер управления принимает агента с более новым младшим номером. Необязательные функции включаются, только когда агент сообщает соответствующую возможность.
- Сервер управления отклоняет агента с другим старшим номером или с младшим номером старше N-1.

Сначала обновите сервер управления. Потом обновите агентов. Агент предыдущей младшей версии продолжает работать во время обновления.

## Как выглядит отказ

Сервер управления отправляет типизированный отказ и закрывает поток. Отказ называет причину, версию протокола сервера управления и наименьший младший номер, который сервер принимает. Агент пишет отказ в журнал с текстом «the control plane does not accept the protocol version of this agent». Затем он ждёт 60 секунд до следующего подключения. Обновите агента или сервер управления так, чтобы у обоих был один старший номер.

## Отметки на экране «Хосты»

Экран «Хосты» показывает версию пакета каждого агента и отметку:

| Отметка | Значение |
|---|---|
| Нет отметки | Версия агента равна версии сервера управления или новее. |
| Доступно обновление | Пакет агента старше сервера управления. Агент работает. |
| Версия не поддерживается | Сервер управления отклоняет версию протокола агента. Агент не может подключиться. |

В API агентов те же сведения: `agent_version`, `protocol_version`, `control_plane_version` и `version_status`.
