title: Метрики Prometheus
description: Как опрашивать точку метрик сервера управления и какие метрики она отдаёт.
---

Сервер управления отдаёт своё состояние Prometheus по `GET /metrics` (FR-MN-05, AC-MN-03). Точка использует текстовый формат Prometheus.

## Доступ

Точка не публична. Ей нужны учётные данные с ролью не ниже Наблюдателя. Идентификаторы агентов, планов и репозиториев — данные организации, поэтому сервер управления не отдаёт их анонимному клиенту.

Для опроса используйте API-токен с ролью Наблюдатель. Токен принадлежит одной организации. Ответ содержит метрики этой организации и не содержит данных другой организации (AC-TN-01). Чтобы читать несколько организаций, создайте по одному токену в каждой и добавьте по одному заданию опроса на каждый токен.

1. Создайте в организации API-токен с ролью Наблюдатель.
2. Сохраните значение токена в файл, который читает только пользователь Prometheus.
3. Добавьте задание опроса, которое читает файл как bearer-токен.

```yaml
scrape_configs:
  - job_name: restichub
    scheme: https
    authorization:
      type: Bearer
      credentials_file: /etc/prometheus/restichub-token
    static_configs:
      - targets: ['restichub.example.com']
```

## Метрики

У каждой метрики есть метка `tenant` с идентификатором организации. Идентификатор не содержит персональных данных.

| Метрика | Тип | Метки | Значение |
|---|---|---|---|
| `restichub_last_success_timestamp_seconds` | gauge | `tenant`, `plan` | Unix-время последней успешной резервной копии плана. У плана без успеха нет значения. |
| `restichub_job_duration_seconds` | histogram | `tenant`, `kind` | Длительность выполненных заданий. Границы: 1, 5, 15, 30, 60, 120, 300, 600, 1800 и 3600 секунд. |
| `restichub_jobs_total` | counter | `tenant`, `status` | Задания, достигшие статуса `succeeded`, `failed`, `expired` или `dead_letter`. |
| `restichub_agent_up` | gauge | `tenant`, `agent` | 1, если у агента открыт поток, иначе 0. |
| `restichub_repo_lock_held` | gauge | `tenant`, `repository` | 1, если ожидающее или выполняющееся задание репозитория сообщило о блокировке, иначе 0. |

Чтобы получить оповещение, когда план сутки не завершает резервную копию, используйте это выражение:

```
time() - restichub_last_success_timestamp_seconds > 86400
```
