title: Установка сервера управления
description: Установка сервера управления, веб-интерфейса и порта агентов на один сервер с помощью Docker Compose.
---

Сервер управления работает на одном сервере Linux. На этой странице описано, как установить на один сервер сервер управления, PostgreSQL, веб-интерфейс и порт агентов. Шаги используют Docker Compose. Для крупной установки нужен отдельный проект.

## Части системы

| Часть | Назначение |
|---|---|
| Сервер управления | Хранит конфигурацию, создаёт задания по расписанию, отвечает на запросы API и отдаёт веб-интерфейс |
| PostgreSQL | Хранит данные установки |
| Обратный прокси | Принимает HTTPS-подключения к веб-интерфейсу и сам получает для него сертификат |
| Порт агентов | Принимает подключения агентов на отдельном порту |

В репозитории есть эталонный набор в каталоге `deploy/stage`. Скопируйте файлы из этого каталога в каталог `/opt/restichub` на сервере. Измените все значения для своей установки.

## Перед началом

- Установите Docker Engine и плагин Compose на сервер.
- Выделите серверу не менее 2 ГБ памяти. Эталонный набор работает в этом размере.
- Создайте запись DNS для хоста сервера управления. Используйте тип A и адрес сервера:

  ```text
  stage.example.com.  A  203.0.113.10
  ```

- Откройте на межсетевом экране сервера эти порты:

| Порт | Протокол | Назначение |
|---|---|---|
| 22 | TCP | Администрирование по SSH |
| 80 | TCP | Проверка домена для выпуска сертификата обратным прокси |
| 443 | TCP | Веб-интерфейс и API |
| 8443 | TCP | Порт агентов |

## Файл окружения

Набор берёт настройки из одного файла — `.env` рядом с `compose.yaml`. Скрипт `bootstrap.sh` создаёт этот файл со случайными секретами. Права на файл — `600`.

| Значение | Содержимое |
|---|---|
| `POSTGRES_USER` | Суперпользователь PostgreSQL набора |
| `POSTGRES_PASSWORD` | Пароль этого суперпользователя |
| `POSTGRES_DB` | Имя базы данных установки |
| `RESTICHUB_OWNER_PASSWORD` | Пароль учётной записи владельца. Его используют миграции |
| `RESTICHUB_RUNTIME_PASSWORD` | Пароль рабочей учётной записи. Его использует сервер управления |
| `RESTICHUB_KEK` | Ключ шифрования ключей. Он открывает пароли репозиториев и удостоверяющий центр установки |
| `RESTICHUB_DOMAIN` | Имя хоста сервера управления |
| `RESTICHUB_ACME_EMAIL` | Адрес электронной почты для сертификата |
| `RESTICHUB_IMAGE_TAG` | Тег образа. `edge` следует за самым новым коммитом, `sha-<short>` закрепляет один коммит |
| `RESTICHUB_TENANCY_MODE` | `single` или `multi` |
| `RESTICHUB_TRUSTED_PROXIES` | Сеть обратного прокси в форме CIDR |
| `RESTICHUB_AGENT_ENDPOINT` | Публичный адрес порта агентов. Сервер управления сообщает его агенту |
| `RESTICHUB_AGENT_PORT` | Порт агентов, доступный снаружи. По умолчанию — 8443 |

Значение `RESTICHUB_AGENT_ENDPOINT` хранит адрес, к которому обращаются агенты, например `https://agents.example.com:8443`. Задайте хост и порт своей установки.

## Установка

1. Скопируйте файлы в каталог `/opt/restichub` на сервере.
2. Создайте файл окружения:

   ```sh
   cd /opt/restichub
   ./bootstrap.sh .env stage.example.com admin@example.com
   ```

3. Загрузите образ и запустите набор:

   ```sh
   docker compose up -d
   ```

4. Дождитесь, когда сервер управления ответит на `/healthz`. Служба `migrate` применяет миграции базы данных до запуска сервера управления.
5. Прочитайте одноразовый токен настройки:

   ```sh
   docker compose logs cp | grep setup_token
   ```

## Первый администратор

Откройте `https://stage.example.com` в браузере. Экран запрашивает токен настройки. Введите токен, затем создайте первого администратора с именем пользователя и паролем.

:::danger[Опасно]
Токен настройки — секрет. Не отправляйте его на общий терминал или в чат. Токен нужен один раз, при первом входе, и действует один день.
:::

## Обновление

1. Задайте новый тег в `RESTICHUB_IMAGE_TAG` в файле `.env`.
2. Загрузите образ и перезапустите набор:

   ```sh
   docker compose pull
   docker compose up -d
   ```

Служба `migrate` применяет новые миграции до запуска сервера управления.

## Резервная копия

Сервер управления хранит пароли репозиториев в базе данных. Ключ шифрования ключей их открывает. Удостоверяющий центр установки тоже лежит в базе данных, поэтому одна копия базы данных хранит всю установку.

1. Сделайте копию базы данных:

   ```sh
   docker compose exec -T postgres pg_dump -U restichub_owner restichub > restichub.sql
   ```

2. Скопируйте файл на другой хост.
3. Храните ключ шифрования ключей вместе с копией. Значение есть в файле `.env`.

:::danger[Опасно]
Потеря базы данных или ключа шифрования ключей лишает вас паролей репозиториев и удостоверяющего центра установки. Restic не может открыть репозиторий без его пароля. Храните копии на другом хосте.
:::

## Порт агентов

Агенты подключаются к отдельному порту с взаимной проверкой сертификатов (mTLS). Сервер управления сам расшифровывает это соединение, поэтому обратный прокси не должен стоять перед этим портом.

:::caution[Внимание]
Порт агентов должен быть доступен из каждой сети с агентами. Проверьте правила межсетевого экрана сервера и всего сетевого пути.
:::

Задайте в `RESTICHUB_AGENT_ENDPOINT` адрес, к которому обращаются агенты. Сервер управления выпускает для порта агентов сертификат, в котором этот хост указан как дополнительное имя (SAN).

Зарегистрируйте каждый хост так, как описано в разделе [Регистрация агента](register-an-agent.md).
