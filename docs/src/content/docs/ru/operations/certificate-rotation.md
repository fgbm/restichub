---
title: Замена сертификата агента
description: Как агент обновляет сертификат и что делать, когда сертификат истёк.
---

У каждого агента есть клиентский сертификат для потока mTLS к серверу управления (ADR-0026). Срок действия сертификата ограничен. Агент обновляет сертификат сам, поэтому в обычной работе оператор ничего не делает.

## Срок действия и окно замены

- Срок действия по умолчанию — 30 дней. Чтобы изменить срок, задайте `RESTICHUB_AGENT_CERT_LIFETIME_SECS` или `agent_cert_lifetime_secs` в файле конфигурации. Значение указывается в секундах. Наименьшее значение — 600, наибольшее — 7 776 000 (90 дней).
- Агент просит новый сертификат, когда пройдут две трети срока. При сроке по умолчанию это 20-й день.
- Сервер управления принимает запрос после половины срока. Разрыв между половиной и двумя третями покрывает разницу часов двух сторон.
- Второй подписанный сертификат на одном потоке сервер управления выдаёт не раньше чем через четверть срока и не раньше чем через 30 секунд.

## Что происходит при замене

1. Агент создаёт новую пару ключей. Новый закрытый ключ остаётся в памяти агента до ответа.
2. Агент отправляет запрос на подпись сертификата (CSR) по открытому потоку.
3. Сервер управления проверяет запрос. Агент должен быть активным и предъявить зарегистрированный сертификат. Запрос должен содержать новый открытый ключ. Сервер подписывает сертификат для личности предъявленного сертификата, а не для личности из запроса.
4. Сервер управления хранит новый сертификат как ожидающий и пишет запись аудита `agent_certificate_rotate`.
5. Агент сверяет ответ с корневым удостоверяющим центром, который он закрепил при регистрации. Агент сохраняет новый ключ, новый сертификат и новую цепочку в защищённом каталоге конфигурации и отправляет подтверждение.
6. Сервер управления делает новый сертификат зарегистрированным. С этого момента он отклоняет серийный номер старого сертификата.

Старый сертификат действует до шага 6. Агент, который подключился с новым сертификатом до отправки подтверждения, тоже делает новый сертификат зарегистрированным.

Открытый поток продолжает работать во время замены. Задание, которое выполняется на агенте, продолжается. Новый сертификат агент использует при следующем подключении.

## Файлы на агенте

Агент записывает новые файлы с теми же правилами доступа только для владельца, что и при регистрации. Он записывает их в тот же каталог, где лежит остальное состояние агента. Потеря питания в середине замены не ломает учётные данные. При следующем запуске агент завершает замену или отбрасывает её. Ключ всегда подходит к сертификату.

## Что показывает экран «Хосты»

Экран «Хосты» и API агентов показывают срок действия сертификата и время последней замены для каждого хоста. Хост со сроком менее 3 дней требует внимания: его агент не обновил сертификат.

## Если агент не обновил сертификат

Агент обновляет сертификат только по открытому потоку. Если агент не в сети до истечения сертификата, он не может подключиться и не может обновить сертификат. Тогда журнал агента показывает сообщение:

```text
the agent certificate is expired and cannot rotate; register the agent again with a new enrollment token
```

## Повторная регистрация агента с истёкшим сертификатом

Сервер управления отклоняет подключение с истёкшим сертификатом. Зарегистрируйте хост заново:

1. Создайте новый токен регистрации в веб-интерфейсе. Используйте прежние метки.
2. Выполните на хосте команду регистрации с параметром `--force`:

   ```sh
   restichub-agent register --url https://<control-plane> --token <token> --force
   ```

3. Перезапустите службу агента.

Регистрация создаёт новую учётную запись агента. Старая запись хоста остаётся в списке со старым сертификатом. Отзовите старую запись, когда появится новый хост.
