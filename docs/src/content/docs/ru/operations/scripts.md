title: Скрипты сервера
description: Как запускать скрипты до и после резервного копирования, как администратор хоста включает режим доверия и какой риск принимает этот режим.
---

Скрипт сервера — это скрипт, который вы пишете в веб-интерфейсе. Сервер управления отправляет его вместе с заданием. Агент выполняет его на хосте до или после резервного копирования. Каждый скрипт — отдельный шаг задания со своим статусом, длительностью и журналом.

Хост выполняет скрипты сервера, только если его администратор включил локальный режим доверия. По умолчанию режим выключен. Хост без этого режима по-прежнему выполняет [хуки из списка разрешённых](hooks/).

## Риск

:::caution
Скрипт сервера выполняется от имени root в Linux и от имени LocalSystem в Windows. Включайте режим доверия только на хосте, который сервер управления может контролировать.
:::

На хосте с режимом доверия человек, который контролирует сервер управления, может выполнить на этом хосте любой код. То же верно для человека, который контролирует учётную запись администратора. Защита выглядит так:

- Режим доверия локальный. Включить его может только root или администратор. Задание не может изменить режим.
- Сервер управления подписывает каждое задание. Подпись охватывает текст каждого скрипта.
- Скрипт или шаблон может изменить только администратор. Оператор и наблюдатель могут их читать.
- Журнал аудита записывает каждое изменение скрипта и каждое задание со скриптами. Каждая запись содержит хеш SHA-256 текста скрипта.
- Секрет попадает в скрипт только в переменной окружения. Он не появляется в тексте, в аргументе или в журнале.

## Включите режим доверия

1. Войдите на хост как root или как администратор.
2. Выполните команду:

   ```sh
   sudo restichub-agent trust-server-scripts --enable
   ```

   В Windows откройте PowerShell от имени администратора и выполните `restichub-agent.exe trust-server-scripts --enable`.
3. Откройте **Хосты** в веб-интерфейсе. После нового подключения агента столбец **Скрипты сервера** показывает «Включены». Агент отправляет состояние при каждом подключении, поэтому столбец меняется только при следующем подключении. Чтобы увидеть новое состояние сразу, перезапустите службу агента.

Чтобы выключить режим, выполните команду с `--disable`. Агент читает настройку для каждого задания, поэтому изменение действует со следующего задания.

Команда записывает небольшой файл рядом с каталогом конфигурации агента.

| Система | Файл |
|---|---|
| Linux | `/etc/restichub-agent-server-scripts` |
| Windows | `%ProgramData%\ResticHub\Agent-server-scripts` |

Агент доверяет файлу, только если им владеет root или администраторы и никакая другая учётная запись не может записать файл или каталог выше него. Если другая учётная запись может записать файл, режим выключен. Тогда список хостов показывает «Выключены, файл настройки не защищён». Задание, сервер управления и самообновление не могут изменить файл.

Агент сообщает режим и найденные интерпретаторы. Сервер управления хранит этот отчёт. Он отклоняет план или задание со скриптом для хоста без режима. Агент тоже отклоняет такое задание с причиной `server_scripts_disabled`.

## Напишите скрипт

1. Откройте **Профили**. Нажмите «Добавить профиль» или «Изменить» у профиля.
2. Перейдите в раздел **Скрипты**.
3. В списке «До резервного копирования» или «После резервного копирования» нажмите «Пустой скрипт» или «Из шаблона скрипта».
4. Введите название, выберите интерпретатор и напишите скрипт.
5. Нажмите «Сохранить».

Скрипты профиля может изменять только администратор. Оператор видит скрипты и может изменять остальные настройки профиля.

В разделе два списка. Скрипты первого списка выполняются до резервного копирования. Скрипты второго списка выполняются после него. Порядок в списке — это порядок выполнения. Стрелками переместите скрипт.

| Фаза | Когда выполняется скрипт |
|---|---|
| До | До резервного копирования. |
| После | После резервного копирования, в том числе когда оно завершилось с ошибкой. |
| При успехе | После резервного копирования, если ни один шаг не завершился с ошибкой. |
| При ошибке | После резервного копирования, если какой-то шаг завершился с ошибкой. |
| В конце | В конце задания, в том числе после отмены. |

### Интерпретаторы

| Интерпретатор | Система | Командная строка агента |
|---|---|---|
| Bash | Linux, macOS | `bash --noprofile --norc <файл>` |
| sh | Linux, macOS | `sh <файл>` |
| PowerShell | Windows | `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <файл>` |
| cmd | Windows | `cmd.exe /D /E:ON /V:OFF /C <файл>` |

Флаги неизменны. Групповая политика может задать политику выполнения PowerShell для компьютера. Эта политика сильнее, чем `-ExecutionPolicy Bypass`. Тогда PowerShell отказывается загрузить скрипт и завершается с ненулевым кодом, а шаг завершается ошибкой, и текст ошибки есть в его журнале. Попросите администратора домена разрешить для хоста агента политику `RemoteSigned` или `Bypass`. PowerShell сам не останавливается на первой ошибке. Начните скрипт PowerShell со строки `$ErrorActionPreference = 'Stop'`. Начните скрипт Bash со строки `set -euo pipefail`.

### Политика ошибки и лимит времени

Политика определяет, что делает скрипт с ошибкой:

- **Остановить резервное копирование.** Скрипт фазы «До» с ошибкой останавливает резервное копирование. Скрипты фаз «При ошибке» и «В конце» всё равно выполняются. Задание завершается с ошибкой.
- **Продолжить и сообщить предупреждение.** Задание продолжается. Шаг показан как завершённый с ошибкой, а задание заканчивается с предупреждением.

Лимит времени задаётся в секундах. Пустое значение означает один час. Самый большой лимит — 24 часа. Когда лимит истекает, агент останавливает скрипт и все его дочерние процессы.

### Параметры и секреты

Скрипт читает параметры как переменные окружения. Параметр — это обычный текст или секрет.

Для секрета выберите сохранённый секрет с назначением `hook_secret`. Нажмите «Новый секрет», чтобы создать его. Сервер управления читает значение только когда отправляет задание, и пишет запись аудита `secret_delivered`. Агент маскирует значение в журнале скрипта. Значение никогда не попадает в аргумент или в файл.

## Шаблоны

Шаблон скрипта — это готовый скрипт с описанными параметрами. Профиль получает копию шаблона. Последующее изменение шаблона не меняет профиль.

Откройте **Настройки**, затем **Шаблоны скриптов**, чтобы увидеть шаблоны. Встроенные шаблоны нельзя изменить. Нажмите «Сделать копию», чтобы изменить шаблон. Сервер управления поставляет такие встроенные шаблоны:

| Шаблон | Система |
|---|---|
| Дамп PostgreSQL с pg_dump | Linux, Windows |
| Дамп MySQL с mysqldump | Linux |
| Резервная копия MSSQL с sqlcmd | Windows |
| Заметка о VSS | Windows |
| Остановка и запуск службы | Linux, Windows |
| Проверка свободного места на диске | Linux, Windows |
| Выполнение команды | Linux, Windows |

Шаблон задания — это набор скриптов в заданном порядке. В форме профиля нажмите «Взять шаблон задания», чтобы добавить его скрипты. Откройте **Настройки**, затем **Шаблоны заданий**, чтобы управлять ими. В шаблоне задания секрет остаётся пустым. Выберите секрет в профиле.

## Что делает агент

Для каждого скрипта агент выполняет такие шаги:

1. Он снова проверяет режим доверия и скрипт.
2. Он записывает скрипт в новый файл в защищённом каталоге своего кеша. Каталогом может пользоваться только учётная запись агента.
3. Он запускает интерпретатор с неизменными флагами. Окружение — это окружение агента без переменных, имена которых начинаются с `RESTIC`, плюс параметры скрипта. Путь поиска (`PATH`) содержит только каталоги, владельцем которых есть root или администраторы и в которые не могут писать другие учётные записи, вместе со всеми каталогами выше. Агент убирает остальные каталоги и один раз для каждого задания называет их в журнале первого скрипта. В Windows `TEMP` и `TMP` указывают на защищённый каталог. Рабочий каталог — защищённый каталог.
4. Он читает вывод. Он маскирует секретные значения и хранит не больше 256 КиБ на скрипт.
5. Он удаляет файл и каталог.

При превышении лимита или отмене агент просит скрипт остановиться. После короткой паузы он завершает всё дерево процессов. Вторая отмена завершает дерево сразу.

У скриптов фаз «После», «При успехе», «При ошибке» и «В конце» есть лимит времени после конца задания. Они работают оставшееся время плюс не больше 10 минут или свой лимит, если он короче.

Процесс, который выходит из группы процессов, например через `setsid` или `nohup`, находится вне дерева, которое завершает агент. В Linux настройка службы `KillMode=control-group` завершает такой процесс при остановке службы агента. Не запускайте из скрипта долгоживущие процессы.

Если агент перезапускается во время задания со скриптом, агент не запускает это задание снова. Он отвечает итоговым результатом `interrupted`, потому что скрипт не должен выполняться дважды. Задание, которое уже завершилось, возвращает сохранённый результат, в том числе после выключения режима.

В Linux служба агента работает с `ProtectSystem=strict`. Скрипт может писать только в каталог кеша, каталог конфигурации и корни восстановления. Чтобы разрешить другой путь, добавьте файл drop-in:

```ini
# systemctl edit restichub-agent
[Service]
ReadWritePaths=/var/backups
```

## Сведения о задании

Сведения о задании перечисляют каждый скрипт и хук по порядку ещё до запуска задания. Каждый шаг показывает статус, время начала, длительность и код выхода. Выберите шаг, чтобы прочитать его собственный журнал. У шага резервного копирования тоже есть свой журнал. Полный журнал задания остаётся под шагами.

## Аудит

| Действие | Когда |
|---|---|
| `profile_create`, `profile_update` | Профиль изменился. Запись содержит название, фазу и хеш каждого скрипта, а также имена параметров. |
| `script_template_create`, `script_template_update`, `script_template_delete` | Шаблон скрипта изменился. |
| `job_template_create`, `job_template_update`, `job_template_delete` | Шаблон задания изменился. |
| `script_run` | Сервер управления отправляет задание со скриптами. Запись содержит название, фазу и хеш каждого скрипта. |
| `secret_delivered` | Сервер управления отправляет секрет агенту. |

Ни одна запись не содержит текст скрипта или значение параметра.

## Роли

| Действие | Администратор | Оператор | Наблюдатель |
|---|---|---|---|
| Читать скрипты и шаблоны | да | да | да |
| Изменять скрипты профиля | да | нет | нет |
| Изменять шаблон | да | нет | нет |
| Запускать план | да | да | нет |
