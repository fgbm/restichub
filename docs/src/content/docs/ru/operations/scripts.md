---
title: Скрипты сервера
description: Как запускать скрипты до и после резервного копирования, как администратор хоста включает режим доверия и какой риск принимает этот режим.
---

Скрипт сервера — это скрипт, который вы пишете в веб-интерфейсе. Сервер управления отправляет его вместе с заданием. Агент выполняет его на хосте до или после резервного копирования. Каждый скрипт — отдельный шаг задания со своим статусом, длительностью и журналом.

Хост выполняет скрипты сервера, только если его администратор включил локальный режим доверия. По умолчанию режим выключен. Хост без этого режима не выполняет скрипты, а сервер управления отклоняет план со скриптом для такого хоста.

## Риск

:::caution
Скрипт сервера выполняется от имени root в Linux и от имени LocalSystem в Windows. Включайте режим доверия только на хосте, которым сервер управления может управлять без риска.
:::

На хосте с режимом доверия тот, кто контролирует сервер управления, может выполнить на этом хосте любой код. То же верно для того, кто контролирует учётную запись администратора. Защита устроена так:

- Режим доверия локальный. Включить его может только root или администратор, а задание изменить режим не может.
- Сервер управления подписывает каждое задание. Подпись покрывает текст каждого скрипта.
- Изменять скрипт или шаблон может только администратор. Оператор и наблюдатель могут их читать.
- Журнал аудита записывает каждое изменение скрипта и каждое задание со скриптами. В каждой записи есть хеш SHA-256 текста скрипта.
- Секрет попадает в скрипт только через переменную окружения. Его нет ни в тексте скрипта, ни в аргументах, ни в журнале.

## Включение режима доверия

1. Войдите на хост как root или как администратор.
2. Выполните команду:

   ```sh
   sudo restichub-agent trust-server-scripts --enable
   ```

   В Windows откройте PowerShell от имени администратора и выполните `restichub-agent.exe trust-server-scripts --enable`.
3. Откройте **Хосты** в веб-интерфейсе. Столбец **Скрипты сервера** покажет «Включены» после следующего подключения агента: агент сообщает состояние при каждом подключении. Чтобы увидеть новое состояние сразу, перезапустите службу агента. Хост, который ещё не прислал отчёт, показан как «Неизвестно». Список хостов показывает и интерпретаторы, которые нашёл агент.

Чтобы выключить режим, выполните команду с `--disable`. Агент читает настройку перед каждым заданием, поэтому изменение действует со следующего задания.

Команда записывает небольшой файл рядом с каталогом конфигурации агента. В файле одна строка: `server_scripts = enabled` или `server_scripts = disabled`.

| Система | Файл |
|---|---|
| Linux | `/etc/restichub-agent-server-scripts` |
| Windows | `%ProgramData%\ResticHub\Agent-server-scripts` |

Агент доверяет файлу, только если им владеет root или администраторы. Другие учётные записи не должны иметь права записи ни в файл, ни в каталоги над ним. Если файл доступен для записи другой учётной записи, режим считается выключенным. В списке хостов написано «Выключены, файл настройки не защищён». Задание, сервер управления и самообновление изменить этот файл не могут.

Агент сообщает режим и найденные интерпретаторы, а сервер управления сохраняет этот отчёт. Форма профиля предупреждает «Хост не принимает скрипты», если хост плана не включил режим или на нём нет интерпретатора для скрипта. Если режим на хосте выключен, сервер отклоняет план или задание со скриптом. Агент тоже отклоняет такое задание с причиной `server_scripts_disabled`.

## Создание скрипта

1. Откройте **Профили**. Нажмите «Добавить профиль» или «Изменить» у профиля.
2. Откройте раздел **Скрипты на хосте** и включите его.
3. В списке «До резервного копирования» или «После резервного копирования» нажмите «Пустой скрипт» или «Из шаблона скрипта».
4. Введите название, выберите интерпретатор и напишите скрипт.
5. Нажмите «Сохранить».

Скрипты профиля может изменять только администратор. Оператор видит скрипты и может изменять остальные настройки профиля.

В разделе два списка. Скрипты первого списка выполняются до резервного копирования. Скрипты второго списка выполняются после него. Порядок в списке — это порядок выполнения. Чтобы переместить скрипт, используйте стрелки.

| Фаза | Когда выполняется скрипт |
|---|---|
| До | До резервного копирования. |
| После | После резервного копирования, в том числе когда оно завершилось с ошибкой. |
| При успехе | После резервного копирования, если ни один шаг не завершился с ошибкой. |
| При ошибке | После резервного копирования, если какой-то шаг завершился с ошибкой. |
| В конце | В конце задания, в том числе после отмены. |

### Интерпретаторы

| Интерпретатор | Система | Командная строка агента |
|---|---|---|
| Bash | Linux, macOS | `bash --noprofile --norc <файл>` |
| sh | Linux, macOS | `sh <файл>` |
| PowerShell | Windows | `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <файл>` |
| cmd | Windows | `cmd.exe /D /E:ON /V:OFF /C <файл>` |

Флаги менять нельзя. Групповая политика может задать для компьютера политику выполнения PowerShell, и она сильнее, чем `-ExecutionPolicy Bypass`. Тогда PowerShell отказывается загружать скрипт и завершается с ненулевым кодом, шаг заканчивается ошибкой, а текст ошибки попадает в журнал шага. Попросите администратора домена разрешить на хосте агента политику `RemoteSigned` или `Bypass`. PowerShell сам не останавливается на первой ошибке. Начните скрипт PowerShell со строки `$ErrorActionPreference = 'Stop'`. Начните скрипт Bash со строки `set -euo pipefail`.

### Политика ошибки и лимит времени

Политика определяет, что происходит, если скрипт завершился с ошибкой:

- **Остановить резервное копирование.** Если скрипт фазы «До» завершился с ошибкой, резервное копирование не запускается. Скрипты фаз «При ошибке» и «В конце» всё равно выполняются. Задание завершается с ошибкой.
- **Продолжить и сообщить предупреждение.** Задание продолжается. Шаг отмечен как завершённый с ошибкой, а задание завершается с предупреждением.

Лимит времени задаётся в секундах. Если поле пустое, лимит равен одному часу. Наибольший лимит — 24 часа. Когда лимит истекает, агент останавливает скрипт и все его дочерние процессы.

### Параметры и секреты

Скрипт получает параметры в переменных окружения. Параметр — это обычный текст или секрет.

Для секрета выберите сохранённый секрет с назначением `hook_secret`. Нажмите «Новый секрет», чтобы создать его. Сервер управления читает значение только в момент отправки задания и добавляет запись аудита `secret_delivered`. Агент маскирует значение в журнале скрипта. Значение никогда не попадает в аргументы или файлы.

## Шаблоны

Шаблон скрипта — это готовый скрипт с описанными параметрами. В профиль попадает копия шаблона, поэтому последующие изменения шаблона профиль не затрагивают.

Шаблоны находятся в разделе **Настройки** → **Шаблоны скриптов**. Встроенные шаблоны изменить нельзя: нажмите «Сделать копию» и меняйте копию. Встроенные шаблоны:

| Шаблон | Система |
|---|---|
| Дамп PostgreSQL с pg_dump | Linux, Windows |
| Дамп MySQL с mysqldump | Linux |
| Резервная копия MSSQL с sqlcmd | Windows |
| Заметка о VSS | Windows |
| Остановка и запуск службы | Linux, Windows |
| Проверка свободного места на диске | Linux, Windows |
| Выполнение команды | Linux, Windows |

Шаблон задания — это набор скриптов в заданном порядке. В форме профиля нажмите «Взять шаблон задания», чтобы добавить его скрипты. Управлять шаблонами заданий можно в разделе **Настройки** → **Шаблоны заданий**. В шаблоне задания секрет остаётся пустым. Выберите секрет в профиле.

## Что делает агент

Для каждого скрипта агент выполняет такие шаги:

1. Он ещё раз проверяет режим доверия и скрипт.
2. Он записывает скрипт в новый файл в защищённом каталоге своего кеша. Доступ к каталогу есть только у учётной записи агента.
3. Он запускает интерпретатор с неизменными флагами. Окружение — это окружение агента плюс параметры скрипта. Переменных с именем на `RESTIC` в нём нет. В путь поиска (`PATH`) входят только каталоги, которыми владеет root или администраторы. Другие учётные записи не могут писать в них и в каталоги над ними. Остальные каталоги агент убирает и один раз за задание перечисляет их в журнале первого скрипта. В Windows `TEMP` и `TMP` указывают на защищённый каталог. Рабочий каталог — тот же защищённый каталог.
4. Он читает вывод скрипта, маскирует секретные значения и хранит не больше 256 КиБ на скрипт.
5. Он удаляет файл и каталог.

Если лимит времени истёк или задание отменено, агент просит скрипт остановиться, а после короткой паузы завершает все его процессы. Повторная отмена завершает их сразу.

У скриптов фаз «После», «При успехе», «При ошибке» и «В конце» есть лимит времени после окончания задания. Это оставшееся время плюс не больше 10 минут. Если собственный лимит скрипта короче, действует он.

Процесс, который покидает группу процессов (например, через `setsid` или `nohup`), агент завершить не может. В Linux настройка службы `KillMode=control-group` завершает такой процесс при остановке службы агента. Не запускайте из скрипта процессы, которые должны работать долго.

Если агент перезапустится во время задания со скриптом, он не запустит это задание снова, потому что скрипт не должен выполняться дважды. Агент вернёт итоговый результат `interrupted`. Для уже завершённого задания возвращается сохранённый результат, в том числе после выключения режима.

В Linux служба агента работает с `ProtectSystem=strict`. Скрипт может писать только в каталог кеша, каталог конфигурации и корни восстановления. Чтобы разрешить запись в другой путь, добавьте файл-дополнение (drop-in):

```ini
# systemctl edit restichub-agent
[Service]
ReadWritePaths=/var/backups
```

## Сведения о задании

В карточке задания каждый скрипт перечислен по порядку ещё до запуска задания. Каждый шаг показывает статус, время начала, длительность и код выхода. Выберите «Показать журнал шага ...», чтобы прочитать вывод только этого шага. Журнал есть и у шага резервного копирования. «Полный журнал» задания находится под списком шагов.

## Аудит

| Действие | Когда |
|---|---|
| `profile_create`, `profile_update` | Профиль изменился. В записи указаны название, фаза и хеш каждого скрипта, а также имена параметров. |
| `script_template_create`, `script_template_update`, `script_template_delete` | Шаблон скрипта изменился. |
| `job_template_create`, `job_template_update`, `job_template_delete` | Шаблон задания изменился. |
| `profile_hooks_removed` | Миграция удаляет хуки профиля. В записи указаны имя профиля, идентификатор и фаза каждого хука. |
| `script_run` | Сервер управления отправляет задание со скриптами. В записи указаны название, фаза и хеш каждого скрипта. |
| `secret_delivered` | Сервер управления отправляет секрет агенту. |

Ни в одной записи нет текста скрипта или значений параметров.

## Роли

| Действие | Администратор | Оператор | Наблюдатель |
|---|---|---|---|
| Читать скрипты и шаблоны | да | да | да |
| Изменять скрипты профиля | да | нет | нет |
| Изменять шаблон | да | нет | нет |
| Запускать план | да | да | нет |
