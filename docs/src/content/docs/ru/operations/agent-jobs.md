---
title: Задания агента

---

Агент выполняет шаги подписанного задания с помощью restic, который сам скачал и проверил. Агент не запускает задания по своей инициативе: каждое задание присылает сервер управления.

## Шаги, которые выполняет агент

| Шаг | Команда restic | Результат, который сообщает агент |
|---|---|---|
| `backup` | `restic backup` | Новые, изменённые и неизменённые файлы, добавленные байты, идентификатор снимка, длительность |
| `check` | `restic check` | Число ошибок, рекомендация по исправлению |
| `snapshots` | `restic snapshots` | Список снимков |
| `ls` | `restic ls` | Одна страница записей одного каталога снимка |
| `restore` | `restic restore` | Восстановленные и пропущенные файлы и байты, длительность |
| `forget` | `restic forget` | Снимки, которые правило оставило и удалило |
| `prune` | `restic prune` | Код выхода и журнал |
| `unlock` | `restic unlock` | Код выхода и журнал |
| `unlock_all` | `restic unlock --remove-all` | Код выхода и журнал |
| `stats` | `restic stats` | Размеры и число снимков |
| `test_access` и `init` | `restic cat config` и `restic init` | Код выхода |

Шаг `unlock` снимает только устаревшие блокировки. Только шаг `unlock_all` снимает все блокировки, в том числе действующие. Сервер управления создаёт шаг `unlock_all` только по действию администратора с подтверждением.

Агент сообщает о поддержке возможности `restore-v1`: она означает, что агент выполняет шаги `ls` и `restore`. См. [Восстановление](restore/). Возможность `scripts-v1` означает, что агент выполняет шаг `script` на хосте с режимом доверия. См. [Скрипты сервера](scripts/).

Агент собирает аргументы restic из типизированных полей шага. Каждое позиционное значение он ставит после `--`, а каждую опцию записывает как `--flag=value`. Для команд, которые выводят JSON, агент добавляет `--json`. Значение из задания никогда не превращается в опцию.

## Статус шага

Статус шага агент определяет по коду выхода restic.

| Код выхода | Статус |
|---|---|
| 0 | `success` |
| 3 | `warning` |
| 11 | `retry` |
| 10 и 12 | `config_error` |
| 130 | `cancelled` |
| Любой другой код | `failed` |

Шаг со статусом `warning` не останавливает задание. Любой другой статус, кроме `success`, останавливает задание. В результате задания сохраняется статус шага, который его остановил. Процесс restic агент останавливает в два этапа, если задание отменено, шаг стоит дольше тайм-аута простоя или задание превысило предельную длительность. Сначала агент посылает мягкий сигнал остановки, а после паузы принудительно завершает все дочерние процессы и сообщает `possible_stale_lock`.

## Прогресс и журналы

Пока выполняется резервное копирование, агент отправляет сообщение о прогрессе не чаще одного раза в 2 секунды. В сообщении о прогрессе указаны число обработанных файлов и байтов, процент и файлы, которые restic обрабатывает сейчас.

Агент отправляет строки журнала restic частями. Журнал задания ограничен 1 МиБ. Когда лимит исчерпан, агент добавляет одну строку о том, что журнал обрезан, и отбрасывает остальное. Длина каждой строки ограничена 64 КиБ.

Агент удаляет секреты из каждой строки журнала до отправки. Он заменяет пароль репозитория, учётные данные хранилища и данные пользователя в адресе репозитория на `***`.

## Если сервер управления недоступен

Агент завершает задание, когда соединение с сервером управления потеряно. Он хранит в своём журнале заданий результат каждого шага, результат задания и последние 64 КиБ журнала. Журнал заданий не хранит секреты. Когда соединение возвращается, агент сразу отправляет сохранённый результат. Копия шага в журнале заданий хранит сводку резервного копирования, проверки и статистики. Она не хранит список снимков, страницу шага `ls` и результат `forget`.

## Полоса пропускания и приоритет

Шаг `backup` может задать лимит отправки и лимит загрузки в кибибайтах в секунду. Агент передаёт их в restic как `--limit-upload` и `--limit-download`. Значение 0 означает отсутствие лимита.

Шаг `backup`, `check`, `forget` или `prune` может задать низкий приоритет.

- В Linux агент запускает restic со значением nice 10 и классом ввода-вывода best-effort уровня 7.
- В Windows агент запускает restic в классе приоритета `BELOW_NORMAL_PRIORITY_CLASS`.
