Агент регистрируется вручную одноразовым токеном регистрации. Человек на хосте распаковывает пакет агента в любую папку, например в «Загрузки», и выполняет одну команду. Команда `register` делает всё: устанавливает агент, регистрирует хост, запускает службу и сообщает о подключении.

## Команда регистрации

Веб-интерфейс показывает полную команду в диалоге «Добавить хост». Чтобы открыть его, нажмите «Добавить хост» на экране «Хосты». Команда использует адрес сервера управления и токен:

```sh
restichub-agent register --url https://<control-plane> --token <token>
```

- `--url` — адрес сервера управления. Схема должна быть `https`.
- `--token` — одноразовый токен регистрации. Обычно токен передают этим параметром.
- `--token-file PATH` читает токен из файла. Он подходит для скриптов.
- `--token-stdin` читает токен из стандартного ввода.
- `--ca-file PATH` проверяет сертификат сервера управления по удостоверяющему центру из файла. Без этого параметра агент использует системные корневые сертификаты.
- `--force` заменяет имеющуюся учётную запись агента. Используйте его для повторной регистрации хоста.
- `--no-service` только регистрирует хост и не устанавливает службу. Выполните `install-service` позже.
- `--trust-server-scripts` включает локальный режим доверия до использования токена. Тогда сервер управления может выполнить на этом хосте любую команду от имени root или LocalSystem. Без этого параметра режим выключен. См. [Скрипты](/restichub/ru/operations/scripts/).
- `--restic-archive PATH`, `--restic-sums PATH` и `--restic-sums-sig PATH` задают файлы выпуска restic для автономного хоста (см. раздел «Бинарный файл restic»). Укажите все три параметра или ни одного.

Запускайте команду от имени `root` на Linux или в PowerShell с повышенными правами на Windows («Запуск от имени администратора»). Папка запуска не важна. Агент проверяет права, создаёт свои каталоги и убеждается, что может писать в них, до обращения к серверу управления. Если проверка не прошла, токен остаётся неиспользованным.

Укажите токен ровно одним из параметров `--token`, `--token-file` и `--token-stdin`. Если на хосте уже есть учётная запись агента, команда отказывается работать без параметра `--force`.

Если на хосте нет restic, команда устанавливает его. Этот шаг выполняется после проверки прав и каталогов и до запроса к серверу управления. Если у хоста нет доступа в интернет и нет файлов для автономной установки, команда завершается с ошибкой на этом шаге, а токен остаётся неиспользованным.

После успешной регистрации команда запускает службу и ждёт подключения к серверу управления до 60 секунд. Затем она печатает итог:

```text
registered as backup-host-01 (agent id 0192f1e0-0000-7000-8000-000000000001)
organization:  0192f1e0-0000-7000-8000-000000000002
service:       installed and running
connection:    connected to https://<control-plane>
```

Если шаг не удался, итог называет, что именно не удалось, и подсказывает следующую команду. Если агент не подключён, код возврата не равен нулю. Учётная запись агента остаётся, поэтому следующая команда — `install-service` или `status`, а не новая регистрация.

После `register --no-service` команда сообщает, что служба не установлена, и называет `install-service` следующей командой.

После успешной регистрации хост появляется на экране «Хосты» со статусом «Ожидает подключения». Когда агент открывает соединение, статус меняется на «В сети».

Токен одноразовый: сервер управления гасит его при первой успешной регистрации. Если токен уже использован, просрочен или отозван, команда сообщает об этом понятной ошибкой.

## Часы хоста

Часы хоста должны отличаться от часов сервера управления не более чем на 5 минут. Сертификат, который выпускает сервер управления, начинает действовать за 5 минут до выпуска. Агент принимает сертификат, если он начинает действовать не позже чем через 5 минут после текущего времени хоста. При большей разнице сертификат использовать нельзя.

Перед отправкой токена агент читает время из ответа сервера управления. Если разница больше 5 минут, агент останавливается и показывает местное время, время сервера управления и разницу. Токен остаётся неиспользованным. Если проверка выпущенного сертификата не проходит, агент также показывает, какой сертификат недействителен.

Подключение к серверу управления проверяет сроки сертификатов строго, без допуска на расхождение часов. Следите за точностью часов хоста всё время работы агента.

Как проверить и исправить часы:

- Windows: выполните `w32tm /query /status` в PowerShell с повышенными правами, затем `w32tm /resync`. Или откройте «Параметры», «Время и язык», «Дата и время» и нажмите «Синхронизировать». Проверьте и часовой пояс.
- Linux: выполните `timedatectl status` и найдите `System clock synchronized: yes`. Выполните `timedatectl set-ntp true`, чтобы включить синхронизацию времени. С chrony выполните `chronyc makestep`.

## Сохранённые учётные данные

Команда записывает учётные данные в защищённый каталог конфигурации:

- Linux: `/etc/restichub-agent/`, владелец — служебная учётная запись или `root`. Права на каталог — `0700`.
- Windows: `%ProgramData%\ResticHub\Agent\`. Список прав доступа (ACL) даёт полный доступ только SYSTEM и группе «Администраторы».

В каталоге лежат такие файлы:

- `agent-key.pem` — закрытый ключ агента. Права на Linux — `0600`.
- `agent-cert.pem` — сертификат агента. В сертификате записаны идентификатор агента и идентификатор организации.
- `ca-chain.pem` — цепочка из выпускающего и корневого удостоверяющих центров.
- `identity.json` — идентификатор агента, идентификатор организации, адрес сервера управления и адрес gRPC.
- `signing-keys.json` — набор ключей подписи заданий из регистрации.
- `signing-key-updates.json` — цепочка принятых обновлений ключей подписи заданий.
- `job-journal.json` — принятые и завершённые задания. Если сервер управления доставит задание повторно, агент не выполнит его второй раз.

Пустой файл блокировки не даёт двум процессам агента менять учётные данные одновременно: `/etc/restichub-agent/identity.lock` на Linux и `%ProgramData%\ResticHub\Agent.lock` на Windows.

Токен никогда не попадает в файл и в журнал.

## Проверка соединения

Агент подключается к серверу управления после запуска службы. Он держит одно открытое соединение и отвечает на сигналы активности сервера управления. Соединение использует mTLS. Агент проверяет сервер управления только по корневому удостоверяющему центру установки и никогда не использует системные корневые сертификаты.

Чтобы проверить соединение:

1. Откройте экран «Хосты» в веб-интерфейсе.
2. Найдите хост по имени.
3. Прочитайте статус. Хост, который зарегистрировался, но ещё не подключился, имеет статус «Ожидает подключения». После первого подключения статус — «В сети».
4. Прочитайте вторую строку записи, например `связь 24 с назад · linux · amd64 · агент 0.4.2, есть 0.5.0`. Текст `есть 0.5.0` означает, что пакет агента старее сервера управления (см. [Версии агента и сервера управления](/restichub/ru/operations/agent-version-compatibility/)).
5. Нажмите на имя хоста, чтобы открыть страницу хоста. Раздел «Общее» показывает «Версия агента» и метку «Доступно обновление». Для хоста не в сети страница показывает время «Последняя связь».

Сервер управления отправляет сигнал активности каждые 30 секунд и закрывает соединение после трёх сигналов без ответа. На экране «Обзор» хост считается в сети, если сервер управления слышал его за последние 90 секунд. Оповещение «Хост не в сети» ждёт собственного срока (см. [Оповещения](/restichub/ru/operations/alerts/)).

Когда сервер управления приветствует агента, агент пишет одну строку:

```text
the control plane greeted the agent
```

Агент с отозванным или неизвестным сертификатом пишет такую строку:

```text
the control plane refused the agent identity; check that the agent is enrolled and not revoked
```

После этого агент ждёт 60 секунд и пробует снова. После отзыва зарегистрируйте хост заново (см. [Повторная регистрация хоста](/restichub/ru/operations/enroll-a-host-again/)).

Чтобы прочитать состояние агента на хосте, выполните команду `restichub-agent status` (см. «Установка службы»).

## Следующий шаг

Добавьте репозиторий и инициализируйте его с этого хоста. См. [Добавление репозитория](/restichub/ru/operations/add-a-repository/).

## Установка службы

`register` уже устанавливает службу. Используйте `install-service`, если вы зарегистрировали хост с `--no-service` или если службу нужно починить. Если у хоста нет учётной записи агента, команда откажется работать и предложит сначала выполнить `register`. Команду можно повторять без последствий. Она запускает службу и ждёт подключения так же, как `register`.

Запускайте команды от имени `root` на Linux или администратора на Windows.

```sh
restichub-agent install-service
restichub-agent status
restichub-agent uninstall-service
```

- `status` печатает идентификатор агента, идентификатор организации, срок действия сертификата, версию и путь restic, состояние службы, адрес сервера управления, состояние соединения, время последнего подключения и последнюю ошибку. Секретов в выводе нет. Если агент не подключён, код возврата равен 1.
- `uninstall-service` останавливает и удаляет службу. Данные остаются, поэтому `install-service` может установить службу снова.

Вывод `status` выглядит так:

```text
agent id:            0192f1e0-0000-7000-8000-000000000001
organization:        0192f1e0-0000-7000-8000-000000000002
certificate expires: 2026-12-01 10:00:00.0 +00:00:00
restic:              restic 0.19.1 (/opt/restichub-agent/bin/restic)
service:             installed, running, start type automatic
control plane:       https://<control-plane>:8443
connection:          connected
last connected:      2026-10-15 09:30:12.0 +00:00:00
```

Все команды агента:

| Команда | Назначение |
| --- | --- |
| `register` | Зарегистрировать хост, установить файлы, скачать restic, установить и запустить службу и дождаться подключения. |
| `install-service` | Установить и запустить службу для имеющейся учётной записи агента. Скачать restic, если его нет. |
| `restic update` | Скачать последний restic и заменить установленный. |
| `uninstall-service` | Остановить и удалить службу. |
| `status` | Напечатать состояние агента. |
| `trust-server-scripts --enable` или `--disable` | Включить или выключить локальный режим доверия для [скриптов сервера](/restichub/ru/operations/scripts/). Выполняйте от имени `root` или администратора. Новое состояние действует со следующего задания. Простаивающую службу команда перезапускает, чтобы сервер управления увидел новое состояние. Службу с выполняемым заданием команда не перезапускает. Параметр `--no-restart` отключает перезапуск. |
| `run` | Запустить агент на переднем плане. Эту команду выполняет служба. Вручную её не запускают. |
| `version`, `--version` или `-V` | Напечатать версию агента и версию протокола, например `restichub-agent 0.1.0+3b21922 (protocol 1.1)`. |
| `help`, `--help` или `-h` | Напечатать справку. |

Агент устанавливает себя сам, копировать файлы вручную не нужно. Команда копирует запущенный агент в каталог программы. Писать туда могут только SYSTEM и «Администраторы» (на Linux — `root`). Если служба работает из этого каталога, команда останавливает её, заменяет файл и запускает службу снова. Служба запускается из каталога программы.

| Объект | Linux | Windows |
| --- | --- | --- |
| Исполняемый файл агента | `/opt/restichub-agent/bin/restichub-agent` | `%ProgramFiles%\ResticHub\Agent\restichub-agent.exe` |
| Restic | `/opt/restichub-agent/bin/restic` | `%ProgramFiles%\ResticHub\Agent\restic.exe` |
| Учётные данные, файл состояния, запись restic, кэш, журнал | `/etc/restichub-agent`, `/var/lib/restichub-agent`, `/var/cache/restichub-agent` | `%ProgramData%\ResticHub\Agent` |
| Корень восстановления по умолчанию | `/var/lib/restichub-restore` | `%ProgramData%\ResticHub-Restore` |
| Журнал службы | journald | `%ProgramData%\ResticHub\Agent-logs` и журнал событий `ResticHub` |

В прежней установке restic лежал в `/var/lib/restichub-agent/bin`. В прежней установке на Windows он лежал в `%ProgramFiles%\ResticHub\Agent\bin` или в `%ProgramData%\ResticHub\Agent\bin`. Команды `register` и `install-service` останавливают работающую службу, переносят restic в каталог программы, переключают службу на новый путь и удаляют старые копии и пустой каталог `bin`. Агент сверяет перенесённый файл с хешем из записи. Учётная запись агента сохраняется, поэтому хост не регистрируется заново. Служба Windows, которая запускается с новым агентом, переносит restic сама, поэтому она продолжает работать без нового `register`. Чтобы перенести старую установку, распакуйте новый пакет агента и выполните `restichub-agent install-service` от имени `root` или администратора.

На Linux команда записывает `/etc/systemd/system/restichub-agent.service` и включает юнит. На Windows команда записывает службу Windows, которая работает от имени LocalSystem. Служба запускается после перезагрузки.

### Обновление агента

Чтобы обновить агент, не регистрируйте хост заново. Учётные данные остаются.

1. Скачайте новый пакет агента на хост и распакуйте его в пустую папку.
2. Выполните `restichub-agent install-service` из распакованного пакета. На Windows используйте PowerShell с повышенными правами, на Linux — `sudo`.

Команда останавливает работающую службу, копирует новый исполняемый файл в каталог программы, направляет службу на него и запускает её. Учётные данные и запись restic остаются. Команда ждёт соединения, как `register`.

На Windows команда также исправляет права доступа к `%ProgramData%\ResticHub`, если прежний агент оставил там чужой доступ. Сначала команда задаёт каталогу защищённые права. Затем она проверяет объекты в каталоге. Команда печатает одну строку для каждого изменения. Старый корень восстановления `%ProgramData%\ResticHub\Restore` команда не читает. Служба права не исправляет.

Агент не использует файл, который до исправления могла изменить другая учётная запись:

- Если другая учётная запись могла изменить `Agent-server-scripts`, команда удаляет файл. Режим доверия к серверным скриптам после этого выключен. Чтобы включить его снова, выполните `restichub-agent trust-server-scripts --enable` от имени администратора.
- Если другая учётная запись могла изменить `Agent-restore-roots.txt`, команда переименовывает файл в `Agent-restore-roots.txt.untrusted-<время>`. Дополнительные корни восстановления после этого выключены. Проверьте файл и верните ему прежнее имя, чтобы снова включить их.
- В каталоге, который могла изменить другая учётная запись, команда удаляет файлы незавершённой смены сертификата: `rotation.next` и файлы с окончанием `.next`.
- Если другая учётная запись могла прочитать или изменить учётные данные агента, команда выводит предупреждение. Зарегистрируйте хост заново (см. [Повторная регистрация хоста](/restichub/ru/operations/enroll-a-host-again/)).
- Если другая учётная запись могла изменить каталог `Agent` или файл учётных данных, например `ca-chain.pem`, `signing-keys.json` или `identity.json`, `install-service` не использует учётные данные и не запускает службу. Эта учётная запись могла подменить корни доверия агента. Зарегистрируйте хост заново командой `register --force`.

Команда останавливается на объекте, который она не может исправить: объект другого владельца, ссылка, файл с несколькими именами (жёсткая ссылка) или неизвестный агенту файл. Сообщение называет этот объект.

На Linux исправление не нужно: команда сама задаёт режим `/etc/restichub-agent`, и прежняя установка не оставляет каталога, который команда отвергает.

### Журналы агента

Команда, которую вы запускаете в консоли, например `register` или `status`, пишет журнал в стандартный поток ошибок.

На Linux служба пишет журнал в journald. Прочитайте его командой `journalctl -u restichub-agent`.

На Windows служба пишет журнал в два места:

- Каталог `%ProgramData%\ResticHub\Agent-logs` содержит полный журнал. Читать его могут только SYSTEM и «Администраторы». Файлы называются `agent-000001.log`, `agent-000002.log` и так далее. Текущий файл — файл с наибольшим номером. Когда текущий файл достигает 10 МБ, служба начинает следующий файл. Служба хранит 5 файлов и удаляет самый старый. Каталог находится вне каталога учётных данных, поэтому `register --force` сохраняет журнал.
- Журнал событий `ResticHub` содержит каждое предупреждение и каждую ошибку с источником `ResticHub Agent`. Читать этот журнал могут только SYSTEM, «Администраторы» и члены группы «Читатели журнала событий». Писать в него могут только SYSTEM и «Администраторы». Максимальный размер журнала — 20 МБ. Когда журнал заполнен, Windows перезаписывает самые старые события. Запуск и остановку службы диспетчер служб записывает в журнал «Система».

Одно и то же предупреждение или ошибку служба пишет в журнал событий не чаще одного раза в 60 секунд. Следующая копия сообщает, сколько одинаковых событий служба не записала. Файлы журнала содержат каждое событие.

Перевод строки и управляющий символ в значении заменяются escape-последовательностью, например `\n`. Поэтому каждое событие занимает в файле журнала одну строку.

Чтобы прочитать события, откройте «Просмотр событий» и перейдите в «Журналы приложений и служб» > «ResticHub». В PowerShell выполните команду:

```powershell
Get-WinEvent -LogName ResticHub -MaxEvents 50 | Format-List TimeCreated, LevelDisplayName, Message
```

Чтобы прочитать последние строки полного журнала, выполните в PowerShell с повышенными правами:

```powershell
Get-ChildItem "$env:ProgramData\ResticHub\Agent-logs\agent-*.log" | Sort-Object Name | Select-Object -Last 1 | Get-Content -Tail 100
```

Если служба не может записать файл журнала, она пишет одно предупреждение в журнал событий. Если служба не может записать событие, она пишет одно предупреждение в файл журнала. Затем служба повторяет попытку каждые 60 секунд. Когда файл журнала снова доступен, его первая строка сообщает, сколько событий пропущено. Ошибка журнала не останавливает задание.

Команда `install-service` регистрирует журнал `ResticHub` и источник событий. Если регистрация не удалась, команда удаляет созданные ею разделы реестра и не меняет службу.

Команда `uninstall-service` останавливает службу, удаляет её и затем удаляет источник событий. После этого остаются:

- журнал событий `ResticHub` и его события. «Просмотр событий» показывает текст каждого события под примечанием «Не найдено описание для события с кодом ...»;
- файлы журнала в `%ProgramData%\ResticHub\Agent-logs`.

Чтобы удалить журнал событий, выполните `Remove-EventLog -LogName ResticHub` в Windows PowerShell 5.1 с повышенными правами. Чтобы удалить файлы журнала, удалите каталог `Agent-logs`.

В журнале нет паролей репозиториев и других секретов.

### Устранение неполадок

Агент завершается с кодом 0 при успехе, с кодом 1 при ошибке и с кодом 78, если служба запустилась без действующей учётной записи агента. После кода 78 юнит systemd не перезапускает службу, потому что перезапуск не создаст учётную запись.

| Сообщение или признак | Причина | Действие |
| --- | --- | --- |
| `--url is required for register` | В команде нет `--url`. | Добавьте адрес сервера управления. |
| `give the token with --token, --token-file or --token-stdin` или `give exactly one of ...` | В команде нет источника токена или их несколько. | Укажите только один источник. |
| `an agent identity already exists in ...; pass --force to register again` | На хосте уже есть учётная запись агента. | Создайте токен командой «Зарегистрировать заново» в записи хоста и выполните `register --force` (см. [Повторная регистрация хоста](/restichub/ru/operations/enroll-a-host-again/)). |
| `run this command as an administrator ... or as root` | Команда запущена не от имени `root` или администратора. | Выполните её через `sudo` или в PowerShell с повышенными правами. |
| В ошибке названа разница часов | Часы хоста отличаются больше чем на 5 минут. | Исправьте часы (см. «Часы хоста»). Токен остаётся неиспользованным. |
| Ошибка сообщает, что restic не скачивается | Хост не достигает GitHub. | Используйте прокси или файлы для автономной установки (см. «Исполняемый файл restic»). Токен остаётся неиспользованным. |
| Сервер управления отклоняет токен | Токен использован, просрочен или отменён. | Создайте новый токен командой «Добавить хост». |
| `register first: restichub-agent register ...` | `install-service` не нашла действующей учётной записи агента. | Выполните `register` с новым токеном. |
| `service: installed, not running` | Служба остановилась сразу после запуска. | На Linux прочитайте `journalctl -u restichub-agent`. На Windows прочитайте журнал событий `ResticHub` и файлы в `%ProgramData%\ResticHub\Agent-logs` (см. «Журналы агента»). Устраните причину и выполните `install-service`. |
| `connection: not connected ... after the wait` | Агент не может подключиться к серверу управления. | Проверьте часы хоста, межсетевой экран до порта 8443 и адрес. Выполните `status`, чтобы прочитать последнюю ошибку. |
| `cannot load the agent identity in ...; register the agent again with a new enrollment token` | Каталог учётных данных повреждён или пуст. Служба завершается с кодом 78 и не перезапускается. | Создайте токен командой «Зарегистрировать заново» и выполните `register --force` с ним. |
| Хост остаётся в статусе «Ожидает подключения» | Служба не работает или не может связаться с сервером управления. | Выполните `restichub-agent status` и прочитайте строку `last error`. Проверьте службу, часы и межсетевой экран. |
| `the control plane does not accept the protocol version of this agent` | У агента и сервера управления разные версии протокола. | Обновите агент (см. [Версии агента и сервера управления](/restichub/ru/operations/agent-version-compatibility/)). |
| `... cannot protect the directory ...ResticHub ... grants the access mask ... to an account that is not SYSTEM or Administrators` | Прежний агент оставил `%ProgramData%\ResticHub` с правами `%ProgramData%`. | Выполните `restichub-agent install-service` из нового пакета от имени администратора. Команда исправит права и сохранит учётные данные. Не удаляйте каталог: в нём лежат учётные данные. |
| `... holds ..., which is not a file of the agent`, `... is owned by an account that is not SYSTEM or Administrators, so the agent does not use it`, `... is a hard link ...` или `... is a reparse point ...` | В каталоге есть неизвестный агенту файл, файл другого владельца, жёсткая ссылка или ссылка. | Проверьте названный файл. Удалите этот файл, а не каталог. Выполните команду снова. Если файл относится к учётным данным агента, например `agent-key.pem`, после удаления зарегистрируйте хост заново. |
| `the identity of this host could be changed by another account (...)` | Прежний агент дал другой учётной записи право менять каталог `Agent` или файл учётных данных. Исправление не меняет доступ к этим объектам, поэтому каждый запуск `install-service` снова отказывает. `install-service` не устанавливает службу и останавливает работающую службу. Служба остаётся установленной. | Создайте токен командой «Зарегистрировать заново» на странице хоста. Выполните `restichub-agent register --force --url <URL> --token <TOKEN>` (см. [Повторная регистрация хоста](/restichub/ru/operations/enroll-a-host-again/)). Команда удаляет прежние файлы учётных данных и записывает новые. |
| `warning: another account could read or change ..., so the agent identity may be exposed` | Прежний агент дал другой учётной записи право читать или менять учётные данные агента. Исправление закрыло этот доступ, но ключ мог стать известен. | Зарегистрируйте хост заново (см. [Повторная регистрация хоста](/restichub/ru/operations/enroll-a-host-again/)). |
| `... is owned by an account that is not SYSTEM or Administrators, so that account may have put files there` | Каталог агента принадлежит другой учётной записи. Агент его не исправляет. | Проверьте файлы в каталоге. Затем выполните две строки PowerShell из сообщения: `icacls <каталог> /setowner *S-1-5-32-544` и `Set-Acl` с SDDL `O:BAG:SYD:P(A;OICI;FA;;;SY)(A;OICI;FA;;;BA)`. Выполните команду снова. |
| Команда не принимает каталог или файл | Владелец объекта — другая учётная запись, или она может в него писать. | Верните владельца и доступ SYSTEM и «Администраторы» (Linux: `root`, права 0755). Повторите команду. |
| `cannot stop the service` на Windows | Идёт выполнение задания. | Дождитесь задания или остановите службу вручную. Повторите команду. |
| `the restic binary ... is missing` на Windows после обновления | Прежний агент держал restic в каталоге `bin`, и служба не смогла его перенести. В журнале службы есть `cannot remove` или `cannot replace`. | Закройте программу, которая держит старый файл, или снимите с него атрибут «только чтение». Затем выполните `restichub-agent install-service` от имени администратора. Команда переносит restic в `%ProgramFiles%\ResticHub\Agent\restic.exe`. |
| `restic differs from its record after the move` | Старый файл изменился до переноса. | Выполните `restichub-agent restic update` от имени администратора. |

## Ограничения юнита systemd

Юнит оставляет службе пять привилегий (capabilities): `CAP_DAC_READ_SEARCH`, `CAP_DAC_OVERRIDE`, `CAP_CHOWN`, `CAP_FOWNER` и `CAP_FSETID`. Restic работает от имени `root`, поэтому только эти пять привилегий остаются в ограниченном наборе. Без них restic не может прочитать файл другой учётной записи и не может сохранить владельца и права восстановленного файла.

`ProtectSystem=strict` делает всю файловую систему доступной только для чтения. Исключения — каталог учётных данных (через `ReadWritePaths`) и каталог кэша. Читать источник резервного копирования по-прежнему можно. Restic пишет в локальный репозиторий, поэтому добавьте каждый путь локального репозитория в `ReadWritePaths`. Там же юнит перечисляет корневые каталоги восстановления (`/var/lib/restichub-restore` и каждый корень из `/etc/restichub-agent-restore-roots.txt`). Команда `install-service` создаёт корневой каталог по умолчанию. Выполните её снова после добавления корневого каталога: systemd читает список при запуске юнита. `ProtectHome` остаётся выключенным, потому что источник резервного копирования часто лежит ниже `/home`.

Юнит задаёт `CacheDirectory=restichub-agent` и `RESTIC_CACHE_DIR=/var/cache/restichub-agent`. Так кэш restic остаётся в каталоге, в который юнит может писать.

## Исполняемый файл restic

Пакет агента не содержит restic. Агент скачивает restic сам. Команды `register` и `install-service` скачивают его, если на хосте его нет. Команда `run` ничего не скачивает: работающая служба не обращается в сеть за restic.

Агент берёт последний выпуск restic с GitHub. Он проверяет подпись OpenPGP файла `SHA256SUMS` ключом подписи выпусков проекта restic, который входит в состав агента. Затем он проверяет сумму архива. Агент устанавливает только restic 0.18.1 и новее и отклоняет выпуск с основной версией выше 0. Если проверка не прошла, ничего не устанавливается.

Агент хранит исполняемый файл в защищённом каталоге:

- Linux: `/opt/restichub-agent/bin/restic`.
- Windows: `%ProgramFiles%\ResticHub\Agent\restic.exe`, рядом с исполняемым файлом агента. Писать туда могут только SYSTEM и группа «Администраторы».

Защищённый каталог конфигурации хранит файл `restic.json` с версией и суммой SHA-256 установленного файла. При каждом запуске и перед каждым процессом restic агент сверяет файл с этой записью и не принимает другой файл. Сервер управления не может задать путь к restic. Если restic нет или он не совпадает с записью, служба останавливается и сообщает, что делать дальше: выполните `restichub-agent restic update`.

### Обновление restic

Выполните команду от имени `root` или в PowerShell с повышенными правами:

```sh
restichub-agent restic update
```

Команда скачивает последний выпуск и проверяет его. Она запускает новый файл с командой `version` и только после этого заменяет старый файл одним переименованием. Старый файл остаётся в том же каталоге под именем `restic-previous`. Если какой-то шаг не удался, старый файл и старая запись не меняются. Служба читает запись перед каждым процессом restic, поэтому следующее задание использует новый файл. Если служба установлена, команда перезапускает её. Параметр `--no-restart` отключает перезапуск: сделайте его сами. В Windows замена не удаётся, пока служба использует файл. В этом случае остановите службу, выполните команду ещё раз и запустите службу.

Команда не ставит выпуск старее установленного. Параметр `--allow-downgrade` разрешает такую установку.

Последний выпуск может не пройти проверки, например из-за новой основной версии, изменённого формата подписи или ограничения частоты запросов GitHub. Тогда команда берёт новейший поддерживаемый выпуск из последних десяти выпусков GitHub. Если и он не подходит, команда использует выпуск, закреплённый в этой сборке агента. Если установить не удалось ни один выпуск, в сообщении перечислены все причины. В этом случае используйте файлы для автономной установки.

### Автономный хост

Хост без доступа к GitHub использует файлы, которые вы перенесли с другого компьютера. Скачайте со страницы нужного выпуска restic три файла:

- `restic_<version>_linux_amd64.bz2` (Linux) или `restic_<version>_windows_amd64.zip` (Windows). Для хоста ARM используйте `arm64`.
- `SHA256SUMS`
- `SHA256SUMS.asc`

Не переименовывайте архив, потому что его имя задаёт версию. Затем выполните любую из команд `register`, `install-service` или `restic update` с параметрами:

```sh
restichub-agent restic update \
  --restic-archive ./restic_0.19.1_linux_amd64.bz2 \
  --restic-sums ./SHA256SUMS \
  --restic-sums-sig ./SHA256SUMS.asc
```

Агент проверяет эти файлы так же, как скачанные.

### Прокси для скачивания

При скачивании учитываются переменные `HTTPS_PROXY` и `NO_PROXY` процесса, который выполняет команду. Адрес прокси должен начинаться с `http://`, например `http://proxy.example:3128`. Агент открывает через него туннель `CONNECT`, поэтому сеанс TLS и все проверки выполняются напрямую между агентом и GitHub. Прокси с именем пользователя и паролем задайте как `http://user:password@proxy.example:3128`. Специальный символ в имени или пароле записывайте в процентной кодировке, например `%40` вместо `@`. Адрес IPv6 пишите в квадратных скобках, например `http://[2001:db8::1]:3128`.

`sudo` сбрасывает эти переменные. Чтобы сохранить их, выполните: `sudo --preserve-env=HTTPS_PROXY,NO_PROXY restichub-agent restic update`.

GitHub ограничивает число запросов без токена. Если GitHub отвечает, что лимит запросов исчерпан, агент сообщает об этом. Повторите позже или используйте файлы для автономной установки.

## Настройки прокси

Если репозиторий доступен только через прокси, restic использует прокси хоста. Агент передаёт дочернему процессу restic переменные `HTTPS_PROXY`, `HTTP_PROXY` и `NO_PROXY` из собственного окружения, а на Linux и macOS — и их варианты строчными буквами. Задайте эти переменные в окружении службы агента, а не в задании.

Дочерний процесс restic не получает других переменных агента, поэтому задание не может перенаправить трафик репозитория.
