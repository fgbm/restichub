Для оповещений нужны четыре настройки установки (ADR-0036). Они относятся к установке, а не к организации. Задайте их в файле конфигурации или в переменных окружения. Переменная окружения переопределяет файл.

## Публичный адрес

Публичный адрес — это базовый URL ссылок в сообщении.

| Ключ в файле | Переменная окружения | Значение |
|---|---|---|
| `public_origin` | `RESTICHUB_PUBLIC_ORIGIN` | Схема, хост и порт веб-интерфейса, например `https://backup.example.com`. |

В значении нет пользователя, пути и параметров. Без него в сообщении нет ссылки.

## Язык сообщений

Письма и сообщения вебхуков используют один язык на всю установку. Веб-интерфейс показывает каждое оповещение на языке читателя.

| Ключ в файле | Переменная окружения | Значение |
|---|---|---|
| `notifications.language` | `RESTICHUB_NOTIFICATIONS_LANGUAGE` | `en` (по умолчанию) или `ru`. |

Сообщение вебхука также содержит типизированные значения в `params` и очищенный текст ошибки задачи в `error_text`, чтобы получатель мог собрать свой текст.

## Сервер SMTP

Канал почты отправляет сообщения через один сервер SMTP. Без сервера каналы почты не отправляют сообщения.

| Ключ в файле | Переменная окружения | Значение |
|---|---|---|
| `smtp.host` | `RESTICHUB_SMTP_HOST` | Имя хоста сервера. Если задать его, почта включается. |
| `smtp.port` | `RESTICHUB_SMTP_PORT` | Порт. По умолчанию 587 для `starttls`, 465 для `tls` и 25 для `none`. |
| `smtp.security` | `RESTICHUB_SMTP_SECURITY` | `starttls` (по умолчанию), `tls` или `none`. |
| `smtp.username` | `RESTICHUB_SMTP_USERNAME` | Имя пользователя. Без него сервер управления не входит на сервер SMTP. |
| `smtp.password_file` | `RESTICHUB_SMTP_PASSWORD_FILE` | Путь к файлу с паролем. |
| — | `RESTICHUB_SMTP_PASSWORD` | Пароль. Используйте его вместо файла. Не задавайте оба варианта. |
| `smtp.from` | `RESTICHUB_SMTP_FROM` | Адрес отправителя. Он обязателен, если задан хост. |

Правила для пароля:

- Пароль никогда не попадает в базу данных и в журнал аудита.
- В рабочей установке используйте файл. Это должен быть обычный файл, который читает только его владелец.
- Сервер управления входит командой `AUTH PLAIN` и только по TLS. При `none` и заданном пароле сервер управления не запускается.
- Если сервер отклоняет часть получателей и принимает остальных, сервер управления отправляет сообщение. В записи доставки остаётся пометка с числом отклонённых получателей.
- Сервер управления проверяет сертификат сервера по системным корневым сертификатам и по встроенным публичным.

Пример:

```toml
public_origin = "https://backup.example.com"

[smtp]
host = "smtp.example.com"
security = "starttls"
username = "restichub"
password_file = "/run/secrets/smtp-password"
from = "restichub@example.com"
```

## Список разрешённых сетей вебхуков

По умолчанию вебхук использует `https` и публичный адрес. Администратор может ослабить два правила.

| Ключ в файле | Переменная окружения | Значение |
|---|---|---|
| `webhook.allow_http` | `RESTICHUB_WEBHOOK_ALLOW_HTTP` | Разрешает схему `http`. По умолчанию `false`. |
| `webhook.allow_networks` | `RESTICHUB_WEBHOOK_ALLOW_NETWORKS` | Сети в форме CIDR, которые проверка адреса пропускает. В переменной разделяйте записи запятыми. |

Проверка адреса всегда отклоняет петлевые, частные, локальные, общие, зарезервированные и многоадресные диапазоны. Она также отклоняет диапазоны `2001::/23` (в нём Teredo), `64:ff9b:1::/48` и `192.88.99.0/24`. Кнопка проверки канала ограничена: 6 проверок в минуту на пользователя и 20 в минуту на организацию.

Сеть в списке действует для всех организаций установки. Добавляйте самую маленькую сеть, в которой находится получатель.

```toml
[webhook]
allow_networks = ["10.20.30.0/24"]
```

> **Предупреждение:** Список разрешённых сетей позволяет Администратору любой организации заставить сервер управления отправлять запросы в эту сеть. Добавляйте сеть, только если вы доверяете всем Администраторам установки.
