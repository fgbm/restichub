---
title: Восстановление
description: Как посмотреть снимки репозитория, открыть снимок и восстановить файлы на тот же агент или на другой агент.
---

Экран «Восстановление» показывает снимки репозитория, файлы снимка и восстанавливает их. Экран доступен оператору и администратору. Наблюдатель не может им пользоваться.

Данные восстановления идут из репозитория на целевой агент. Они не проходят через сервер управления (ADR-0003). Целевой агент получает секреты этого репозитория только на время задания восстановления. Каждая выдача пишет запись аудита `secret_delivered`. Запуск восстановления пишет запись аудита `restore_start`. В записи указаны репозиторий, снимок, целевой агент и целевой путь.

## Требования

- Репозиторий должен быть инициализирован.
- Выбранный агент должен быть в сети.
- Агент должен объявить возможность `restore-v1`. Она есть в пакетах агента, которые включают экран восстановления. Агент без неё может показать список снимков. Для дерева файлов и для восстановления сервер управления отклоняет задание с причиной `agent_capability_missing`. Обновите пакет агента.
- Репозиторий с локальным путём принимает только свой агент обслуживания. Данные остаются на этом хосте.

## Список снимков

1. Откройте **Восстановление**.
2. Выберите репозиторий. Экран показывает последний сохранённый список и его возраст.
3. Введите хост, тег или путь. При необходимости задайте диапазон дат.
4. Нажмите **Обновить**. Агент запускает `restic snapshots` с этими фильтрами, и список обновляется.

Диапазон дат применяет сервер управления. Хост, тег и путь применяет restic. Список совпадает с выводом `restic snapshots --json` для тех же фильтров. Если в репозитории больше снимков, чем помещается в один результат, экран показывает предупреждение и оставляет самые новые снимки.

## Дерево снимка

Выберите снимок, чтобы открыть его дерево файлов. Экран показывает один каталог за раз. Агент читает каталог и возвращает страницу не больше чем из 1000 записей. Нажмите **Загрузить ещё**, чтобы прочитать следующую страницу. Первая страница каталога с миллионом файлов появляется меньше чем за 5 секунд.

Сервер управления хранит страницу 10 минут. Если вы снова откроете тот же каталог за это время, экран покажет сохранённую страницу, и задание не запустится. В списке заданий этих заданий нет.

## Восстановление файлов

1. Отметьте нужные файлы и каталоги в дереве. Если вы ничего не отметите, восстановится весь снимок.
2. Нажмите **Восстановить**.
3. Выберите целевой агент. По умолчанию это агент обслуживания репозитория.
4. Введите целевой путь. Путь должен быть абсолютным, например `/srv/restore` или `D:\restore`.
5. Выберите, что делать с файлом, который уже есть в целевом каталоге.
6. Нажмите **Восстановить**. Экран откроет задание.

Подробности задания показывают ход выполнения. После завершения они показывают, сколько файлов и байтов агент восстановил и сколько пропустил.

| Параметр | Значение |
|---|---|
| Перезапись: `always` | Заменять каждый существующий файл. |
| Перезапись: `if-changed` | Заменять файл, содержимое которого отличается. |
| Перезапись: `if-newer` | Заменять файл, который старше копии в снимке. |
| Перезапись: `never` | Оставлять каждый существующий файл. |
| Пробный запуск | Проверить восстановление. Агент не пишет и не меняет файлы. |
| Проверка | После восстановления агент снова читает файлы и сравнивает их со снимком. |

restic не принимает в одном восстановлении список включений и список исключений. Экран восстанавливает отмеченные файлы, а API отклоняет запрос с обоими списками.

Восстановление в системный путь, например `/etc`, `/usr`, `C:\Windows` или `C:\Program Files`, может нарушить работу целевого хоста. Экран показывает предупреждение. Сервер управления не блокирует такое восстановление.

## API

| Метод и путь | Роль | Назначение |
|---|---|---|
| `POST /api/v1/repositories/{id}/snapshots` | Оператор | Запускает задание со списком снимков. |
| `GET /api/v1/repositories/{id}/snapshots` | Наблюдатель | Читает список задания (`job`) или последний сохранённый список. Параметры `from` и `to` фильтруют по дате. |
| `POST /api/v1/repositories/{id}/ls` | Оператор | Запускает задание со списком одного каталога снимка. Сохранённая страница возвращается с кодом HTTP 200. |
| `GET /api/v1/repositories/{id}/ls` | Оператор | Читает страницу задания (`job`). |
| `POST /api/v1/repositories/{id}/restore` | Оператор | Запускает восстановление и возвращает задание. |

Агент не в сети даёт HTTP 409 `agent_offline`. Слишком старый агент даёт HTTP 409 `agent_capability_missing`. Репозиторий другой организации даёт HTTP 404.
