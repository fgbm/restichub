title: Восстановление
description: Как посмотреть снимки репозитория, открыть снимок и восстановить файлы на тот же агент или на другой агент.
---

Экран «Восстановление» показывает снимки репозитория, файлы снимка и восстанавливает их. Экран доступен оператору и администратору. Наблюдатель не может им пользоваться.

Данные восстановления идут из репозитория на целевой агент. Они не проходят через сервер управления (ADR-0003). Целевой агент получает секреты этого репозитория только на время задания восстановления. Каждая выдача пишет запись аудита `secret_delivered`. Запуск восстановления пишет запись аудита `restore_start`. В записи указаны репозиторий, снимок, целевой агент и целевой путь. Список снимков или страница дерева, которые запускают задание, пишут запись аудита `browse_start`. В ней указаны репозиторий и агент, который читает репозиторий, потому что этот агент получает секреты репозитория.

## Требования

- Репозиторий должен быть инициализирован.
- Выбранный агент должен быть в сети.
- Агент должен объявить возможность `restore-v1`. Она есть в пакетах агента, которые включают экран восстановления. Агент без неё может показать список снимков. Для дерева файлов и для восстановления сервер управления отклоняет задание с причиной `agent_capability_missing`. Обновите пакет агента.
- Репозиторий с локальным путём принимает только свой агент обслуживания. Данные остаются на этом хосте.
- Целевой путь должен лежать внутри корня восстановления агента (см. [Корни восстановления](#корни-восстановления)).

## Список снимков

1. Откройте **Восстановление**.
2. Выберите репозиторий. Экран показывает последний сохранённый список и его возраст.
3. Введите хост, тег или путь. При необходимости задайте диапазон дат.
4. Нажмите **Обновить**. Агент запускает `restic snapshots` с этими фильтрами, и список обновляется.

Диапазон дат применяет сервер управления. Хост, тег и путь применяет restic. Список совпадает с выводом `restic snapshots --json` для тех же фильтров. Если в репозитории больше снимков, чем помещается в один результат, экран показывает предупреждение и оставляет самые новые снимки.

## Дерево снимка

Выберите снимок, чтобы открыть его дерево файлов. Экран показывает один каталог за раз. Агент читает каталог и возвращает страницу не больше чем из 1000 записей. Нажмите **Загрузить ещё**, чтобы прочитать следующую страницу. Первая страница каталога с миллионом файлов появляется меньше чем за 5 секунд.

Сервер управления хранит страницу 10 минут. Если вы снова откроете тот же каталог за это время, экран покажет сохранённую страницу, и задание не запустится. Если такой же запрос уже ждёт или выполняется, он получает то же задание. Сервер управления хранит список снимков один час. В списке заданий этих заданий нет.

Один человек может отправить 60 запросов списка и страниц в минуту. Один агент держит не больше 8 ожидающих заданий просмотра. Следующий запрос даёт HTTP 429 `rate_limited`. Агент выполняет не больше двух заданий просмотра одновременно, и они никогда не задерживают резервное копирование.

## Восстановление файлов

1. Отметьте нужные файлы и каталоги в дереве. Если вы ничего не отметите, восстановится весь снимок.
2. Нажмите **Восстановить**.
3. Выберите целевой агент. По умолчанию это агент обслуживания репозитория.
4. Проверьте целевой путь. Экран предлагает новый каталог в первом корне восстановления агента, например `/var/lib/restichub-restore/a1b2c3d4`. Путь должен быть абсолютным и лежать внутри корня восстановления.
5. Выберите, что делать с файлом, который уже есть в целевом каталоге.
6. Нажмите **Восстановить**. Экран откроет задание.

Подробности задания показывают ход выполнения. После завершения они показывают, сколько файлов и байтов агент восстановил и сколько пропустил.

| Параметр | Значение |
|---|---|
| Перезапись: `always` | Заменять каждый существующий файл. |
| Перезапись: `if-changed` | Заменять файл, содержимое которого отличается. |
| Перезапись: `if-newer` | Заменять файл, который старше копии в снимке. |
| Перезапись: `never` | Оставлять каждый существующий файл. |
| Пробный запуск | Проверить восстановление. Агент не пишет и не меняет файлы. |
| Проверка | После восстановления агент снова читает файлы и сравнивает их со снимком. Её нельзя включить вместе с пробным запуском, потому что пробный запуск не пишет файлы. |

restic не принимает в одном восстановлении список включений и список исключений. Экран восстанавливает отмеченные файлы, а API отклоняет запрос с обоими списками.

Экран экранирует символы `*`, `?` и `[` в отмеченном пути, поэтому путь совпадает только с самим собой. Снимок выбирается по идентификатору. Экран и API не принимают `latest`, потому что это значение может измениться между двумя чтениями.

## Корни восстановления

Агент работает от имени root на Linux и от имени LocalSystem на Windows. Он восстанавливает файлы только ниже *корня восстановления*. Корни задают только root или администраторы на хосте. Сервер управления и задания не могут их менять.

| Система | Корень по умолчанию |
|---|---|
| Linux | `/var/lib/restichub-restore` |
| Windows | `C:\ProgramData\ResticHub\Restore` |

Команда `install-service` создаёт корень по умолчанию с доступом только для учётной записи службы. Агент сообщает свои корни серверу управления. Экран предлагает первый корень, а сервер управления отклоняет путь вне корней с кодом HTTP 409 `restore_target_denied`. Агент проверяет путь ещё раз, и его проверка окончательная. Он отклоняет задание с причиной `restore_target_denied`.

Чтобы добавить корень, запишите по одному абсолютному пути в строке файла `/etc/restichub-agent-restore-roots.txt` (Windows: `C:\ProgramData\ResticHub\Agent-restore-roots.txt`). Строка, которая начинается с `#`, — комментарий. Владельцем и автором файла может быть только root или администратор. Агент игнорирует файл, который может изменить другая учётная запись. Создайте каталог каждого корня и снова выполните `restichub-agent install-service`. Команда добавляет корни в `ReadWritePaths` юнита systemd. Без этого шага systemd оставляет корень доступным только для чтения, и восстановление не работает.

Корень `/` разрешает восстановление на месте, например в `/srv/data`. Задавайте его только осознанно. Для системного пути, например `/etc`, экран показывает предупреждение.

Агент всегда отклоняет путь, который совпадает с его собственными файлами, содержит их или лежит внутри них. Это каталог учётных данных, каталог кэша, каталог бинарных файлов агента и restic и список разрешённых хуков. Сначала агент раскрывает символьные ссылки. Корень `/` не меняет это правило.

## API

| Метод и путь | Роль | Назначение |
|---|---|---|
| `POST /api/v1/repositories/{id}/snapshots` | Оператор | Запускает задание со списком снимков. |
| `GET /api/v1/repositories/{id}/snapshots` | Наблюдатель | Читает список задания (`job`) или последний сохранённый список. Параметры `from` и `to` фильтруют по дате. |
| `POST /api/v1/repositories/{id}/ls` | Оператор | Запускает задание со списком одного каталога снимка. Сохранённая страница возвращается с кодом HTTP 200. |
| `GET /api/v1/repositories/{id}/ls` | Оператор | Читает страницу задания (`job`). |
| `POST /api/v1/repositories/{id}/restore` | Оператор | Запускает восстановление и возвращает задание. |

Восстановление и страница дерева требуют идентификатор снимка из 8–64 строчных шестнадцатеричных символов. Восстановление с `dry_run` и `verify` вместе даёт HTTP 400. Агент не в сети даёт HTTP 409 `agent_offline`. Слишком старый агент даёт HTTP 409 `agent_capability_missing`. Путь вне корней агента даёт HTTP 409 `restore_target_denied`. Репозиторий другой организации даёт HTTP 404.

`GET /api/v1/agents` показывает `restore_roots` каждого агента.
