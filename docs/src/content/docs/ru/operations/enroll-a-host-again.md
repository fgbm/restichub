---
title: Повторная регистрация хоста и дубли хостов
description: Как сохранить планы хоста при повторной регистрации агента и как объединить две записи одного компьютера.
---

Один компьютер может зарегистрироваться дважды, например когда на нём заново установили агент и использовали новый токен регистрации. Тогда на экране «Хосты» две записи одного компьютера. Эта страница описывает, как не получить вторую запись и как объединить две записи.

## Хосты, которые ожидают подключения

Агент зарегистрировался, но ещё не открыл поток: хост имеет статус «Ожидает подключения». Такой хост не в сети и не вне сети. Панель показателей считает его отдельно. Статус меняется, когда агент подключается в первый раз.

## Зарегистрировать хост заново

Используйте эту процедуру, когда агент потерял идентичность или когда агент нужно перенести в новую установку. Хост сохраняет идентификатор, планы, ссылки на хост обслуживания и метки.

1. Откройте экран «Хосты» от имени администратора.
2. Откройте меню хоста и выберите «Зарегистрировать заново».
3. Выберите «Создать токен». Экран показывает токен один раз.
4. Выполните показанную команду на компьютере хоста: `restichub-agent register --force --url <url> --token <token>`.

Токен привязан к хосту. Команда сообщает, что заменила хост. Сервер управления сразу перестаёт принимать старый сертификат и закрывает открытый поток старого агента. В журнале аудита появляется действие `agent_reenroll`.

Токен, привязанный к хосту, виден в списке «Ожидающие регистрации» вместе с именем хоста. Токен забирает идентичность хоста, поэтому он действует не дольше одного часа. Чтобы изменить предел, задайте `RESTICHUB_REENROLL_TOKEN_MAX_TTL_SECS`. Новый токен для того же хоста отменяет прежние неиспользованные токены этого хоста, а успешная регистрация отменяет остальные. Отозванный хост не может зарегистрироваться заново, а журнал аудита фиксирует попытку.

Пока новый агент не подключился, хост имеет статус «Ожидает подключения» и не вызывает оповещение «Хост недоступен».

## Возможные дубли

При регистрации агент отправляет дайджест стабильного идентификатора компьютера: `MachineGuid` в Windows и файла `/etc/machine-id` в Linux. Сам идентификатор остаётся на компьютере. Сервер управления хранит только ключевой хеш дайджеста. Ключ строится из KEK и организации, поэтому организация не узнаёт, что компьютер зарегистрирован в другой организации, а дамп базы данных не подтверждает регистрацию компьютера. У виртуальных машин, клонированных из одного образа, идентификатор может совпасть. Предупреждение — только подсказка, решение принимаете вы.

Если токен без привязки к хосту регистрирует компьютер с уже известным идентификатором, обе записи показывают «Возможный дубль хоста «имя»».

Чтобы объединить записи:

1. Откройте меню более новой записи. Замену предлагает только новая запись.
2. Выберите «Заменить старую запись». Диалог показывает время последнего контакта обеих записей.
3. Подтвердите действие.

Сервер управления переносит планы, ссылки на хост обслуживания, задания в очереди и метки старой записи на новую запись. Затем он отзывает старую запись и отменяет её выполняющиеся задания, как при отзыве. В журнале аудита появляются действия `agent_replace` и `agent_revoke`. Обе записи должны быть активными.

Если старая запись выходила на связь за последние 5 минут, сервер управления отклоняет замену с HTTP 409 `agent_recently_online`. Чтобы изменить окно, задайте `RESTICHUB_REPLACE_ONLINE_WINDOW_SECS`.

## Ожидающие регистрации

Список «Ожидающие регистрации» обновляется каждые 10 секунд. Токен, который использовал хост, исчезает из списка. Диалог «Добавить хост» показывает «Хост зарегистрирован: имя», когда хост использует токен, созданный в этом диалоге.

Токен нельзя отменить в таких случаях. Сервер управления отвечает HTTP 409 с типизированным кодом:

| Код | Значение |
|---|---|
| `token_used` | Хост уже использовал токен. |
| `token_already_revoked` | Администратор уже отменил токен. |
| `token_expired` | Срок действия токена истёк. |
