---
title: Переход с resticprofile
description: Как перенести резервное копирование из конфигурации resticprofile в профили, планы и репозитории ResticHub.
---

resticprofile хранит настройки restic в файле конфигурации на каждом хосте. ResticHub хранит их на сервере управления. Эта страница сопоставляет настройки resticprofile с настройками ResticHub. Функции импорта в ResticHub нет. Объекты создаются в веб-интерфейсе.

## Что остаётся прежним

- Репозиторий restic остаётся без изменений. ResticHub запускает restic на хосте, поэтому снимки читаются как раньше.
- Пароль репозитория остаётся прежним. Введите его в ResticHub при добавлении репозитория.
- Не запускайте `restic init` повторно.

## Сопоставление настроек

| resticprofile | ResticHub |
|---|---|
| `repository`, `password-file`, переменные хранилища | [Репозиторий](/restichub/ru/concepts/repositories/). Сервер управления шифрует пароль и учётные данные. Репозиторий выбирает план, а не профиль. |
| Раздел профиля | [Профиль](/restichub/ru/concepts/profiles/). |
| `backup.source` | «Что копировать» |
| `backup.exclude`, `exclude-file` | «Исключения» |
| `backup.tag` | «Теги» |
| `backup.one-file-system`, `exclude-caches`, `limit-upload`, `limit-download`, `use-fs-snapshot` | «Параметры копирования» |
| `retention` | «Хранение». Наборы правил и сами правила заменяют ключи `keep-*`. |
| `check` | «Проверка репозитория» |
| `run-before`, `run-after` | «Скрипты на хосте». См. [Скрипты сервера](/restichub/ru/guides/scripts/). |
| `schedule`, таймер systemd или запись cron | [План](/restichub/ru/concepts/plans/) с выражением cron и часовым поясом. |
| `groups` | Один план на каждый профиль. |
| `inherit` | Создайте второй профиль вручную. Наследования профилей в ResticHub нет. |

## Порядок действий

1. Установите сервер управления. См. [Установка сервера управления](/restichub/ru/getting-started/install-control-plane/).
2. Зарегистрируйте каждый хост. См. [Регистрация агента](/restichub/ru/getting-started/add-a-host/).
3. Добавьте репозиторий. Введите тот же адрес хранилища и тот же пароль, что в resticprofile.
4. Добавьте профиль для каждого профиля resticprofile. Перенесите пути, исключения и теги.
5. Задайте хранение. Выберите набор правил, ближайший к вашим значениям `keep-*`, и измените числа.
6. Добавьте план для каждого профиля. Выберите репозиторий и преобразуйте расписание в выражение cron.
7. Нажмите «Запустить сейчас» у плана. Прочитайте журнал задания.
8. Убедитесь, что в репозитории появился новый снимок.
9. Отключите расписание resticprofile на хосте. Удалите таймер systemd или запись cron.

Не оставляйте старое расписание и новый план одновременно. Иначе одни данные копируются дважды.

## Отличия, которые нужно знать

- Расписание хранит сервер управления. Хост, который не в сети, пропускает запуски. Параметр плана «Пропущенные запуски» решает, что произойдёт при следующем подключении.
- Сервер управления выполняет `forget` и `prune` только на хосте обслуживания репозитория. Выберите этот хост в настройках репозитория.
- В профиле нет произвольных флагов restic. Редактор профиля предлагает только типизированные параметры. Если нужного флага нет, напишите об этом в задачах проекта.
- Хуков в ResticHub нет. Используйте скрипт сервера. Скрипт выполняется только на хосте, где администратор включил режим доверия.
- Агент сам скачивает restic. Управлять бинарным файлом restic не нужно.
