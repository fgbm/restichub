---
title: Добавление репозитория

---

Репозиторий — место, где restic хранит снимки. Сервер управления хранит расположение репозитория и его секреты. Хосты подключаются к репозиторию напрямую, поэтому данные резервных копий не проходят через сервер управления.

## Перед началом

- Зарегистрируйте хотя бы один хост и убедитесь, что его состояние — «В сети». См. [Регистрация агента](/restichub/ru/getting-started/add-a-host/). Этот хост станет хостом обслуживания.
- Подготовьте хранилище, доступное хосту по сети:
  - S3-совместимое хранилище: бакет, ключ доступа и секретный ключ с правами на чтение, запись, просмотр списка и удаление объектов в бакете.
  - [rest-server](https://github.com/restic/rest-server). Дайте каждому репозиторию свой путь, например `https://rest.example.com:8000/fs-01`. Если rest-server использует файл `.htpasswd`, подготовьте имя пользователя и пароль одной учётной записи из этого файла.
  - Локальный путь: каталог на диске одного хоста, например `/mnt/backup/restic`. В Linux сначала разрешите путь на хосте. См. [Локальный репозиторий](#локальный-репозиторий) и [Локальный репозиторий в Linux](#локальный-репозиторий-в-linux).
- Войдите как Admin. Репозиторий создаёт только Admin.

## Поля хранилища

| Тип хранилища | Поле | Значение |
|---|---|---|
| S3-совместимое | «Адрес» | Адрес хранилища со схемой, например `https://s3.example.com` |
| S3-совместимое | «Бакет» | Имя бакета, например `backups` |
| S3-совместимое | «Префикс» | Необязательно. Путь внутри бакета, например `restic/fs-01` |
| S3-совместимое | «Регион» | Необязательно. Регион бакета, например `us-east-1` |
| S3-совместимое | «Ключ доступа S3», «Секретный ключ S3» | Учётные данные бакета |
| REST-сервер | «Адрес» | Адрес репозитория на rest-server, например `https://rest.example.com:8000/fs-01` |
| REST-сервер | «Имя пользователя» | Необязательно. Имя учётной записи из файла `.htpasswd` rest-server |
| REST-сервер | «Пароль REST-сервера» | Необязательно. Пароль той же учётной записи |
| Локальный путь | «Путь» | Абсолютный путь на диске хоста репозитория, например `/var/spool/restichub/fs-01` |

Одно расположение занимает один репозиторий. Сервер управления отклоняет репозиторий с расположением другого репозитория вашей организации, с кодом `repository_location_taken`. Страница называет репозиторий, который занимает расположение. Локальное расположение — это хост и путь, расположение S3 — адрес, бакет и префикс, расположение REST-сервера — URL.

«Адрес» использует схему `https` или `http`. В нём не может быть имени пользователя, пароля, строки запроса или фрагмента. Учётные данные rest-server введите в поля «Имя пользователя» и «Пароль REST-сервера» в разделе «Доступ».

Имя пользователя не секрет: страница репозитория показывает его, и его можно изменить в любой момент. Пароль — секрет. Агент передаёт оба значения restic в переменных окружения `RESTIC_REST_USERNAME` и `RESTIC_REST_PASSWORD`, а не в командной строке. Для rest-server с `--no-auth` учётные данные не нужны.

## Создание репозитория

:::danger[Опасно]
Сохраните копию пароля репозитория вне ResticHub. Если сервер управления потерян, restic не откроет снимки без пароля. После сохранения репозитория пароль изменить нельзя.
:::

1. Откройте «Репозитории».
2. Нажмите «Добавить репозиторий». Откроется страница «Новый репозиторий».
3. В разделе «Основное» введите имя в поле «Репозиторий».
4. В разделе «Расположение» выберите «Тип хранилища»: «S3-совместимое», «REST-сервер» или «Локальный путь».
5. Заполните поля хранилища по таблице выше.
6. В разделе «Доступ» введите «Пароль репозитория».
7. Введите учётные данные хранилища.
8. В разделе «Хост обслуживания» выберите хост. Для локального репозитория раздел называется «Хост репозитория», и хост обязателен.
9. Нажмите «Сохранить».

Репозиторий появится в списке с состоянием «Не инициализирован». Сервер управления больше не показывает значения секретов. Ключи S3 и пароль REST-сервера можно только заменить.

Разделы «Обслуживание» и «Проверка» содержат расписания заданий обслуживания. Для первого репозитория оставьте значения по умолчанию. См. [Репозитории](/restichub/ru/concepts/repositories/#обслуживание).

## Локальный репозиторий в Linux

Служба агента в Linux работает в песочнице systemd. Песочница делает файловую систему доступной службе только для чтения. Поэтому restic не может записать локальный репозиторий по любому пути. Администратор хоста разрешает места для локальных репозиториев в файле. Сервер управления и задания не могут изменить этот файл.

Выполните эти шаги на хосте обслуживания до инициализации репозитория:

1. Запишите родительский каталог репозитория отдельной строкой в файл `/etc/restichub-agent-repository-roots.txt`, например `/srv/restichub` или `/var/spool/restichub`. Каждая строка содержит один абсолютный путь. Строка, которая начинается с `#`, — комментарий. В Linux агент игнорирует строку с кавычкой, обратной косой чертой, `%`, пробелом или управляющим символом. Агент записывает в журнал предупреждение о такой строке и о строке без абсолютного пути. Команда `install-service` отклоняет такую строку и называет её номер.
2. Убедитесь, что владелец файла — root и что другие учётные записи не могут его изменять: `sudo chown root:root /etc/restichub-agent-repository-roots.txt` и `sudo chmod 0644 /etc/restichub-agent-repository-roots.txt`.
3. Выполните `sudo restichub-agent install-service`. Команда добавит каждый корень в `ReadWritePaths` юнита systemd и перезапустит службу. Отсутствующий корень команда создаст с доступом только для root, а отсутствующие родительские каталоги — с правами `0755`.

После каждого изменения файла снова выполните `install-service`. При каждом запуске агент записывает в журнал предупреждение о корне, который установленный юнит не может изменять.

Корень и все его существующие родительские каталоги должны принадлежать root. Ни у одной группы или другой учётной записи не должно быть права записи. Агент игнорирует файл или корень, который нарушает это правило, и записывает предупреждение в журнал. Команда `install-service` такой корень отклоняет. Иначе другая учётная запись могла бы заменить каталог ссылкой.

Агент отклоняет локальный репозиторий вне корней до запуска restic. Задание завершается ошибкой с причиной `repository_path_denied`, и экран называет файл. Агент также отклоняет путь, который содержит файлы агента или лежит внутри них.

Корнем не может быть `/`, системный каталог (`/etc`, `/usr`, `/bin`, `/sbin`, `/lib`, `/lib64`, `/boot`, `/proc`, `/sys`, `/dev`, `/run`, `/var/spool/cron`, `/var/lib/systemd`), каталог, который содержит один из них, сам каталог `/home` или `/root`, каталог `/var/lib/restichub*` или каталог агента. Каждый корень становится доступным restic для записи, поэтому такой корень открыл бы системные файлы или файлы всех учётных записей. Корнем должен быть отдельный каталог только для репозиториев. Агент игнорирует такой корень и записывает в журнал предупреждение с этой строкой. Команда `install-service` останавливается с сообщением.

Юнит задаёт `ProtectHome=read-only`. Служба читает источник резервного копирования ниже `/home`, но пишет ниже `/home`, `/root` и `/run/user` только в корень. Каталог учётной записи пользователя, например `/home/<user>`, не может содержать корень: его владелец — не root. Используйте каталог, владелец которого — root, например `/srv/restichub`.

Не размещайте локальный репозиторий внутри каталога другого локального репозитория. Агент такой путь не отклоняет, но restic найдёт файлы второго репозитория среди файлов первого.

Корни репозиториев — не каталоги восстановления. Восстановление никогда не пишет в корень репозиториев, даже при каталоге восстановления `/`. Команда `install-service` отклоняет каталог восстановления и корень репозиториев, если один из них содержит другой. См. [Каталоги восстановления](/restichub/ru/guides/restore/#каталоги-восстановления).

В Windows у службы нет такой песочницы. Локальный репозиторий может лежать по любому пути, в который может писать учётная запись службы. Файл корней репозиториев агент в Windows не читает.

## Инициализация репозитория

Новый репозиторий в пустом расположении нужно инициализировать. Если в расположении уже есть репозиторий restic с тем же паролем, проверьте доступ.

1. В списке «Репозитории» откройте меню «…» в строке репозитория.
2. Выберите «Инициализировать». Для существующего репозитория restic выберите «Проверить доступ».
3. Убедитесь, что в поле «Хост» указан хост обслуживания. Сервер управления выполняет инициализацию только на хосте обслуживания.
4. Нажмите «Запустить».
5. Дождитесь, когда диалог покажет состояние «Успешно» и результат «Репозиторий готов.».

Состояние репозитория изменится на «Готов».

| Результат | Значение | Действие |
|---|---|---|
| «Репозиторий готов.» | Restic инициализировал репозиторий, или доступ работает. | Не нужно. |
| «Репозитория пока нет. Инициализируйте его.» | Проверка доступа не нашла репозиторий в расположении. | Выберите «Инициализировать». |
| «Пароль репозитория или учётные данные неверны.» | Restic не может открыть репозиторий. | Проверьте пароль и учётные данные хранилища. |
| «Репозитория нет по этому пути на этом хосте. Проверьте путь, точку монтирования и хост.» | Хост не может обратиться к расположению. | Проверьте «Адрес», бакет и сетевой путь от хоста. |
| «Срок задания истёк до ответа хоста. Запустите его снова.» | Хост не ответил вовремя. | Убедитесь, что хост в сети, и запустите задание снова. |
| «Хост отклонил путь локального репозитория. …» | Путь лежит вне корней репозиториев хоста Linux (`repository_path_denied`). | Добавьте корень в `/etc/restichub-agent-repository-roots.txt` и выполните `install-service`. См. [Локальный репозиторий в Linux](#локальный-репозиторий-в-linux). |
| «Агент не может писать по пути локального репозитория. …» | Restic сообщил `read-only file system` для пути репозитория (`repository_read_only`). Корень есть в файле, но установленный юнит его не содержит. | Выполните `sudo restichub-agent install-service` и запустите задание снова. |

## Как работает инициализация

Задание содержит шаг `test_access` и, для инициализации, шаг `init`. Для шага `test_access` агент выполняет `restic cat config`, для шага `init` — `restic init`.

Агент выполняет `init` только тогда, когда `test_access` завершается с кодом restic 10. Код restic 10 означает, что репозиторий не существует. В задании инициализации страница задания показывает этот результат `test_access` как сведения: «Репозитория нет — он будет создан.». При любом другом результате задание останавливается, поэтому агент не инициализирует существующий репозиторий повторно. Неверный пароль даёт код 12, и задание сообщает `config_error`.

Пароль репозитория и учётные данные хранилища передаются только в составе подписанного задания. Агент передаёт их restic через переменные окружения. Они никогда не попадают в аргументы команды, журнал, файл журнала заданий или текст ошибки.

## Локальный репозиторий

Локальный путь есть только на диске одного хоста. Поэтому локальный репозиторий привязан к одному хосту — хосту репозитория. Хост репозитория — это и хост обслуживания репозитория.

- Хост репозитория нужно выбрать при создании репозитория. Сервер управления отклоняет локальный репозиторий без хоста.
- Все задания репозитория выполняются на хосте репозитория. Это резервные копии планов, `forget`, `prune`, `check`, `unlock`, инициализация, проверка доступа, список снимков, дерево файлов и восстановление.
- План профиля, который пишет в этот репозиторий, выполняется только на хосте репозитория. Страница плана предлагает только этот хост. См. [Планы](/restichub/ru/concepts/plans/#локальный-репозиторий).
- Восстановление из репозитория пишет файлы только на хост репозитория, потому что restic читает репозиторий на этом хосте.
- До инициализации хост репозитория можно изменить. Сервер управления отклоняет изменение, пока план репозитория выполняется на старом хосте. Сначала перенесите или удалите план.
- После инициализации хост репозитория изменить нельзя, как и путь. Снимки лежат на диске этого хоста. Страница показывает поле заблокированным и объясняет причину. API отклоняет изменение с кодом `repository_host_locked`.

Репозиторий S3 или rest-server доступен каждому хосту по сети. Для него смена хоста обслуживания — обычная операция.

Замена записи хоста переносит хост репозитория на новую запись, в том числе после инициализации. Обе записи относятся к одной машине, поэтому путь остаётся на том же диске. См. [Повторная регистрация хоста](/restichub/ru/guides/agent-certificates/).

:::caution
Не используйте общий сетевой диск (NFS или SMB) как локальный репозиторий для нескольких хостов. ResticHub отправляет задания локального репозитория только на хост репозитория, поэтому планы на других хостах завершаются ошибкой. Для репозитория, в который пишут несколько хостов, используйте rest-server или SFTP.
:::

### Хост репозитория отозван

ResticHub не переносит инициализированный локальный репозиторий на другой хост. Если хост репозитория отозван, например после переустановки с новым идентификатором машины, выполните одну из процедур ниже.

Чтобы сохранить старые снимки на новом хосте:

1. Удалите репозиторий в ResticHub. Сначала перенесите или удалите его профили. Данные restic на диске остаются.
2. Если данные перенесены на новый хост, добавьте их как новый локальный репозиторий на новом хосте. Укажите тот же пароль репозитория.
3. Выберите «Проверить доступ». Проверка находит существующий репозиторий и отмечает его инициализированным.

Чтобы сохранить планы и данные по тому же пути:

1. Добавьте новый локальный репозиторий с тем же путём на новом хосте. Добавьте новый профиль, который пишет в него.
2. Откройте каждый план старого профиля. Выберите новый профиль и новый хост в одном изменении и сохраните план.
3. В новом репозитории выберите «Проверить доступ». Проверка находит существующий репозиторий и отмечает его инициализированным.
4. Удалите старый репозиторий и старый профиль.

История заданий и расписания обслуживания старого репозитория в новый репозиторий не переносятся.

### Репозитории, сохранённые до этого правила

Сервер управления сохраняет локальный репозиторий без хоста и план, который выполняется на другом хосте. Он ничего не удаляет. Задание такого плана сервер управления отклоняет с причиной `not_repository_host`. Как найти такой план:

- Откройте «Задания», выберите вкладку «Не выполнены» и отфильтруйте список по репозиторию. Неуспешное задание такого плана показывает причину «Репозиторий локальный, и его путь находится на другом хосте». В строке указан план.
- Откройте план. Поле хоста показывает ошибку, если план выполняется не на хосте своего локального репозитория.
- «Запустить сейчас» для такого плана показывает ошибку.

Журнал сервера управления также содержит предупреждение о каждом таком репозитории, не более 20 идентификаторов планов. Этот журнал читает только администратор сервера управления.

Чтобы исправить репозиторий:

1. Откройте страницу репозитория.
2. В разделе «Хост репозитория» выберите хост, на котором лежит путь. Репозиторий без хоста принимает это изменение, даже если план выполняется на другом хосте.
3. Откройте каждый найденный план и выберите хост репозитория.

## Удаление репозитория

Удалите репозиторий через меню «…» в строке репозитория в списке «Репозитории». Сначала удалите или измените каждый профиль, который использует репозиторий. Пока задание репозитория активно, сервер управления тоже отклоняет удаление.

Удаление убирает из ResticHub запись репозитория и его сохранённые секреты. Данные restic в хранилище или на диске оно не удаляет никогда. Для удаления ResticHub не отправляет хосту задание. Сохраните пароль репозитория: ResticHub удаляет свою копию, а пароль нужен, чтобы добавить репозиторий снова.
