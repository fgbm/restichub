На этой странице вы установите один сервер управления, зарегистрируете один хост Linux и сделаете первую резервную копию в S3-совместимое хранилище или на rest-server. У каждого шага есть бюджет времени и результат, который можно проверить. Общий бюджет — 29 минут. Каждый шаг ссылается на полную страницу.

## Перед началом

Бюджет времени не включает эту подготовку:

- Сервер Linux для сервера управления с памятью не менее 2 ГБ и доступом в интернет.
- Доменное имя, например `restichub.example.com`, и запись DNS типа A, которая указывает на сервер.
- Открытые на сервере порты 80, 443 и 8443.
- Второй хост Linux для агента с доступом `root`. Хост должен обращаться к серверу по портам 443 и 8443.
- Хранилище для репозитория: бакет S3 с ключом доступа и секретным ключом или rest-server. См. [Добавление репозитория](/restichub/ru/getting-started/add-a-repository/#перед-началом).

## Шаги

1. **Установите Docker (4 мин).** Установите на сервер Docker Engine, плагин Compose и `git` по [руководству Docker](https://docs.docker.com/engine/install/).

   Результат: `docker compose version` выводит версию.

2. **Получите выпуск (3 мин).** В оболочке root (`sudo -i`) получите тег выпуска:

   ```sh
   git clone --depth 1 --branch v0.1.0-rc.4 https://github.com/fgbm/restichub.git /opt/restichub
   ```

   Результат: каталог `/opt/restichub` содержит выпуск. Раздел «Contents» на [странице выпуска](https://github.com/fgbm/restichub/releases) показывает ссылку на образ `ghcr.io/fgbm/restichub-cp@sha256:<digest>`. См. [Получение дайджеста образа](/restichub/ru/getting-started/install-control-plane/#получение-дайджеста-образа).

3. **Запустите сервер управления (5 мин).** Возьмите ссылку на образ из шага 2 и выполните эти команды:

   ```sh
   cd /opt/restichub/deploy/reference
   ./init-env.sh restichub.example.com admin@example.com ghcr.io/fgbm/restichub-cp@sha256:<digest>
   docker compose up -d
   ```

   Результат: `curl -fsS https://restichub.example.com/healthz` выводит `ok`. См. [Установка сервера управления](/restichub/ru/getting-started/install-control-plane/#установка).

4. **Создайте администратора (2 мин).** Прочитайте токен настройки и введите его на экране «Первоначальная настройка» по адресу `https://restichub.example.com`:

   ```sh
   docker compose logs cp | grep setup_token
   ```


   <Screen name="setup-first-admin" alt="Экран «Первоначальная настройка» с полем «Токен настройки»" />

   Результат: вы вошли как администратор. См. [Первый администратор](/restichub/ru/getting-started/install-control-plane/#первый-администратор).

5. **Зарегистрируйте хост (5 мин).** На хосте выполните эти команды от `root`. Последнюю команду скопируйте из диалога «Добавить хост» («Хосты» → «Добавить хост» → «Создать токен»):

   ```sh
   curl -LO https://github.com/fgbm/restichub/releases/download/v0.1.0-rc.4/restichub-agent-0.1.0-rc.4-linux-amd64.tar.gz
   tar -xzf restichub-agent-0.1.0-rc.4-linux-amd64.tar.gz
   sudo ./restichub-agent register --url https://restichub.example.com --token <token>
   ```


   <Screen name="hosts-add-command" alt="Диалог «Добавить хост» с токеном и командой register" />

   Результат: на экране «Хосты» у хоста состояние «В сети». Агент сам скачивает restic. См. [Регистрация агента](/restichub/ru/getting-started/add-a-host/).

6. **Добавьте репозиторий (3 мин).** Добавьте репозиторий с этим хостом в поле «Хост обслуживания». Затем выберите «Инициализировать» в меню «…» его строки.

   Результат: у репозитория состояние «Готов». См. [Добавление репозитория](/restichub/ru/getting-started/add-a-repository/).

7. **Создайте профиль (3 мин).** На экране «Профили» нажмите «Добавить профиль» и введите эти значения:

   - «Основное»: имя в поле «Профиль» и новый репозиторий в поле «Репозиторий».
   - «Что копировать»: каталог в поле «Все системы», например `/etc`.
   - «Хранение»: готовый набор «Стандарт».

   Результат: после «Сохранить» профиль есть в списке. См. [Создание профиля и плана](/restichub/ru/getting-started/profiles-and-plans/).

8. **Создайте план (2 мин).** На экране «Планы» нажмите «Добавить план» и введите эти значения:

   - «Основное»: имя в поле «План».
   - «Что копировать»: новый профиль в поле «Профиль» и хост в поле «Хост».
   - «Расписание»: шаблон «Ежедневно в 02:00».

   Результат: после «Сохранить» план есть в списке. См. [Создание профиля и плана](/restichub/ru/getting-started/profiles-and-plans/).

9. **Запустите первую резервную копию (2 мин).** На экране «Планы» выберите «Запустить сейчас» в меню «…» плана.


   <Screen name="jobs-list" alt="Список заданий с успешным заданием" />

   Результат: на экране «Задания» у задания состояние «Успешно». Выберите имя задания, чтобы прочитать его шаги и журнал. См. [Задания](/restichub/ru/concepts/job-lifecycle/).

## Проверка восстановления

Эта проверка не входит в бюджет времени. Она занимает около 3 минут.

1. Откройте «Восстановление» и выберите репозиторий.
2. Выберите новый снимок и отметьте один файл в дереве.
3. Нажмите «Восстановить…». Диалог предлагает хост и «Целевой путь» в корне восстановления, например `/var/lib/restichub-restore/a1b2c3d4`.
4. Нажмите «Начать восстановление».

<Screen name="restore-dialog" alt="Диалог восстановления с целевым хостом и целевым путём" />

Результат: у задания восстановления состояние «Успешно», а файл лежит в целевом пути на хосте. См. [Восстановление](/restichub/ru/guides/restore/).
