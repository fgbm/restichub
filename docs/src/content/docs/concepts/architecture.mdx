## Parts

| Part | Function |
|---|---|
| Control plane | Keeps the configuration, schedules jobs, sends jobs to agents, shows results. |
| Agent | Runs on each host. Receives signed jobs, runs restic, sends results. |
| Repository | A restic repository. The agent accesses it directly. |

## Connections

<Diagram name="architecture" label="The connections between the browser, the control plane, the agents and the repositories" />

| From | To | Port and protocol | Purpose |
|---|---|---|---|
| Browser | Reverse proxy | 443, HTTPS | The web interface and the API. |
| Reverse proxy | Control plane | 8080, HTTP | The proxy sends the requests to the control plane on the internal network. |
| Agent | Control plane, through the reverse proxy | 443, HTTPS | Enrollment, one time. See [Add a host](/restichub/getting-started/add-a-host/#how-enrollment-works). |
| Agent | Agent listener of the control plane | 8443, gRPC with mTLS | The stream for jobs, progress and results. The agent opens it and keeps it open. |
| restic on the host | Repository | The port of the backend | The backup data. It does not go through the control plane. |

The control plane never opens a connection to a host. The reverse proxy does not terminate the mTLS of the agents. The agent listener port goes to the control plane directly.

## Terms

| Term | Meaning |
|---|---|
| Tenant | An isolated organization in one installation. |
| Profile | A backup definition: paths, exclusions, options, retention and scripts. A profile declares parameters but holds no repository. |
| Plan | A profile, a host and a repository with a schedule. |
| Profile parameter | A named value that a profile declares. A host or a plan sets the value. |
| Job | One run of a plan or a manual operation. |
| Step | One command in a job, for example `backup` or `forget`. |
| Server script | A script that you write in the web interface. The agent runs it on a trusted host before or after the backup. |
| Maintenance host | The host that runs `forget`, `prune` and `check` for a repository. |

## How a job runs

1. The control plane calculates the time of the next job from the plan schedule.
2. At that time the control plane puts the job in the queue.
3. When the repository is free, the control plane signs the job and sends it to the agent.
4. The agent verifies the signature.
5. The agent runs the steps in sequence and sends progress to the control plane.
6. The agent sends the result. The control plane shows it on the dashboard.
