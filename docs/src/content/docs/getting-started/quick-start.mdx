This page installs one control plane, enrolls one Linux host and makes the first backup to an S3-compatible storage or a rest-server. Each step has a time budget and a result that you can check. The total budget is 29 minutes. Each step links to the full page.

## Before you start

The time budget does not include these preparations:

- A Linux server for the control plane with at least 2 GB of memory and access to the internet.
- A domain name, for example `restichub.example.com`, with a DNS record of type A to the server.
- The ports 80, 443 and 8443 open on the server.
- A second Linux host for the agent, with `root` access. The host must reach the server on the ports 443 and 8443.
- A backend for the repository: an S3 bucket with an access key and a secret key, or a rest-server. See [Add a repository](/restichub/getting-started/add-a-repository/#before-you-start).

## Steps

1. **Install Docker (4 min).** On the server, install Docker Engine and the Compose plugin with the [Docker guide](https://docs.docker.com/engine/install/).

   Result: `docker compose version` prints a version.

2. **Install the control plane (6 min).** Find the version of the release on the [releases page](https://github.com/fgbm/restichub/releases). Run the script of the release with your domain and your email address:

   ```sh
   VERSION=<version>
   curl -fsSL "https://github.com/fgbm/restichub/releases/download/v${VERSION}/install.sh" | sudo bash -s -- --domain restichub.example.com --email admin@example.com
   ```

   Result: the script prints `The control plane is healthy and runs the verified image`. Then it asks you to store the key encryption key (KEK). See [Install the control plane](/restichub/getting-started/install-control-plane/#install).

3. **Store the KEK (2 min).** Copy the KEK and the environment file outside the server. Then type `saved` in the terminal of the script. See [Store the KEK outside the server](/restichub/getting-started/install-control-plane/#store-the-kek-outside-the-server).

   Result: `curl -fsS https://restichub.example.com/healthz` prints `ok`.

4. **Create the administrator (2 min).** In a root shell (`sudo -i`), read the setup token. Use it on the screen "Initial setup" at `https://restichub.example.com`:

   ```sh
   cd /opt/restichub && docker compose logs cp | grep setup_token
   ```


   <Screen name="setup-first-admin" alt="The screen Initial setup with the field Setup token" />

   Result: you sign in as the administrator. See [The first administrator](/restichub/getting-started/install-control-plane/#the-first-administrator).

5. **Enroll the host (5 min).** On the host, run these commands as `root`. Copy the last command from the dialog "Add a host" ("Hosts" → "Add host" → "Create token"):

   ```sh
   VERSION=<version>
   curl -fsSLO "https://github.com/fgbm/restichub/releases/download/v${VERSION}/restichub-agent-${VERSION}-linux-amd64.tar.gz"
   tar -xzf "restichub-agent-${VERSION}-linux-amd64.tar.gz"
   sudo ./restichub-agent register --url https://restichub.example.com --token <token>
   ```


   <Screen name="hosts-add-command" alt="The dialog Add a host with the token and the register command" />

   Result: the host has the status "Online" on the screen "Hosts". The agent downloads restic itself. See [Register an agent](/restichub/getting-started/add-a-host/).

6. **Add the repository (3 min).** Add the repository with this host as the "Maintenance host". Then select "Initialize" in the menu "…" of its row.

   Result: the repository has the status "Ready". See [Add a repository](/restichub/getting-started/add-a-repository/).

7. **Create a profile (3 min).** On the screen "Profiles", select "Add profile" and enter these values:

   - "Main": a name in "Profile".
   - "What to back up": a directory in "All systems", for example `/etc`.
   - "Retention": the preset "Standard".

   Result: after "Save", the profile is in the list. See [Create a profile and a plan](/restichub/getting-started/profiles-and-plans/).

8. **Create a plan (2 min).** On the screen "Plans", select "Add plan" and enter these values:

   - "Basics": a name in "Plan".
   - "What to back up": the new profile in "Profile", the new repository in "Repository", and the host in "Host".
   - "Schedule": the preset "Daily at 02:00".

   Result: after "Save", the plan is in the list. See [Create a profile and a plan](/restichub/getting-started/profiles-and-plans/).

9. **Run the first backup (2 min).** On the screen "Plans", select "Run now" in the menu "…" of the plan.


   <Screen name="jobs-list" alt="The list of jobs with a succeeded job" />

   Result: on the screen "Jobs", the job has the status "Succeeded". Select the name of the job to read its steps and log. See [Jobs](/restichub/concepts/job-lifecycle/).

## Check the restore

This check is outside the time budget. It takes about 3 minutes.

1. Open "Restore", and select the repository in the field at the top of the page. The field shows the name, the backend kind and the location of each repository.
2. Select the new snapshot, and select one file in the tree.
3. Select "Restore…". The dialog proposes the host and a "Target path" in the restore directory, for example `/var/lib/restichub-restore/a1b2c3d4`.
4. Select "Start restore".


<Screen name="restore-dialog" alt="The restore dialog with the target host and the target path" />

Result: the restore job has the status "Succeeded", and the file is in the target path on the host. See [Restore](/restichub/guides/restore/).
